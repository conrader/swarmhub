# Connector configuration

Swarm Hub ships `Resources/Skills/swarmhub-manager/scripts/default-connectors.py` with the manager skill. The examples below use that checkout path; an installed Hermes manager uses `~/.hermes/profiles/<manager>/skills/swarmhub/swarmhub-manager/scripts/default-connectors.py` (or `~/.hermes/skills/swarmhub/swarmhub-manager/scripts/default-connectors.py` for the default manager). Older installations receive the current helper at `~/.config/swarmhub/default-connectors.py` during new-bot creation.

New bots receive SB's forced-command read-only wiki connector and the optional read-only defaults in `~/.config/swarmhub/default-connectors.json`. Additional defaults remain filtered references to their original source; their credentials are never copied. Aliases, unreadable sources and refused HTTP defaults retain the behavior established in PR #5. OpenClaw's new workspace has no MCPorter imports. Its AGENTS.md must require `mcporter --config ~/.openclaw/workspace-<id>/config/mcporter.json` for every connector call, preventing MCPorter from merging the home catalog. The manager creation recipe supplies this rule.

Use the manager's normal approved creation flow. The helper's `create hermes <bot> --manager <profile> --description '<description>'` or `create openclaw <bot>` calls the stock backend CLI without copying a manager profile/workspace. Both refuse existing directories. A fresh Hermes profile gets the manager's selected model, provider and endpoint, only that provider's env keys, and only that provider's static entries from auth.json (including credential pools). OAuth uses Hermes' shared-root login without copying rotating refresh tokens. A private named-manager OAuth login must first be configured at the shared root; otherwise creation stops before writing a bot. External CLI-only OAuth and providers without a credential rule also stop with a setup error. Named-manager credentials override root entries. The helper checks this before invoking Hermes and writes private files (0600); it never runs a login, refresh, model request or connector discovery. Missing, ambiguous auto-selection or unsupported provider authentication stops creation with a setup error. Select the provider explicitly on the manager first. Local custom endpoints need no key. OpenClaw keeps its stock shared model/auth inheritance; its create command was checked against the published CLI source without creating an agent. Never restore a manager's entire `.env`, auth files, config or credential-bearing skills to recover authentication.

The helper creates a temporary `.swarmhub-new-bot` marker in the freshly created directory and provisions defaults immediately. `provision <backend> <bot>` only completes that pending creation; after success it returns the saved setup report without changing connectors. It refuses an unmarked legacy bot. No startup migration rewrites existing bots.

To opt one existing bot into one other manager connector, explicitly select both names:

```sh
python3 Resources/Skills/swarmhub-manager/scripts/default-connectors.py opt-in hermes reports --manager manager --connector finance
python3 Resources/Skills/swarmhub-manager/scripts/default-connectors.py opt-in openclaw reports --manager manager --connector finance
```

This copies only `finance` from the manager's `mcp_servers` (Hermes) or workspace `config/mcporter.json` `mcpServers` (OpenClaw). Inline `env`, headers, command and arguments are copied. OpenClaw HTTP endpoints accept `url`, `baseUrl` and `serverUrl`. For a manager connector inherited from a home or imported catalog, add `--source /path/to/its/source-config.json` to select only that entry from its actual source; no whole catalog is imported. `$VAR`, `$env:VAR`, `${VAR}` and `${VAR:-fallback}` references are resolved from the process environment and the backend and manager `.env` files, in backend, manager, then selected source directory order (the last value wins); only values referenced by that connector enter the target config. Missing variables fail before changing the bot. Standard unquoted, single-quoted, double-quoted and `export KEY=value` dotenv lines are supported; shell evaluation and multiline dotenv values are not supported. External credential files remain references to their existing paths. Target configs and provenance files are written with mode 0600.

The command refuses an existing target connector, the manager itself, the default bot, directory symlinks, default connector names, and aliased source names of defaults from that manager. It does not broaden defaults or overwrite an existing connection. It returns a status report without credentials. Other bots and manager files are unchanged.

Read-only inventory of existing non-default holdings:

```sh
python3 Resources/Skills/swarmhub-manager/scripts/default-connectors.py audit hermes
python3 Resources/Skills/swarmhub-manager/scripts/default-connectors.py audit openclaw
```

`--home /path/to/fixture-home` before `audit` targets an offline fixture tree. The JSON lists `bot`, `connector`, `source`, `config` and `origin_known`. Explicit opt-ins record their manager config as source. For legacy holdings the original manager is unknown, so source identifies the bot config containing the connector and `origin_known` is false. Hermes includes the default profile and named profiles; OpenClaw scans standard `workspace-<bot>` directories. OpenClaw also resolves the stock main workspace and configured custom paths from current `agents.entries` and legacy `agents.list` in the local `openclaw.json`; it never edits the Gateway config. JSON is supported directly; JSON5/JSONC configs require the optional Python `json5` module and fail with a fixed error when it is unavailable. Legacy bots also include home MCPorter entries that are not overridden locally. `unresolved_catalogs` flags imported editor catalogs and possible environment-selected legacy catalogs for separate review, without opening imports or displaying their potentially sensitive strings.

The audit reads local configs, the agent inventory, the defaults policy and provenance only. It never invokes a backend, discovers tools, reads secret values into its output, or changes any file. An unreadable or malformed config fails with exit 1 and a fixed error instead of silently omitting a bot. The regression tests run it only on synthetic homes; do not run it against live Hermes for this change.
