# Herdr workspace feature plan

The SwarmHub browser companion uses the familiar three regions: agent roster, central task view, and agent details. The Mac app chats with the same agents through the same bridge ([setup](../HerdrWorkspace/README.md#use-the-mac-app)). Herdr Core manages processes; the interface and optional agent integrations will need to provide higher-level product features.

| Grok Bot workflow | Herdr workspace |
| --- | --- |
| Create and find personal Bots; give instructions in chat ([Bots](https://docs.x.ai/grok-bot/bots)) | Create a saved agent and draft its first task before choosing a runtime, or start directly from a template. The roster is searchable and saves follow-ups. Saved profiles support renaming, labels, preset and uploaded avatars with crop preview, pinning, hiding, movable roster sections, and opening past sessions. Standing instructions can be saved from a task, edited on the profile, or appended from a reviewed agent memory suggestion in chat. The reviewed instructions carry across sessions and templates. Duplicating an agent copies its setup, skill availability, and paused routines into a separate profile with a fresh conversation. Agent templates carry reviewed profile settings into a new profile without starting a session. Automatic learning and generated avatars remain open. |
| Follow work, steer, attach files, and use group chats ([Chat](https://docs.x.ai/grok-bot/chat-and-collaboration)) | Persistent tasks, delivery feedback, live terminal output, status, interrupt and end. Claude Code, Codex, and OpenCode V2 integrations record completed replies; OpenCode V2 and opted-in interactive Claude Code show live text in direct conversations. Generic templates can post replies too. Direct conversations support quoted replies and a thread panel with the original message and its user follow-ups, available from the Library even offline. Any tool-capable template can use the supplied reply command to post an answer linked to its exact follow-up; replies captured without a link stay in the main conversation. Groups of two to six agents support editable membership, `@` mentions, per-recipient receipts, attachments in both directions, direct replies, clarifying questions, and forms with text and choice fields. Agents can post temporary progress updates to the group using the task's reply command. New API-backed OpenCode V2.3 sessions can preview the exact group task’s assistant text while it is streaming, separately from the saved group answer. Saved agent replies display Markdown, with source and code-copy controls. Reactions work on saved messages in direct conversations, archives, and groups. A user can hand off a saved direct or group reply to another agent by reviewing and sending it from a new draft. Automatic group previews for other runtimes, live replies from other agent programs in direct chats, and automatic handoffs remain open. |
| Choose the agent's runtime | Search and choose among installed Herdr templates. Runtime setup shows which templates Herdr can load, offers downloadable examples, and keeps a first draft open while you add one. Codex, Claude Code, and OpenCode V2 support named model presets and exact model IDs at launch. Custom templates can opt in by reading the selected model ID from `SWARMHUB_MODEL_ID`. Session details retain the selected ID and available labels. Enabled OpenCode V2 and Codex templates can list model IDs from the runtime’s own catalog. In Codex the list may be bundled or cached and does not verify account or provider access. Each agent program handles provider authentication. A live API-backed OpenCode session can apply a reviewed model or restore its configured default from Details before later tasks; other sessions use their native runtime controls. The official [Grok Bot FAQ](https://docs.x.ai/grok-bot/faq#can-i-pick-the-model) says Grok Bot chooses the model itself, so letting users choose is a product difference. |
| Switch from an existing Grok Bot workspace | Review local SwarmHub Grok export bundles, then import profiles, standing instructions, searchable read-only history, and inert routine drafts for personal bots. Download a helper from the import dialog to create a bundle from recent history cached on the Mac, without signing in. Choosing an export folder restores matching local attachments. Re-importing adds missing messages, local files, and drafts and preserves edits. A v1 export folder with actual indexed Markdown skill files can supply editable drafts for the private Skills library. The cache exporter does not include private skills or restore assignments. Users choose a Herdr template and explicitly opt to send imported instructions at the first launch. They can finish setting up an imported routine as paused for that profile’s running session. Retrieving files and skills absent from the export and reconnecting accounts remain open. |
| Reuse instructions and run schedules ([Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)) | The private Skills library supports creating skills from scratch or from replies, reviewing a local Markdown or text file as a new skill, downloading and importing portable SwarmHub copies, editing, per-agent availability, and inserting a reviewed version into task and routine drafts. Agents can suggest skills and routines in direct chat. Review, edit, or dismiss suggestions; adopting a routine on the same agent profile starts it paused. Interval, daily and weekday routines support pause/resume, editing, testing, and archiving. Run history separates delivery from agent-reported success or failure and links to the exact saved outcome. Routines can also run from authenticated local webhooks, including signed GitHub issue and pull-request events and Slack app mentions, with filters and duplicate-request protection. During private desktop takeover, users can turn a short, labeled click demonstration into a reviewed skill draft. Other named provider triggers, automatic replay, and shared skill publishing remain open. |
| View the computer, take over, and connect accounts ([Computer and apps](https://docs.x.ai/grok-bot/computer-and-apps)) | Herdr streams read-only and interactive terminal views. An optional Linux wrapper also gives a session a private graphical desktop with a watch view and explicit takeover. Detaching does not stop the agent. OpenCode V2 reports work, completion, errors, and pending decisions through Herdr. **Needs attention** leads directly to pending approvals, blocked terminals, and unanswered group questions and forms. The bridge can browse one configured HTTPS WebDAV collection, attach files to agent drafts, and optionally save copies of Library files or group attachments to that collection. The connected file picker also supports Google Drive. Users can grant a running agent one hour of read access to that folder and review or revoke it in Details. GitHub has its own read grant for open issues and pull requests in one configured repository. Broader web app connections and managed sign-in remain open. |
| Find files, results, and Pages ([Files and results](https://docs.x.ai/grok-bot/files-and-results)) | The Library preserves task history, terminal snapshots, published files, and editable Markdown Pages with interactive checklists. Pages retain 50 revisions for reading, download, and restore. Agent-published Pages have stable conversation cards and a panel to request changes from the original session; request links open the exact revision while it is retained. Opt-in results folders automatically save finished files and revisions from an agent session. Workspace search opens saved direct, group, and imported messages at the match. It finds Pages, files and direct attachments, snapshots, agents, groups, skills, and routines including imported drafts even while Core is offline. The Library and group attachments preview saved images, CSV tables, plain text, and PDF pages with selectable text, and play MP4, WebM, and WAV recordings. A Page can have one revocable seven-day viewer link at the existing workspace address, for a fixed copy or for future updates. Readers can filter and sort tables and inspect chart values without the workspace token. Hosted publication, team sharing, and custom controls remain open. |
| Approve actions and manage secret values ([Approvals](https://docs.x.ai/grok-bot/approvals-security-and-privacy), [Vault](https://docs.x.ai/grok-bot/vault)) | Opt-in Claude Code and Codex permission requests support exact-argument review, allow once, deny, and terminal fallback. OpenCode V2 can use the same inbox for file reads and searches, with the action and resource list shown for review. A confirmed read of one regular file can be remembered for one OpenCode session and one hour, with metadata checks and revocation. The Vault supports secure entry on Mac and web, single-use and bounded reusable credential approval for managed agent sessions, and named credentials for connectors. Secure sign-in forms, automatic login, broader connector and OpenCode tool coverage, agent policies, and automatic review remain open. |
| Track unread results ([Attention states](https://docs.x.ai/grok-bot/settings-and-notifications#understand-attention-states)) | Activity shows saved replies, new Pages, and published files, alongside persistent unread counts for agents and groups. Entries open the exact saved message, and a focused conversation acknowledges activity up to the latest item it shows. Opt-in desktop browser alerts cover new results, approvals, and group requests while a tab is open. Agent-level mutes apply in that browser. Mobile push and closed-tab alerts remain open. |
| Collaborate with a team or in meetings ([Team Bots](https://docs.x.ai/grok-bot/team-bots), [Meetings](https://docs.x.ai/grok-bot/meetings)) | Shared agents, permissions, team knowledge, voice, and meeting actions are later requirements with independent access and runtime contracts. |

The source review was based on official documentation, without access to an authenticated Grok Bot session. Current personal-Bot documentation uses chat for role and memory; older introductory screenshots show settings that no longer match that workflow. Next priorities include structured replies from more agents, additional permission integrations, and connected apps. Hosting and billing are out of scope.

See the [Grok Bot parity audit](grok-parity-audit.md) for remaining workflows, local evidence, and acceptance checks.

Draft tasks, reply targets, and group recipient selections survive a reload in the same browser tab. Unsent files need to be selected again; the interface lists what is missing before sending.

Both chat composers accept dropped files and pasted images. Record and review a short voice memo, then add it as an attachment before sending. On supported browsers, use Dictate to review and add text recognized on the device. The draft holds up to four removable files and stages them for the recipients when you send. Direct drafts also accept copies selected from the connected folder.

Files on newly sent direct tasks stay with the message and can be previewed or downloaded from the conversation, thread, or archive while Core is offline.

The connected file picker can also browse an administrator-configured Google Drive folder and attach files or Office exports of Docs, Sheets, and Slides. Users can authorize with Google from the browser when a Desktop OAuth client and the Vault are configured; credentials stay in the bridge. Drive defaults to read-only access. Administrators can enable saving copies to writable folders without replacing existing files.

The browser can browse open issues and pull requests in one explicitly configured GitHub repository. Users preview a plain-text excerpt and attach it to a direct or group draft before sending. Browsing works while Herdr Core is offline. In **Details → GitHub read access**, users can also authorize one running agent to read excerpts by issue or pull request number for up to one hour. The browser can revoke access and shows each recent request's type, number, time, and outcome. The optional Vault credential stays in the bridge. GitHub comments, diffs, and writes are outside this connection.

Pages have bookmarkable workspace links for the latest view or an exact retained revision. Links require normal workspace access and work while Core is offline.

Markdown tables in Pages let readers filter by text and column, sort, and reset their view without saving a new revision. Each table has its own controls, including in retained revisions.

Agents can publish bar and line charts in Pages using fenced `chart` blocks with JSON data. The browser renders them locally and includes an exact values table.

Saved agents have authenticated chat links, optionally with suggested draft text. Links preserve existing drafts and never dispatch a task or start a session by themselves. See [Grok Bot deep links](https://docs.x.ai/grok-bot/deep-links) for the reference workflow.

An agent’s details open a dedicated Library with published Pages, published or collected files, and terminal snapshots across past and current sessions. Results appear newest first with filters by type and remain available offline.

Pin a Page, file, or snapshot to keep it above newer work wherever that result appears in the Library. The workspace saves pins independently of Core.

Direct sessions, groups, and imported history can also be downloaded as plain-text transcripts while Core is offline. Attachments and terminal snapshots stay separate.

Incoming webhook routines can require exact matches on several JSON fields. Nonmatching events do not start runs. GitHub issue and pull-request deliveries and Slack app mentions use signed local receivers. Slack routines require matching workspace and channel IDs. Public ingress and other named providers still need separate integration.

Routines can move to a replacement session of the same agent profile. They pause for review on the new session, and old run links still open the original conversation.

Webhook routines can wait for a person to review the incoming payload and approve or dismiss it before dispatch. A change to the routine invalidates approval of older waiting events. **Needs attention** links to the exact event, with an optional desktop notification that does not include its payload.

The [Vault](../HerdrWorkspace/README.md#vault) opens a masked request sheet on Mac and a masked modal in the browser. Agent sessions request a credential by name and use an approval for one command or up to 10 commands within 30 minutes. The browser also shows which connectors use a named entry and which are waiting for one.
