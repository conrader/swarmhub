# Personal-agent parity audit

Scope: SwarmHub’s browser workspace on DMT, compared with the published Grok Bot workflows. This is a source audit, not a certification against a logged-in Grok Bot account. Deployment, billing, enterprise policy, and meetings are outside this pass. The [workspace feature plan](herdr-workspace.md) describes scope; the implementation is the evidence below.

| Workflow | What the workspace supports | What remains |
| --- | --- | --- |
| [Create and manage a personal Bot](https://docs.x.ai/grok-bot/bots) | **New agent** saves a profile and opens its empty conversation, even with Core offline. The first draft carries into runtime review; **Start from template** remains available. Profiles support labels, avatars, standing instructions, duplication, roster sections, and prior sessions. An agent can propose a preference or correction in chat; the user can edit it, dismiss it, or append it to standing instructions, including while Core is offline. A versioned agent template carries reviewed setup into a new offline profile. | Cross-session memory requires explicit review. Portable templates carry profile settings and standing instructions; they do not carry conversations, connections, files, skills, or routines. ([Profile routes](../HerdrWorkspace/src/profiles.rs), [memory suggestions](../HerdrWorkspace/src/memory_proposals.rs), [launch and composer](../HerdrWorkspace/web/index.html)) |
| [Chat and collaboration](https://docs.x.ai/grok-bot/chat-and-collaboration) | Direct and group chat, attachments, saved replies and threads, reactions, and reviewed handoffs. In a group, an agent can propose a follow-up for one named member. The user sees the original task, reviews or edits the follow-up, and decides whether to send it. Agents can also suggest an editable email draft in direct chat for download as a plain-text `.eml`, including while Core is offline. OpenCode and opted-in interactive Claude Code support live direct reply previews. Opted-in OpenCode V2.3 also shows a live group preview tied to the exact task and recipient. A final group answer still uses the supplied reply command. Direct and group composers can record and attach voice memos and, on supported browsers, dictate text locally. | Most runtimes do not stream structured live replies into chat. Group handoffs need explicit approval and do not cascade. Email drafts are never sent by SwarmHub. Voice memos have no built-in transcription, and live calls remain open. The DMT Chrome fixture verified the on-device dictation UI; its native profile lacked English (US) recognition. ([Group handoffs](../HerdrWorkspace/src/group_handoffs.rs), [email drafts](../HerdrWorkspace/src/email_drafts.rs), [OpenCode integration](../HerdrWorkspace/src/opencode_agent.rs), [chat UI](../HerdrWorkspace/web/workspace.js)) |
| [Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations) | An agent can propose a skill or a routine in direct chat for the user to review, edit, or dismiss. Skills can be saved offline; adopting a routine requires a running session on the same agent profile and creates a paused routine with no run. Other workflows include event-driven routines, paused imported drafts, and a review queue for webhook events. During private desktop takeover, users can record mouse clicks, label steps, and review them in the skill editor. | Automatic replay and additional provider triggers remain open. ([Skill proposals](../HerdrWorkspace/src/skill_proposals.rs), [routine proposals](../HerdrWorkspace/src/routine_proposals.rs), [imported drafts](../HerdrWorkspace/src/routine_drafts.rs)) |
| [Use the computer and apps](https://docs.x.ai/grok-bot/computer-and-apps) | Live terminal viewing and keyboard takeover. Templates configured for the optional Linux graphical desktop get their own X11 display; users can watch, take over keyboard and pointer, return to watching, or detach. On DMT, an RFB test verified input isolation, and Chrome verified viewing, taking control, releasing control, and closing the viewer when Core stopped. WebDAV and Google Drive support browsing, attaching, and copying files through the browser. A running agent can read the connected Drive folder after a one-hour grant. Users can browse open GitHub issues and pull requests in one configured repository and attach a reviewed excerpt to a direct or group draft. A separate one-hour grant lets a running agent read an excerpt by issue or pull request number. Chrome and a loopback GitHub fixture verified session scope, in-flight revocation, and a recent-requests view with type, number, time, and outcome. The credential stays in the bridge. | Graphical viewing requires a configured Linux template. GitHub comments, diffs and writes, broader agent-callable apps, and managed custom MCP integrations remain open. Provider sign-in and model availability are handled by the configured runtimes. ([Desktop](../HerdrWorkspace/src/desktop.rs), [terminal](../HerdrWorkspace/src/terminal.rs), [Drive](../HerdrWorkspace/src/drive_files.rs), [GitHub project](../HerdrWorkspace/src/github_project.rs), [agent GitHub access](../HerdrWorkspace/src/github_access.rs), [runtime choices](../HerdrWorkspace/src/runtimes.rs)) |
| [Files and results](https://docs.x.ai/grok-bot/files-and-results) and [approvals and privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy) | Saved results, offline library and transcripts, private Page links and revisions, checklists/tables/charts, opt-in runtime approval cards, and encrypted, write-only connector credentials. After a confirmed OpenCode approval, users can remember a single file read for one native session and one hour. Rules check file metadata before each approval, can be revoked, and leave a distinct decision record. Any retained Page revision can be downloaded as a standalone read-only HTML file with its checklist state, tables, and exact chart values. | Hosted public Pages and team sharing remain open. A revocable viewer link shares one Page at the existing workspace address and can follow future edits without giving readers workspace access. Current approval hooks do not provide a general action policy. The Vault and provider consent screen do not support task-specific secure sign-in forms. Closed-tab alerts require a separate delivery design. ## Three independent work tracks

1. **Open a conversation before choosing a runtime.** Implemented through the authenticated profile route and existing no-session view. The first draft carries into template review; canceling retains it, and confirming opens one session on the saved profile. Model-free tests exercised offline profile creation and draft reload, independent template drafts, first-task delivery, browser access controls, and human names with duplicate or non-ASCII characters.
2. **Review a reusable workflow proposed in chat.** Skill and routine proposals are implemented. A routine proposal accepts supported schedules and binds to the originating running session or a running replacement on the same profile. Model-free smoke tests verified early proposal attribution, malformed input rejection, offline review and dismissal, idempotent adoption, and paused state with no run.
3. **Let a running agent read from a configured source with a scoped grant.** The Drive broker limits reads to the configured folder. The separate GitHub broker reads open issue and pull-request excerpts in the configured repository. Both use private local sockets, revocable grants for the exact running session, and browser audit views separate from agent commands. Loopback fixtures verified scope, credential handling, and revocation. Processes sharing one OS account still share its privileges.

Live calls, separately hosted Page publication, background push, and broad MCP installation need distinct product decisions.

The import dialog offers a downloadable, offline Grok Bot cache exporter that creates private bundles without replacing an older export. A DMT fixture downloaded it in Chrome, ran it on a synthetic Mac cache, and imported the resulting redacted conversation with Core offline. This verifies the transfer format; the cache may not contain every message, and this test used no live Grok account.

The browser also recognizes written `SKILL.md` copies listed in the root index of a supplied [v1 export folder](agentapp-bot-bundle-v1.md#historical-snapshot-contract). Users stage selected files, then edit, save, or dismiss each draft in the private Skills library. Chrome verified the workflow with Core offline and a synthetic folder containing real Markdown, missing files, an unlisted file, and an unsafe index path. The current cache exporter leaves the skill list empty; this flow does not recover private skills absent from an export or restore which Bots used them. See the [official Grok Bot skills workflow](https://docs.x.ai/grok-bot/skills-routines-and-automations) for how skills differ from scheduled routines.

Opted-in OpenCode V2.3 templates submit the first task and web follow-ups through the same private session API. The shared transport covers direct chat, groups, and routines. A DMT smoke with real Herdr and OpenCode kept Mini closed while sending all three kinds of follow-up and verified attached file access and result attribution. Mini remains available for takeover. Legacy templates use terminal input, and ambiguous API delivery never falls back to terminal input.

Live API-backed OpenCode sessions also expose reviewed model changes in Details. SwarmHub shows OpenCode’s current and configured default selections, checks for pending work, applies the exact reviewed ID, and verifies it through the native session API. A loopback test verified that one real OpenCode session used the original, changed, and restored default models for successive provider turns. The control does not change running work or promise that Mini’s displayed model will update. ([Model controls](../HerdrWorkspace/src/opencode_agent/models.rs))

The [disposable demo](../HerdrWorkspace/dev/preview.py) runs the actual bridge against a separate Herdr Core, with model-free example agents and a read/write conversation. Chrome verified the initial roster and replies, and the launcher smoke verified shutdown, scratch cleanup, and independence from the caller’s existing workspace settings.

DMT Chrome tests ran [workspace search](../HerdrWorkspace/src/search.rs) with Core running and after it stopped. They opened older direct and group messages at their exact position, previewed the original direct attachment, and opened settings for a saved skill, a paused routine, and an inactive imported draft. Search reads the saved workspace under the same access token as the Library.

The [OpenCode smoke](../HerdrWorkspace/tests/smoke.py) ran real Herdr Core and OpenCode V2.3 on DMT with a loopback model fixture. Chrome showed live assistant text in the correct group with its task and recipient, kept it out of another group with the same members, and cleared it without creating a saved reply. The API check also kept the preview out of direct chat and older group pages and confirmed that the explicit group reply remains available.

DMT Chrome opened a [shared Page](../HerdrWorkspace/src/page_share.rs) without the workspace token, applied a table filter, rendered a chart, and received a later edit at the same address while Core was stopped. The open viewer cleared its content after revocation. API tests verified fixed content, restart persistence, expiry, and that a viewer link cannot open workspace routes.
