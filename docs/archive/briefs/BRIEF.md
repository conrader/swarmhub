Build a working native macOS prototype (Swift 6 / SwiftUI, macOS 14+, Xcode 16.2 on this Mac) of Konrad's open agent app (working codename "AgentApp"; final name TBD, so keep the name in one constant). The concept: a Grok Bot / ChatGPT-desktop-style assistant app with NO built-in model. It connects to the user's own agent harness (Hermes Agent first, then OpenClaw) and gives a polished UI for bots, chats, sub-agents and the agent's virtual desktop. Priority: ultra fast and lightweight (instant launch, smooth scrolling with long chats, low memory).

Work in this directory (a new git repo; commit in small steps). Use a Swift Package / SwiftPM-based app or an .xcodeproj generated by a script; it must build from the command line with `swift build` or `xcodebuild`, and include a `scripts/run.sh`.

Prototype scope:
1. Sidebar: a list of bots (name, avatar initial, unread badge) with a create/edit-bot sheet (name, persona instructions, backend selection). Persist bots and chats locally (SwiftData or SQLite via GRDB; pick the fastest and simplest).
2. Chat view per bot: streaming responses, Markdown rendering, code blocks, a composer with Enter to send and Shift+Enter for a newline, stop button. Lazy list that stays smooth with 5k messages.
3. Backend adapter layer: a Swift protocol `AgentBackend` (send message, stream events, list sessions, cancel, approvals). Implementations: (a) `HermesBackend` using Hermes Agent's OpenAI-compatible API server (configurable base URL + API key, SSE streaming of chat completions); check Hermes Agent's public docs (hermes-agent.nousresearch.com, NousResearch/hermes-agent on GitHub) for the actual endpoint and auth, and note what you verified; (b) `OpenClawBackend` stub following OpenClaw's gateway docs (docs.openclaw.ai), behind the same protocol, can be partial; (c) `MockBackend` that streams fake replies, including a fake sub-agent event and an approval request, so the UI is demoable without a server.
4. Approvals: render an approval card in the chat (approve/deny) driven by backend events; draft-before-send style card for an outgoing email example from MockBackend.
5. Sub-agents panel: a collapsible right panel showing sub-agent tasks spawned by the bot (from backend events; mocked for now) with status.
6. Computer view: a tab or panel that shows the agent's virtual desktop via a noVNC URL in a WKWebView (configurable URL); placeholder when not set.
7. Settings: backends (add/edit URL, key stored in the macOS Keychain, test connection), appearance (follows system dark/light).
8. Performance: measure and print cold launch time and memory in a README section; avoid heavy dependencies (at most 1-2 small SwiftPM packages, e.g. a Markdown renderer).

Quality: clean architecture (Models, Backends, Views, Stores), no secrets in the repo, a README with a screenshot taken via `screencapture` of the running app with MockBackend if possible (save to docs/screenshot.png), and how to point it at a Hermes agent. Don't push anywhere; local git only. Don't install system-wide software beyond SwiftPM packages.

Finish by printing: build command, run command, what works, what's stubbed, the measured launch time and memory, and the next steps.
