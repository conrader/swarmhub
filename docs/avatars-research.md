## Recommendation

**No ready-made animated pack in Grok's style survived checking; the closest is an MIT SwiftUI library.**

**Grok's avatars** (reconstructed from code, not seen on screen). Each bot is one flat-colour soft shape (blob, cloud, hexagon...) with two tall capsule eyes cut out as negative space; no mouth, outline or background. Not image or video files: code draws a small 3D shape as a 2D silhouette, animated with squishy idle loops, blinks, glances, pointer-following eyes, busier working motion and a slump when blocked.

**Pick: BotAvatarsKit.** It is the only candidate already in SwiftUI, has enough shapes, and its bodies turn, hop and flip like Grok's; idle/working/sleeping map onto bot status. Use flat shading and Grok's 11 hex colours. **Runner-up: Blobatar**, if macOS proves painful: same style score and richer eye expressions, but tiny idle motion (only blinks show at 28 px).

**Caveats**
- **Unverified:** nothing was compiled or run on a Mac; the SwiftUI kit was judged through its web twin. It has two iOS-only calls (fix looks small, untested) and probably needs its own Swift 5-mode target (Torvli is Swift 6). It and Blobatar are young, AI-assisted projects: vendor pinned copies.
- **Licenses:** libraries.dev also sells Pro/Studio content (its site calls some shipped features Pro); use none of it. The Rive file stays CC BY, not MIT, and rests on the uploader's ownership claim. Excluded: Bloub, a measured Grok clone whose README leaves the design unlicensed. Unchecked: LottieFiles face sets.
- **PLAN.md says "No animations"**; you would need to relax that. Suggest a calm variant: animate only a working or hovered bot, keep other rows still, honour macOS Reduce Motion.

## How Grok Bot draws its avatars (from its code, not seen on screen)

- **Style:** Grok Bot (Cursor/SpaceXAI Electron app 'sand' v0.70.2) does not use illustrated characters. Each bot is an abstract 'mark': ONE solid, flat-colour silhouette of a soft geometric shape whose whole face is two tall capsule (pill / rounded-rectangle) eyes punched out as negative space. No mouth, nose, limbs, outline, text, badge or background disc; the mark is centred, fills about 92% of a square frame, and the silhouette itself is the avatar boundary (the picker's selection ring follows the shape outline). xAI's own design article: 'simple shapes and expressive eyes', identity carried by outline + colour + eye expression + small controlled variations; clay, watercolour, pixel, emoji, initials and identicon styles were tried and rejected as too detailed or too interchangeable at sidebar scale. SUBJECT/SHAPES: the engine has 25 shapes (blob, pebble, bean, egg, squircle, tablet, capsule, cylinder, hex, gem, crystal, wedge, shield, dome, arch, cloud, teardrop, leaf, square, sparkle, clover, flower, heart, house, star); the current picker offers 13 (blob, cloud, square, sparkle, clover, heart, flower, teardrop, tablet, wedge, house, star, hex). RENDERING: vector, flat single paint, pseudo-3D: every body is a small 3D solid (extrusion / loft / ball chain / sphere) rotated by a quaternion and drawn as a 2D silhouette, so turning changes the outline and the eyes wrap around the surface; squash-and-stretch on top; normally no outline, shading or texture (an optional radial glow/halo mode and a 135-degree two-stop gradient palette table exist, use not confirmed). PALETTE: 11 saturated 'bright' hues - black, brown, red, orange, yellow, green, cyan, blue, violet, magenta, gray (picker swatches #000000 #936439 #FF263C #FF6700 #FF9800 #00C972 #00BCA6 #1084FE #9159FE #FF309B #777777; in-app ink comes from theme tokens bg/<hue>-bright and black flips to white in dark mode); eyes are transparent cut-outs by default (optional second eye colour). EXPRESSION is eyes only: neutral = two vertical capsules; happy = upward arcs; sleepy = small arcs; squint = horizontal bars; surprised = larger taller capsules; inspecting = two different-sized round eyes; sad = tilted; calm = flat arcs; confused = asymmetric; plus blinking and gaze that follows the pointer. FRAMING/SIZES: 16/22/28/36/72 px (sidebar row ~28), centred, no circle crop for marks; groups show a cluster of up to 4 member marks. MOTION: squishy, springy idle loops (4-6 s) with blinks and glances; working = busier loops; blocked = slump then drowsy; finished = happy face + bounce; body can morph into radar/orbit/progress shapes while searching/connecting/generating. CUSTOM PICTURES (secondary path): user-picked or AI-generated image ('centered portrait or emblem ... clean stylized illustration'), squircle-masked; two cached examples on Konrad's Mac are 512x512 RGB smooth low-detail art (one dark green-teal, one deep navy with small gold/orange accents) but no current roster row uses a photo. Not visually observed on screen (no GUI/screenshot allowed); described from the rendering code, palette tables and public text.

- **Format:** In-house procedural vector engine shipped inside the renderer JS. It is NOT Rive, Lottie/dotLottie, video, GIF/APNG, sprite sheets, CSS keyframes, three.js or WebGL, so there is no avatar asset file to reuse (the designers say the whole icon set 'was created using code'). Pipeline: React component GrokBotMark (class sand-grok-bot-mark; props shape, color, state, isPaused, maxFrameRate, isEmphasized, spinSignal, isFollowingPointer, eyeColor, sourceId; CSS vars --grok-bot-ink / --grok-bot-eye) -> forwardRef renderer in index.eager-platform-DUN5VkaE.js: a rig (rotation quaternion, position, squash/stretch, zoom, eyelids, expression morph, glow, poke/spin, gaze) + a state machine over 53 named states + 28 authored keyframe clips stored as JSON tracks with cubic-bezier easings (1.4-10 s each) -> 3D body projected to flat 2D silhouette path strings, eyes cut out with an SVG mask -> a live <svg> built with createElementNS and patched in place every frame (replaceChildren only when the tree shape changes) from requestAnimationFrame at <= 60 fps (maxFrameRate prop), skipped when document.hidden, one settled render under prefers-reduced-motion, a compact clip set below 48 px, clip order shuffled from a hash of the bot id so identical bots do not move in lockstep, pointer-follow gaze when enabled. List rows appear to use a pre-rendered still image (AgentAvatar isStatic defaults to true; a shared overlay stage appears to animate live marks); Cursor forum: the icon animation is 'only visible when the pointer is directly on that bot's icon'. A separate still-SVG exporter ('grok-bot-still') draws the same mark for static uses. Counts over 593 packed text files: Rive 0, @rive-app 0, .riv 0, lottie 0, dotlottie 0, three.js 0, Spline 0, pixi/babylon 0; no .riv/.lottie/.webm/.mp4/.mov/.gif/.apng among the 673 asar files; the only WebGL use is an unrelated canvas field; Assets.car holds only the app icon.

- **Count / assignment:** Procedural and effectively unbounded. The renderer supports 25 shapes x 11 colours = 275 combinations (the picker currently exposes 13 x 11 = 143; older shapes such as cylinder, gem, leaf and shield stay valid and are what Konrad's bots use). Each bot stores avatarShape + avatarColor (+ optional avatarPhoto/avatarVersion). How a bot gets one: (a) chosen in the bot's Agent settings avatar editor (character picker); (b) if unset (empty string/null) the look is derived deterministically from the bot UUID by hash: shape from 8 (blob, pebble, squircle, tablet, wedge, hex, cloud, teardrop), colour from 10 (all but black) = 80 default combos, and the same id seeds animation variation; (c) a custom picture, user-picked or AI-generated from a text description (IPC 'sand:avatar-source', kinds picked/generated), squircle-masked; (d) group chats show a cluster of up to 4 member marks. Konrad's account (roster cache, 17 conversations = 16 bots + 1 group): 7 bots have explicit pairs (Jarvis blob/black, Infra cylinder/violet, Finance Controller gem/yellow, Reactor hex/orange, DMT leaf/green, Admin shield/blue, Achilles shield/yellow); 9 bots have empty values and therefore hash defaults, which I computed by re-implementing the app's hash (not seen on screen): Boppy blob/blue, Botsilo cloud/blue, Ermes tablet/green, Vised wedge/red, Doc teardrop/brown, Plainsay hex/blue, NetROAS tablet/gray, Saldora tablet/brown, Rapper blob/green; the group is a member cluster; no row uses a photo (avatarPhoto and avatarVersion are null in all 17). Implication: Grok distinguishes 17 conversations with one shape family + colour, and 4 of the 16 bots share a colour family; a replacement needs 17 distinguishable variants of one consistent style.

- **Animation states:** idle (random Idle_A/B/D loops 4-6 s, blink, glances; Idle_B only below 48 px), listening (calm face), thinking (body morph), streaming (reply in progress = speaking; Streaming_A/B/C 2.4-2.6 s), working (Working_A-F), waiting (orbit morph), blocked (needs the user; becomes drowsy after 120 s), finished (happy face, Done_A/B, then idle after 8 s), failed (Blocked_B, then idle), sleeping (sleepy face), waking (surprised, 1.6 s), searching (radar morph), reading, coding, running, computing, controlling, happy, excited, laughing, proud, curious, playful, shy, surprised, suspicious, angry, confused, sad, drowsy, bored, scared, celebrate, approving, orbit, radar, progress, spawning, loading, dictating, sending, receiving, uploading, writing, alerting, bouncing, powering-down, humming, notifying, dragging, logo, showcase, turntable
