# Hermes Agent integration

AgentApp targets **Hermes Agent v0.21.7**, whose official date tag is `v2026.9.24`. Source excerpts and the captured local transcript are in [`hermes-v0.21.7-evidence.md`](hermes-v0.21.7-evidence.md).

## Transport and authentication

Hermes has three programmatic transports: ACP over stdio, TUI Gateway JSON-RPC over stdio/WebSocket, and the OpenAI-compatible API server over HTTP/SSE ([programmatic integration](https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/website/docs/developer-guide/programmatic-integration.md)). AgentApp uses the API server because it exposes capability, Runs, and Sessions APIs. Set a strong `API_SERVER_KEY`, run `hermes gateway run`, and connect to the loopback default `http://127.0.0.1:8642`; requests use `Authorization: Bearer …` ([API server guide](https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/website/docs/user-guide/features/api-server.md)).

The client probes `GET /health/detailed`, `GET /v1/capabilities`, and `GET /v1/models`. Chat uses `POST /api/sessions`, `GET /api/sessions`, `GET /api/sessions/{id}/messages`, and `POST /api/sessions/{id}/chat/stream`. The SSE stream includes `assistant.delta`, `assistant.commentary`, tool lifecycle, `approval.request`, `assistant.completed`, and terminal `run.*` events. Every native-session event carries `session_id` and `run_id`. `assistant.completed.content` repeats the full answer after deltas, so AgentApp uses it only when no deltas arrived. Stop and approval use the stream's `run_id` with `POST /v1/runs/{id}/stop` and `POST /v1/runs/{id}/approval`. These routes are implemented in [`gateway/platforms/api_server.py`](https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/gateway/platforms/api_server.py) and [`gateway/platforms/api_server_runs.py`](https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/gateway/platforms/api_server_runs.py).

Session listing accepts a `source` filter, but v0.21.7 only preserves a fixed allowlist and normalizes unknown values to `api_server`. This is persisted classification metadata; API-server tool selection and execution remain keyed to the API-server platform. AgentApp uses the truthful `api_server` source, establishes ownership with deterministic ID `agentapp_<bot UUID>`, and never adopts an arbitrary listed session.

History is fetched oldest-first in 500-row pages, with a 100-page safety cap that raises an error rather than returning a truncated transcript. Loads never replace or shrink local history: existing rows retain IDs, timestamps, reactions, replies, and presentations; local system/Stop/approval/delegation rows stay local; and only server turns after the latest overlap containing a full user/assistant pair are appended for established histories. Empty, malformed, null, unsupported, or non-overlapping results do not overwrite a non-empty local transcript. When overlap cannot be established—for example after a Stop-truncated reply—the conversation shows a quiet local note explaining that history was not merged. Typed text and image content arrays are rendered instead of being silently dropped.

## Multiple agents and delegation

A Hermes profile is an independent agent with its own config, credentials, memory, sessions, and skills ([profiles](https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/website/docs/user-guide/profiles.md)). With `gateway.multiplex_profiles`, named profiles are routed through `/p/<profile>/…`; every named profile requires its own `API_SERVER_KEY`. Runs are profile-scoped. The API-key server deliberately has no profile-list route, so AgentApp discovers the default model and probes operator-supplied profile names/keys. Hermes Desktop's `/api/profiles` belongs to the separate `hermes serve` backend and is not this API-key contract.

Hermes delegates through `delegate_task`, and child sessions are omitted from ordinary lists unless `include_children` is requested. The v0.21.7 native HTTP session-stream implementation does **not** emit `subagent.start` or `subagent.complete`. AgentApp retains tolerant parsing for those names for fixtures and forward compatibility, but does not claim v0.21.7 produces them. See [delegation](https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/website/docs/user-guide/features/delegation.md).

## Compatibility

AgentApp probes `/v1/capabilities` before any Sessions API call and caches the result per server/profile. If that route is absent (the 0.16–0.20.x family), it skips REST session create/history and uses `POST /v1/chat/completions` with OpenAI SSE, a client-owned `X-Hermes-Session-Id`, and `hermes.tool.progress`. Cancellation then means closing the stream because the old response does not expose a controllable run. On native sessions, AgentApp captures the current run ID, cancels locally immediately, then posts `/stop` with an eight-second timeout and reports one result beside the stopped turn. A failed or timed-out server Stop is likewise recorded as “Hermes Stop failed” beside that turn; late feedback never clears or reports against a newer run. Registry cleanup is stream-token-conditional, so an old cancelled stream cannot erase a newer run ID. Text typed during the brief Stop-cleanup window is retained if the store cannot yet accept a new send. Approval cards show “Command unknown” and disable Approve when an event omits command text, and the store rejects such approvals even if called outside the UI. The checked v0.21.7 source emits the redacted command in the top-level `command` field; its general redactor can produce `***`, head/tail `...` masks, and `«redacted:…»` sentinels, so redacted-looking commands are never automatically approved. The parser also accepts non-empty command and identity fields in wrapped approval payloads used by compatible status surfaces; only raw `command` drives approval while `display_command` is presentation-only. Named profile routing, durable REST session loading, and approval resolution require the newer surface.

## Verification note

Verification used the existing isolated official `v2026.9.24` source/install at `/private/tmp/hermes-v0.21.7-src` and `/private/tmp/hermes-test`. No personal or fleet server was contacted.

A real throwaway gateway previously ran on port 18642 with a dummy API-server key and no readable provider credentials. Health, capabilities, models, deterministic session create/409, paged history, and native session SSE routing were exercised then; the turn reached Hermes but returned a provider-authentication failure. In the fifth pass, the native fixture failed while binding `127.0.0.1:18643`; because the script uses `set -e`, the legacy fixture never ran. The sixth-pass retry had the same result: native failed at the bind, legacy never ran, and the isolated throwaway gateway also failed to bind (this time at its default port 8642). Nothing live or fixture-backed executed in either retry. Exact sixth-pass output is saved in `hermes-fix6-fixtures.log`, `hermes-fix6-live-gateway.log`, and `hermes-fix6-live-client.log`.

The Swift unit tests have never executed on this host. With `DEVELOPER_DIR=/Applications/Xcode-16.2.0.app/Contents/Developer`, `swift test` aborts before package compilation: Xcode 16.2's `CoreDevice.framework` requires missing symbol `_XPCTypeBool` from the installed macOS `Mercury.framework`. The sixth-pass command and output are saved in `hermes-fix6-swift-test.log`; it again exited 72 before compiling tests. The production target builds with the direct compiler fallback (`hermes-fix6-build.log`). A provider-backed long-running cancel, real approval pause, and delegated child remain unverified live.

## MacBook install checklist

1. Copy the entire reviewed source tree **including `.git`** with `scp` or `rsync` (do not exclude dotfiles). Packaging reads the source commit from `.git`; cloning is not equivalent while the reviewed changes remain uncommitted. This transfer also avoids adding a browser-download quarantine attribute.
2. Run `swift test` on the MacBook and stop the install if any test is red.
3. On an Apple Silicon MacBook, run `./scripts/build.sh`, then `./scripts/package-release.sh` on that same source tree. The package name and bundled `SOURCE.txt` identify the source SHA, dirty state, and a hash plus file list for the dirty summary.
4. Smoke-test Stop during a reply, a second send/Stop, and a failed Stop if practical; confirm each note stays beside its stopped turn. Confirm the first real approval displays its command before enabling Approve. Reopen the bot and confirm history merge neither shrinks nor duplicates the transcript.
5. Expect macOS Keychain access prompts after rebuilds because the ad-hoc code signature changes.
