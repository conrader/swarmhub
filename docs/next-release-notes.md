# Changes since SwarmHub 0.8.23

- **Auto mode is on by default.** A bot works in its sandbox and automatic review answers its requests for wider access, so it no longer stops to ask you. Updating the workspace turns Auto on once for every existing bot, except bots set to ask before every tool call and read-only document reviewers. Turn it off for one bot in **Details → Approvals**; that choice is kept.
- Moving bots to another server keeps each bot's Auto mode. Before, a move left every moved bot in Standard mode on the new server, and their next sessions asked for permission in a read-only sandbox.
- The main bot now looks into a workspace problem itself when looking only reads (a terminal prompt, a status, a log) and reports what it found with a recommendation, instead of asking whether it may look. It still asks before work that changes, sends, deletes or spends.
- A goal you stopped no longer stays above the message box. A goal that ended by itself (completed, step or spending limit) shows its reason until you choose **Dismiss**.
- **Bots in Auto mode finish a task without asking about its steps.** Their standing rules now say that reading, building, testing, editing, changes that can be undone, and removing files that can be made again (caches, temporary files, build output, old logs) need no question. A bot still asks, once and with a recommendation, before deleting data that cannot be restored, sending something to other people, spending money or deploying to production. Bots with Auto off keep the stricter rules.
- A check-in that gets no answer, or does not reach the bot, is tried once more before you are told. If the second try fails as well, the notice says so and the main bot is asked to look at that bot's terminal. An answer that arrives late takes the second try back.
- A scheduled routine run that comes due while its agent is working or at a prompt waits up to 10 minutes for it instead of skipping. A test run and a webhook event are still answered at once.
- A goal continues by itself in two more cases: when a step finished while SwarmHub was closed and reported progress, and when the goal was only waiting for a workspace prompt that has since been answered. Before, both needed **Resume**.
- Bots are told to give an independent part of a larger task to a helper.
- **Goals keep running with SwarmHub closed.** On a workspace with this update, `/goal` hands the goal to the server. The server sends each step to the bot, reads how it ended and sends the next one, also while this Mac sleeps or SwarmHub is closed, and the chat shows what happened when you come back. A goal that asked you a question goes on as soon as you answer in the chat. A goal without `--steps` stops after 40 steps. Goals with a spending limit or attached files still run from this Mac.
- **Set how much each bot asks.** **Details → Approvals → Autonomy** has three levels: **Asks first**, **Asks when it matters** and **Does not ask**. One button applies the level to every bot on the server. The bot is told at once. At every level, telling a bot "do not ask me about this" settles it for the rest of the conversation.
- **Alerts when SwarmHub is closed.** In **Settings → Servers**, give the server an address (an ntfy topic, a Slack incoming webhook). The server posts a short line there when a bot finishes a goal, needs your answer or misses a check-in. The bot's name and the start of its message are sent to that address, so use one only you read.
- A scheduled routine run now starts up to 30 minutes late instead of being skipped after 30 seconds, and a routine whose session ended moves to the session its bot has now.
- Turning **Auto mode** on while a bot's session sits at a permission prompt ends that session, so its next message starts in Auto instead of waiting on the prompt.
- **AIs on a server.** **Settings → Servers** now lists the AIs on a server you reach over SSH. **Add** registers one that is installed there, and **Install** installs Codex, OpenCode or Gemini CLI on the server with npm. Signing in is still done once in the AI's terminal on the server.
