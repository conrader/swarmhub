# SwarmHub 0.8.140

- **Auto mode is on by default.** A bot works in its sandbox and automatic review answers its requests for wider access, so it no longer stops to ask you. Updating a server turns Auto on once for every existing bot, except bots set to ask before every tool call and read-only document reviewers. Moving bots to another server keeps each bot's setting. Turning Auto on while a session sits at a permission prompt ends that session, so the next message starts in Auto.
- **Set how much each bot asks.** **Details → Approvals → Autonomy** has three levels: **Asks first**, **Asks when it matters** and **Does not ask**, with a button to use one level for every bot on the server. The bot is told at once. At the two levels that still ask, telling a bot "do not ask me about this" settles it for the rest of the conversation.
- Bots can diagnose incidents, restore a failed service to its known configuration and clean up verified redundant copies within their assigned work without asking for fresh consent. A command reviewer checks what the proposed operation would actually do.
- **Goals keep running with SwarmHub closed.** On an updated server, `/goal` hands the goal to the server, which sends each step, reads how it ended and sends the next, also while this Mac sleeps. A goal that asked you a question goes on when you answer in the chat. A goal without `--steps` stops after 40 steps. Goals with a spending limit or attached files still run from this Mac. A goal you stopped no longer stays above the message box.
- **Alerts when SwarmHub is closed.** In **Settings → Servers**, give the server an address such as an ntfy topic or a Slack incoming webhook. The server posts a short line there when a bot finishes a goal, needs your answer or misses a check-in. The bot's name and the start of its message are sent to that address, so use one only you read.
- **AIs on a server.** **Settings → Servers** lists the AIs on a server you reach over SSH. **Add** registers one that is installed there, and **Install** installs Codex, OpenCode or Gemini CLI with npm. Signing in is still done once in the AI's terminal on the server.
- A check-in that gets no answer is tried once more before you are told, and the main bot is asked to look at that bot's terminal. The main bot now looks into a problem itself when looking only reads, instead of asking whether it may.
- A scheduled routine run waits up to 10 minutes for a busy agent, may start up to 30 minutes late, and follows its bot to the session the bot has now.
