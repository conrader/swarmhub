## Goal

Konrad (2026-10-13) attached "POZNAN-SYPLPOZ01-….pdf" and got "only PNG, JPEG, GIF and WebP images and text files up to 200 KB can be sent." After this phase, attaching a PDF just works:

## Facts (recon 2026-10-13, read-only)

- **No file path exists on the box.**
  - Both 0.20.5 and 0.21.7 answer 400 `unsupported_content_type` to any `file` or `input_file` part and to a `data:application/pdf` URL. Image parts accept only `data:image/…` or http(s).
  - One normaliser serves `/v1/chat/completions`, `/v1/responses`, `/v1/runs` and `/api/sessions/{id}/chat[/stream]`.
  - 0.20.5 has no upload or files route. `session_resources=true` is a bare flag; do not infer a route from it.
  - 0.21.7's `POST /v1/artifacts/upload` is browser-extension control. It needs browser control on, takes 10 MB, expires in 300 s, allows one download, returns no path, and is not wired to chat or agent tools.
  - The agent could not read a PDF on the box anyway: `read_file` needs the uninstalled `firecrawl-anydoc`, and there is no pypdf or poppler.
- **Limits on the chat path:**
  - 10 MB request body.
  - **65,536 characters per text part or per plain string, silently truncated.** This applies to string `content` on any message, including history messages in a `messages` array, not only to parts. The server counts Python `len`, which is Unicode code points.
  - 1000 parts.
  - Parts are joined with `\n`.
- **The latent bug.** The app has the same truncation today. `AttachmentEncoder.compose` inlines a text file up to 200 KB as one string. Anything over about 64 KB reaches the model cut off, with no error.
- The model gets images natively if it has vision. Otherwise Hermes describes them with `vision_analyze`, whose backend was not verified. It never gets a PDF. Whether `gpt-5.6-terra` takes images was not checked.
- Konrad's PDF is not on the VPS and was not opened, so whether it has a text layer is unknown. Never read, print or log attachment contents in reports, tests or the probe.

2. **Split long text.** This is the fix, and it is a deliberate change from "text files as today".
   - Add one splitter in `HermesBackend` that every text going out passes through:
     - the `input` of `sendSession`;
     - the last user message;
     - **every history message** in `sendLegacyChat`, since the server truncates plain strings too;
     - the group `context` message.
   - Any text over 60,000 **Unicode scalars** (not `Character`, not UTF-16) becomes several `{type:text}` parts, each ≤60,000 scalars, in order. Below the limit, behaviour is unchanged: a plain string when there are no images.
   - Split so the server's `\n` join reproduces the original:
     - Cut at a line break and drop that one `\n`.
     - If a 60,000-scalar window has no line break, cut at a space and drop it.
     - If it has neither, hard-cut. The join then adds one `\n`, so history reconciliation can mismatch. To keep reconciliation reliable, make `comparable` collapse whitespace runs on both sides, only when either side is over 60,000 scalars.
   - Add one guard in the backend: if the estimated JSON body would exceed 9,500,000 bytes, throw a plain `BackendError` ("This conversation is too large for one request. Start a new chat or fork it.") before sending. The legacy path re-sends all history, and a 413 would otherwise read as a mystery failure.

4. **PDF text.**
   - Open with `PDFDocument(url:)`. A nil result gives `unreadable(name)`.
   - Read per page with `PDFPage.string`. Each page is `--- page N ---` plus its text.
   - Caps (constants, injectable):
     - extracted text ≤120,000 characters;
     - ≤100 pages.
   - Stop at a whole page, then append `[truncated: pages 1–K of N]`. If page 1 alone exceeds the cap, cut inside the page at a line break and still append the marker.
   - The composed block (`File:` header, fence, summary) can exceed 120,000, and the splitter handles that.
   - The block starts with a summary line. Variants:
     - `PDF: 12 pages, text extracted`
     - `…, 3 pages read by OCR`
     - `…, 3 pages read by OCR (no Polish model, accents may be wrong)`
     - `…, truncated at page K of N`

   - The same summary shows in the chip. The model sees it too, since it is the block's first line.
   - The block is re-sent in the history of later turns on the legacy path, which is why the cap is low (120,000 characters is about 30,000 tokens per turn).

5. **Scanned pages.**
   - **Textless test.** A page is textless if its trimmed text has <16 non-whitespace characters, or >30% U+FFFD or control characters. It does not catch a wrong-but-valid text layer; say so in the README.
   - For each textless page, in order:
     - **(a) Vision OCR** (`VNRecognizeTextRequest`, `.accurate`, language correction on).
       - Query `supportedRecognitionLanguages()`.

       - Otherwise use `automaticallyDetectsLanguage = true` and flag "no Polish model" in the summary.
       - Sort observations top-to-bottom, then left-to-right.
       - Run it synchronously off the main actor. At most 20 OCR pages.
     - **(b) Page image.** A page whose OCR returns <16 characters is rendered at long edge ≤1600 and attached as a JPEG through `prepare(imageData:)`. At most 4 images per PDF, each ≤0.7 MB. The images share the 10 MB body with base64 overhead.
       - `prepare(imageData:)` only caps at 5 MB, so the reader runs its own encode loop (quality 0.7, 0.5, 0.35, then shrink the edge) until ≤0.7 MB.
       - If it cannot fit, skip the image and count it in the summary.
       - Name them `<file> — page N.jpg`. They appear as separate tiles.
   - **Rendering.**

## Risks

- **Polish OCR is unverified.** If `pl-PL` is missing from the Mac's Vision list, OCR runs on auto-detect and may mangle diacritics. The summary says so, and the page-image fallback then matters. Report the finding; do not tune to hide it.
- **A garbage text layer.** The heuristic catches U+FFFD and control characters, not wrong-but-valid letters.
- **Rendering.** Rotation and crop-box behaviour are unverified, so the rotated fixture is required. DOCX import may hang off the main actor (item 7).
- **Text PDFs inflate every later turn on the legacy path.** The cap is the control. The 9.5 MB guard prevents a silent 413.
- **The page-image fallback is the weakest path.** Whether the model takes images (`supports_vision`) is unknown, and `vision_analyze`'s backend is unverified. OCR text comes first for that reason.
- **Hard cuts** in text with no line breaks or spaces change the server-side text by one `\n`. The whitespace-collapsing `comparable` covers history matching.

## Out of scope

- Sending the PDF itself, a password prompt, table or layout recovery, per-page selection, OCR beyond 20 pages, and other formats (HTML, RTFD, XLSX, PPTX).
- Any change on the box (installing a PDF reader for the agent, a file route).
- Splitting the persona/system prompt.
