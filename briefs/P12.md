## Goal
Konrad (2026-10-13): "ability to connect OpenClaw". `BRIEF.md` always named it the second backend ("Hermes Agent first, then
OpenClaw") and the repo holds only a stub (`BackendKind.openClaw`, a 13-line `OpenClawBackend.swift` that throws, an `openClawURL`
field). OpenClaw (openclaw.ai, github.com/openclaw/openclaw, MIT, OpenClaw Foundation; formerly Clawdbot, then Moltbot) is the
self-hosted personal agent: a long-running Gateway on the user's own machine or server runs the agents, tools, skills, cron and many
chat channels (WhatsApp, Telegram, Slack and more) against the user's own model accounts. Hermes ships `hermes claw migrate` for it,
so it is the same category as the boxes Torvli already serves. After P12 a user adds a Gateway once (URL and token), pairs this Mac
as an operator device, picks agents, and each agent becomes a bot beside the Hermes bots: streaming chat, Stop, steer, images,
reply-in-thread, history, and the agent's tool-approval requests answered natively under the bot's own policy (Ask me, Rules,
Reviewer bot). Torvli holds no model or provider key; persona, tools, skills and memory stay in the Gateway. Settings and the chat
say plainly what is connected, what the link can do, and what is unavailable.

## Facts (recon 2026-10-13, read-only; confirm in the references before relying on them)
- **Thing.** npm `openclaw` 2026.10.3 (`latest` on 2026-10-13; `extended-stable` 2026.8.35), MIT, bin `openclaw`, Node ≥24.16.
  Versions are `YYYY.M.N` and ship every few days. The repo LICENSE is MIT, © OpenClaw Foundation.
- **Surface used.** Gateway WebSocket RPC, wire protocol **v4**, `ws://127.0.0.1:18789` by default (loopback bind); remote access is
  an SSH forward, Tailscale Serve or `wss://`. Operator clients send `minProtocol = maxProtocol = 4`. **Not used:** the
  OpenAI-compatible HTTP tier (off by default, chat only, its bearer token restores every scope including `operator.admin`, and the
  docs tell native clients to use the WebSocket device-token flow instead), the `openclaw` CLI, ACP, MCP, the Admin HTTP RPC plugin.
  The README line "not an OpenAI-compatible HTTP endpoint" is out of date.
- **Frames.** JSON text frames: `{type:"req",id,method,params}`, `{type:"res",id,ok,payload |
  error{code,message,details?,retryable?,retryAfterMs?}}`, `{type:"event",event,payload,seq?}`. The first client frame must be
  `connect`. Branch on `error.code` and `error.details.code`, never on `message`. A frame is ≤64 KiB before auth, then
  `policy.maxPayload` (25 MiB in the doc example). Replies can arrive out of order; side-effecting methods need an `idempotencyKey`.
- **Handshake.** Event `connect.challenge {nonce, ts}`; the client answers `connect {minProtocol, maxProtocol,
  client{id,version,platform,mode,displayName?,deviceFamily?}, caps, role, scopes, auth{token | deviceToken},
  device{id,publicKey,signature,signedAt,nonce}, userAgent?}`. `ConnectParams` is `additionalProperties:false`. `client.id` is a
  closed enum of 17 ids (`gateway-client` is the generic SDK id; `openclaw-macos`, `openclaw-control-ui`, `webchat-ui`, `cli`… are
  first-party) and `client.mode` is webchat, cli, ui, backend, node, worker, probe or test (the official macOS app connects as
  `openclaw-macos` / `ui`; the doc example's `mode:"operator"` is not in the schema). The server gives the handshake 30 s; the
  references wait 6–15 s for the challenge. `hello-ok {protocol, server{version,connId}, features{methods,events,capabilities?},
  snapshot, auth{role,scopes,deviceToken?}, policy{maxPayload,maxBufferedBytes,tickIntervalMs,
  attachments?{maxBytes,maxImageBytes}}}`. `features.methods` is a conservative discovery list, not a full enumeration.
- **Identity and signing.** Ed25519. `device.id` = lowercase hex SHA-256 of the raw 32-byte public key; `publicKey` and `signature`
  are base64url without padding. Signed string:
  `v3|deviceId|clientId|clientMode|role|scopes|signedAtMs|token|nonce|platform|deviceFamily` (scopes joined with `,` as sent;
  `token` = the credential actually used, shared or device, empty if none; `platform` and `deviceFamily` trimmed and

- **Pairing and credentials.** An unknown device gets `NOT_PAIRED` with `details {code:"PAIRING_REQUIRED", requestId, reason
  (not-paired | role-upgrade | scope-upgrade | metadata-upgrade), recommendedNextStep, retryable}`; the operator approves on the
  Gateway host with `openclaw devices list` and `openclaw devices approve <requestId>`. By default a direct loopback connect pairs
  silently, and so does one through an SSH port forward (the Gateway sees loopback); tailnet and LAN peers count as remote. The same
  identity and parameters keep the same request; changed parameters supersede it. `hello-ok.auth.deviceToken` is then the reusable
  credential for this device and role. The shared Gateway token is an owner credential, printed on the Gateway host by `openclaw
  gateway auth-token --show` (interactive terminal only). A shared secret travels in `auth.token` for token and password mode alike;
  the reference client sends a stored device token as `auth.deviceToken` and signs with it. Other codes: `AUTH_TOKEN_MISMATCH`
  (+`canRetryWithDeviceToken`), `AUTH_TOKEN_MISSING`, `AUTH_SCOPE_MISMATCH`, `AUTH_RATE_LIMITED`, `PROTOCOL_MISMATCH`,
  `DEVICE_AUTH_*`, `OPERATOR_ACCESS_DENIED`, and a retryable `UNAVAILABLE` with `details.reason:"startup-sidecars"` and
  `retryAfterMs`.
- **Scopes.** For "a full interactive chat client that renders approval prompts" the docs say `operator.read`, `operator.write`,
  `operator.approvals`. The reference client defaults to `operator.admin` when given none, so always send them. Scopes are
  guardrails inside one trusted operator domain, not tenant isolation. Cron writes, config and skill install need `operator.admin`.
- **Methods Torvli uses** (all `since ≤2026.7`):

  | Torvli | Gateway call | Scope |
  |---|---|---|
  | list agents | `agents.list` → `{defaultId, mainKey, agents[{id, name?, identity?}]}` | read |
  | new chat session | `sessions.create {agentId, key, displayName, idempotencyKey}` → `{ok, key, sessionId?}` | write |
  | send | `chat.send {sessionKey, agentId?, message, idempotencyKey, attachments?, timeoutMs?, queueMode?}` → `{runId, status}` | write |
  | steer | `chat.send` with `queueMode:"steer"` (others: `followup`, `collect`, `interrupt`) | write |
  | stop | `chat.abort {sessionKey, agentId?, runId?}` | write |
  | history | `chat.history {sessionKey, agentId?, limit?, maxChars?}` → `{messages, sessionInfo{hasActiveRun,activeRunIds?}, inFlightRun?{runId,text}}` | read |
  | thread | `sessions.create {parentSessionKey, fork:true, forkFrom:"last-completed", key, agentId}` (`sessions.fork {sessionKey, entryId}` forks at an entry) | write |
  | approvals | events `exec.approval.requested` / `.resolved`; `exec.approval.list`; `exec.approval.resolve {id, decision}` | approvals |

  `sessions.create` is scoped `dynamic` in the schema (the plain forms Torvli uses need `operator.write`).

- **Events.** `chat {runId, sessionKey, agentId?, seq, state: status | delta | final | aborted | error, deltaText, message?,
  replace?, usage?, stopReason?, errorMessage?, errorKind?}`. A `message` is the authoritative full snapshot (it already contains
  the delta); `replace:true` means `deltaText` is the whole new text; an append without a baseline is skipped (that is
  `mergeChatStreamMessage`). `agent {runId, seq, stream, ts, data}`: tool events (`data.phase`, `data.name`) arrive only if
  `connect.caps` has `tool-events`; assistant text is duplicated in `agent`, so render `chat` only and send cap
  `chat-only-assistant-text`. `tick {ts}` every `policy.tickIntervalMs`; `shutdown`. Approval events carry `{id, request{command,
  cwd, host, agentId, sessionKey, runId…}, createdAtMs, expiresAtMs}`.
- **Session keys** are canonical lowercase `agent:<agentId>:<name>`; `agent:main:main` is the agent's main session, which channel
  DMs share. **Attachments** are `{type, mimeType, fileName, content}` with `content` raw base64 (not a data URL); ceilings in
  `policy.attachments` (20 MB, images 6 MB in the example) and the whole frame must fit `maxPayload`.
- **Approvals.** `decision` is `allow-once`, `allow-always` or `deny`; `allow-always` mints a standing grant on the Gateway, which
  Torvli never sends. A client declaring cap `exec-approvals` (or `approvals`) also receives approvals raised by the Gateway's own
  cron automations; with none connected they are denied at once.
- **Torvli today.** `AgentBackend` is Hermes-shaped: `sessionTransport()` returns a `HermesTransport`, `features()` returns Hermes
  flag names (`run_steer`, `session_fork`, `session_chat_streaming`) that the UI gates on, and the session id lives in
  `Bot.hermesSessionID`. `AppStore.backend(for:)` builds the stub; `AppStore.send`, `groupTurn` and the loop in `AgentApp.swift`
  switch exhaustively over `AgentEvent`; about 20 sites guard on `bot.backend == .hermes` (grep it); stop and approval messages say
  "Hermes".

## Design
- **One WebSocket per saved Gateway**, shared by its bots: `OpenClawHub` (actor) owns `GatewayConnection` actors over a
  `GatewayTransport` seam. Nothing connects at launch; first use connects, the link stays up and reconnects. The seam matters twice:
  URLProtocol cannot intercept WebSocket tasks, and the tests need a scripted Gateway.
- **Identity.** Torvli is a third party with no `client.id` of its own, so it connects as `gateway-client`, mode `ui`, platform
  `macos`, deviceFamily `Mac` (constants in one place; changing one later can make the Gateway ask for a `metadata-upgrade`
  re-approval; never use a first-party id). One Ed25519 key per Gateway, so two Gateways cannot correlate this Mac.
- **Least privilege.** Scopes exactly `operator.read operator.write operator.approvals`; caps `chat-only-assistant-text`,
  `tool-events` and `exec-approvals` (Torvli implements all three; the last also makes it an approval surface for the Gateway's cron
  automations, which then wait for an answer instead of failing at once, and the Gateway sheet says so). The shared token serves the
  first connect only: once the device token is stored and read back, the shared token leaves the Keychain (unless "Keep the Gateway
  token" is ticked).
- **Binding.** `Bot.openClaw = OpenClawBinding {gatewayID, agentID, sessionMode: own | main}` (optional, `decodeIfPresent`, so old
  stores load). The canonical session key goes in the existing `hermesSessionID` (documented reuse; renaming is out of scope). `own`
  (default) makes a session just for Torvli; `main` uses `agent:<id>:<mainKey>`, shared with the agent's channels, so steer and
  interrupt there act on the user's real assistant. OpenClaw has no system-prompt parameter (identity lives in the agent's
  workspace): `bot.persona` is sent nowhere.
- **Gating** comes from `hello-ok`, never a version: a feature is available only if its method is in `features.methods` and its
  scope is in `auth.scopes`. What the user sees: no Gateway configured, only the empty Settings pane and an explanation in the bot
  editor (no network); Gateway unreachable or unpaired, a banner and a disabled composer; a missing method or scope hides the
  control (Steer, Reply in thread, attachments, approvals) and the Overview says why.

### Part A — Connect (no chat yet)
1. **Wire types** (`Sources/AgentApp/OpenClaw/JSONValue.swift`, `GatewayFrame.swift`). A `Sendable` `JSONValue` (Codable, Equatable,
   typed accessors) instead of `[String: Any]`; frames decode req, res and event and ignore unknown fields and events;
   `GatewayError` and the `details` fields above are typed. A malformed frame is skipped, never a crash (fuzz test).
2. **Transport** (`GatewayTransport.swift`): a small protocol (`open(URLRequest)`, `send(String)`, an incoming-text
   `AsyncThrowingStream`, `close(code:reason:)`) and `WebSocketTransport` over `URLSessionWebSocketTask`. Set `maximumMessageSize`
   to 32 MiB at creation (the 1 MiB default fails the receive with "message too long" on a long `chat.history` or an image frame);
   text frames only; the server pings and URLSession pongs; also `sendPing` every 15 s and treat a failed ping as a dead link (the
   Swift client does). Keep `URLRequest` in the signature (custom upgrade headers come later). Confirm with a five-line probe that
   URLProtocol does not see WebSocket tasks. Optional smoke test of the real transport against a loopback-only `NWListener`
   WebSocket (skip it if it prompts or flakes, and say so).
3. **Identity** (`GatewayIdentity.swift`): CryptoKit `Curve25519.Signing`; the raw private key is stored base64 in the Keychain
   through the existing `HermesKeyStore` seam (`openclaw.<gatewayID>.device-key`; tests use `InMemoryKeyStore`); if the write fails,
   stop with an error, never fall back to a memory-only key. `deviceId`, base64url helpers, `v3` and `v2` builders, `sign`. Tests:
   the vector above (payload strings, `publicKey`, `deviceId` exact; **verify** the two Node signatures with the CryptoKit public
   key; never compare your own signature bytes, CryptoKit may randomise them); reload gives the same id; metadata normalisation; the
   private key appears in no `String(reflecting:)`, `store.json` or UserDefaults.
4. **Connection** (`GatewayConnection.swift`, `GatewayConnection+Handshake.swift`, `OpenClawHub.swift`); inject a `Clock` for every
   wait.
   - Handshake: wait for the challenge (15 s), send ONE `connect`: min = max = 4; `client{id gateway-client, mode ui, version
     CFBundleShortVersionString, platform macos, deviceFamily Mac, displayName <device name>}`; role `operator`; the scopes and caps
     above; `auth{token: shared}` or `{deviceToken}`; `device{…}` with `signedAt` = the challenge `ts` and its nonce; `userAgent
     torvli/<version>`; nothing else (no locale, commands, permissions, admin scope). Sign v3; on `DEVICE_AUTH_SIGNATURE_INVALID`
     retry once with v2. From `hello-ok` require `protocol == 4` and keep version, methods, events, scopes, policy; persist
     `auth.deviceToken` (write, read back, only then drop the shared token).
   - Requests: UUID ids, a correlation map, 30 s timeout (history 15 s, abort 10 s), out-of-order replies. Every pending request fails
     on close and is never replayed. Events fan out to subscribers by predicate and are buffered from subscription time.
   - Liveness: tick watchdog closes with code 4000 after silence beyond 2 × `policy.tickIntervalMs` (30 s before hello). Reconnect 1 s
     doubling to 30 s, ±20% jitter, reset after 30 s up, at once on `NSWorkspace.didWakeNotification` and on Retry.
   - Pairing: keep the device key, role, scopes and auth identical (nonce and signature differ per attempt) and retry every 5 s for up
     to 10 minutes, always showing the latest `requestId`. `AUTH_TOKEN_MISMATCH` retries once with the stored device token, only
     when `canRetryWithDeviceToken` is true and the endpoint is trusted (loopback or `wss://`). `UNAVAILABLE`/`startup-sidecars`
     waits `retryAfterMs`.
   - Outcomes map to `GatewayState`: `connecting`, `pairingRequired(requestId, reason, deviceId)`, `connected(summary)`,
     `reconnecting(in)`, `failed(GatewayFailure)` with `unreachable`, `notOpenClaw` (no challenge), `unsupportedProtocol(expected)`,
     `tokenRejected`, `tokenMissing`, `deviceRevoked` (the stored device token was refused, e.g. `AUTH_DEVICE_TOKEN_MISMATCH`: drop
     it), `rateLimited(retryAfter)`, `accessDenied` (`OPERATOR_ACCESS_DENIED`: keep backing off), `insufficientScopes(missing)`.
     States publish to a `@MainActor` `OpenClawStatus` (ObservableObject) that `AppStore` owns; `AppStore.init` takes an optional
     hub so tests inject a scripted one.

### Part B — Chat
7. **Capabilities** (`OpenClawCapabilities.swift`). Availability = method listed and scope held, from one method-to-scope table in
   code. The list is conservative and parameters are newer than methods, so an optional call or parameter answered with
   `INVALID_REQUEST` or unknown-method marks only that feature unavailable for the connection (steer without `queueMode`, threads
   without fork, a session without `displayName`) instead of failing the whole action or hiding it blindly. `features()` returns the
   Hermes-named flags: `chat.send` gives `session_chat_streaming` and `run_steer`; `sessions.create` gives `session_fork`.
   Table-driven tests (methods × scopes), including a read-only grant and a Gateway without `chat.abort`.
8. **Backend** (`OpenClawBackend.swift` rewritten, `OpenClawBackend+Chat.swift`, `OpenClawRunMapper.swift`,
   `OpenClawHistory.swift`). `kind .openClaw`; `sessionTransport()` returns `.nativeSessions` (deliberate reuse).
   - `createSession`: `sessions.create {agentId, key: "agent:<agentId>:" + the id lowercased with _ → -, displayName: "Torvli ·
     <title>", idempotencyKey: the key}`; return the response `key`; an existing key is adopted; if an optional parameter is
     rejected, retry once with `{agentId, key}`. `systemPrompt` is ignored.
   - `send`: subscribe to the session's events, then `chat.send {sessionKey, agentId, message: last user text, idempotencyKey (fresh
     UUID), attachments?}`; take `runId` from the ack and replay only that run's buffered events (before the ack, match by
     `sessionKey`; after it, by `runId`). The stream ends on `final`, `aborted` or `error` of the primary run; terminal events of
     steer inputs are ignored.
   - Mapper (pure): a `delta` with `message` replaces the text with the snapshot's visible text (as a `.token` when it extends the old
     text), `replace:true` gives the whole new text, a bare `deltaText` appends, an append with no baseline is skipped; `final`
     whose `message` differs from the streamed text replaces it, then `.completed`; `aborted` is `.completed`; `error` is
     `.failed(errorMessage)` with `errorKind` in plain words (rate limit, timeout, context too long, refusal); `status.phase` and
     `retry` become `.status` text; tool events become `.status("<name>")`. Visible text = `text` blocks only; strip
     `[[reply_to_current]]`, `[[reply_to:<id>]]`, `[[audio_as_voice]]`; an exact `NO_REPLY` is an empty reply. Keep the highest
     `seq` per run and ignore repeats. Add `AgentEvent.replace(String)` and handle it in `AppStore.send`,
     `AppStore+Groups.groupTurn` and the loop in `AgentApp.swift`.
   - Stop: a ledger holds `sessionKey, agentId, runId` of the active run; `stopTarget` gives `.serverRun(runId)` or `.noActiveRun`,
     `requestStop` sends `chat.abort`. Steer: `chat.send` with `queueMode:"steer"` and a new key; the ack's `runId` joins the ignore
     set.
   - `loadMessages`: `chat.history {sessionKey, agentId, limit: 200, maxChars: 20000}` mapped to `BackendMessage` (user and assistant
     rows with non-empty visible text, `[Image: …]` for image blocks, tool and system rows skipped, id = `transcriptMessageID`).
   - A reconnect inside a send: re-read `chat.history`; if the run is in `sessionInfo.activeRunIds` continue from `inFlightRun.text`;
     if it finished, take the final assistant message; else fail with "Connection lost; the run may still be running on the
     Gateway". Never resend by hand (the same `idempotencyKey` makes a retry safe).

## Security and privacy
- **Leaves the Mac, only to the Gateway the user entered:** the client metadata above (no hostname, locale or account name; the
  device name is the editable "Torvli (Mac)"), this Gateway's public key and signatures, the token on the first connect, chat text,
  images and text files the user attaches, approval decisions, and session titles "Torvli · <bot>" (visible to anyone with Gateway
  access). Nothing goes to any other host: no telemetry, no Bonjour browse, no HTTP tier.
- **Never sent or stored:** Hermes keys, other bots' content, provider or model credentials (Torvli has none), the local store.
- **Secrets only in the Keychain** (token, device token, private key; per Gateway; not synchronisable). No `connect` or frame
  logging. Every error string passes one redactor that removes the three secrets.
- **Honest warnings in Settings and README:** a paired device can read and write the Gateway's sessions, and an agent that may run
  tools can run commands on the Gateway host, with approvals only if its policy asks for them. Public `ws://` is refused; plaintext
  on a private network needs a tick box.
- Agent output is untrusted: same renderer as Hermes; approval text is plain text with its host and cwd; Torvli approves only
  `allow-once`, only on a user action or a user-written rule, and never for approvals it did not start.

## Risks
- **First contact is unproven.** Everything is built from the published schema and docs and checked against a fake. Likeliest
  surprises: the `gateway-client` + `ui` identity policy, the signature version, session-key shape, attachment encoding. The fake
  enforces the schema's key sets, and each assumption sits behind a constant.
- **Third-party identity.** The `client.id` registry is closed, so Torvli rides the generic `gateway-client`. If a Gateway refuses
  it, connect fails with a schema error (shown verbatim in the state line); the fix is the constants, or an upstream id.
- **Fast protocol churn.** Releases come every few days; v4 is stable but additions are constant. Decoders are lenient, features
  come from `hello-ok`, `PROTOCOL_MISMATCH` has its own state, and the tested version is written down. A v5 breaks Torvli until
  updated (the docs say client and Gateway upgrade together).
- **Owner-level trust.** The token is an owner credential and `operator.write` lets Torvli instruct an agent that may have tools.
  The short token life, per-Gateway keys, `allow-once` only and the warnings reduce this; a stolen device token is still not
  harmless.
- **Pairing friction.** Remote or LAN pairing needs a manual `devices approve`; only loopback (an SSH forward included) is silent.
  Changing `platform`, `deviceFamily`, `client.id` or `mode` later can force a re-approval.
- **History and streaming edges.** The Gateway normalises history (`NO_REPLY`, directive tags, truncated rows) while the local copy
  holds streamed text, so the merge may report divergence (it never deletes). Missing baselines, `replace` and reconnect-in-run are
  the likely bugs.
- **`main` session mode** shares context with the user's channels; a steer or interrupt there lands in their real conversation. It
  is off by default and named plainly in the editor.
- **Local Network prompt (unverified).** A `ws://` to a LAN address should trigger the macOS 15 Local Network permission; check it
  once on the MacBook with a LAN address and say what happened. Loopback (the recommended tunnel) never prompts.
- **Sleep and dead sockets.** URLSession can take long to notice a dead link; ping, tick watchdog, wake retry and request timeouts
  cover it, but only a real Gateway shows how well.
- **Collisions.** P11 moves the Hermes model section and P10 changes import: touch `InfoPanel`/`BotCapabilitiesView` only to add the
  OpenClaw branch, keep the rest in new files, and rebase instead of merging twice.
- **Brand.** The name says what Torvli connects to; no OpenClaw logo or artwork, SF Symbols only. The MIT reference code is read,
  not copied.
