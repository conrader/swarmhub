## Goal
Konrad (2026-10-13): model selection should "take from the Hermes model account supplier". The Overview picker offers exactly
what the bot's own Hermes profile reports (the providers and accounts the box has credentials for): grouped and labelled by
supplier, current model marked, `session_model_lock` honoured, live per profile, the same on Hermes 0.20.5 and 0.21.x. No
provider credential is sent, read, stored or shown; Torvli holds only the bot's Hermes key. This enhances P3's picker and does
not rewrite it: same Overview "Model" section, same requests, same lock call.

## Facts (recon 2026-10-13, read-only; confirm in `hermes-ref` before relying on them)
- `GET /p/<profile>/api/model/options` → `{model, provider, providers[]}`; `model`/`provider` are the profile's default. A row is
  one supplier: `slug`, `name`, `is_current` (the default supplier, never a model), `models` (id strings), `authenticated`,
  `source` (`built-in`, `hermes`, `canonical`, `user-config`, `model-config`, `configured-current`, `virtual`; 0.21.x adds
  `local-runtime`), `aliases`. Setup skeletons (`authenticated:false`, `models:[]`) pad it: 43 of 47 rows on Konrad's box.
- A row says credentials exist, not that they work. Nous adds `unavailable_models`; 0.21.x adds `limit` (`{scope:"account",
  resets_at}` or `{scope:"models",models:{id:iso}}`, Python `isoformat()` strings), `free_tier_pending` and `usage` (labels may be
  personal). On 0.20.5 a provider whose credential pool is exhausted looks unconfigured (source reading).
- Never send `include_unconfigured=false`: 0.20.5 ignores it, and 0.21.x then drops the `configured-current` row (the default
  supplier lost its login: `authenticated:false` plus the saved model), the only sign of a signed-out supplier. Never send
  `refresh=1`: it clears every provider's catalog cache for the profile.
- Konrad's box (0.20.5, multiplexing on): 16 `grok-*` profiles share one supplier, "ChatGPT or Codex Subscription"
  (`openai-codex`, default `gpt-5.6-terra`); also listed: OpenRouter (59 ids), a virtual preset (1), a keyless tier (6). The
  profile-scope Codex list is Hermes's built-in fallback (5 of its 8 ids are absent from the live catalog), a box-side gap outside
  this repo; the picker mirrors the profile's answer.
- `POST /api/sessions/{id}/model` `{model, provider}` checks routability only (409 when no route resolves, 400 `missing_model`);
  any id up to 200 characters is accepted, so the listed models are the only pre-flight check. `GET /api/sessions/{id}` returns
  `model`, not the lock's provider. There is no unlock route; a fork keeps the model string and drops the lock (source reading).

## Must do
1. **Parse by allowlist** (new `Backends/HermesModelCatalog.swift`: `HermesModelProvider` and `HermesModelOptions` move out of
   `HermesBackend+BotInfo.swift`, names and `selectable` kept). Read only the top-level `model`/`provider` and, per row, `slug`,
   `name` (trimmed, ≤80), `models` (strings or P3's `{id}`/`{name}`; de-duplicated; drop blank, over-200-character and
   control-character ids), `is_current`, `authenticated`, `source`, `aliases`, `unavailable_models`, `free_tier_pending`, `limit`.
   `key_env`, `auth_type`, `api_url`, `warning`, `usage` and every other key are never read, stored or shown; catalog types stay
   out of `Codable`; no version checks. Derive "not offered right now" states in our own words: signed out
   (`configured-current`, or `authenticated:false` with models), no models, paid plan (`unavailable_models`; "checking the plan"
   while `free_tier_pending`), rate-limited (`limit`; show a time only if it parses: drop fractional seconds, offset optional,
   naive = UTC; an unrecognised shape means no state).
2. **Group and label** in one pure type, `ModelPickerModel` (`Stores/ModelPickerModel.swift`, no SwiftUI or network), that decides
   all the view shows.
   - A group per listed supplier except setup skeletons (`authenticated:false`, no models, `source` not `configured-current`),
     which are hidden and counted. Title = the row `name`, never the slug, plus a tag from `source` in our words (`virtual`
     preset, `local-runtime` runs on the box, `user-config`/`model-config` custom endpoint, `configured-current` sign-in needed).
     The default supplier (`is_current`, or slug/alias = top-level `provider`) comes first, tagged "default"; the rest and all ids
     keep the server's order. No hardcoded provider or model names.
   - Each model row knows its supplier: menu group title, supplier in the current-model caption, accessibility label "<model>,
     <supplier>", headless line. Tag the server's default model under the default supplier.
   - Up to 16 models a `Section`, more a submenu with the same title (one constant).
   - Checkmark only under the supplier that holds the current model: the lock's provider (slug or alias), else the default
     supplier if it lists the id, else the only supplier that lists it, else none.
   - Unavailable items stay visible and disabled with the reason; a signed-out supplier shows its saved model. Server strings
     render verbatim; the box's `warning` text is never shown.
   - Under the button: "Models provided by <name> on your Hermes box" (one supplier) or "Models provided by N providers on your
     Hermes box · default <name>". Footer: profile, update time, and how many providers are not configured on the box.
3. **Current model and lock.** P3's order stays (lock confirmed for this session, the session row's model unless it is the virtual
   alias, the server default) with three changes. (a) The session row beats a local lock when it reports a different concrete
   model (changed from another client); compare ids like `HeadlessE2E.sameModel`, moved to shared code. (b) A failed session read
   keeps the last good value (P3's `try?` wrote nil), and a model read for another session id is ignored. (c) After an accepted
   lock, cache the acknowledged model at once, then read the session back; never show the pre-switch model in between. A current
   model no listed supplier offers reads "not in the box's list" where the supplier would go.
4. **Live, per profile.** Per load, P3's GETs, profile-prefixed, with the bot's own key and no query string, the same on both
   Hermes versions. An entry remembers its fetch time, `baseURL|profile` and session id. `load` re-fetches when the entry is older
   than 300 s (injectable clock), was read for another scope or session id, or failed last time; it runs when the Overview appears
   and when the bot's session id changes (the first send creates it), never by polling. The reload button forces. A reload merges
   into the current entry, so a switch in flight keeps its state.
5. **A reason for every state** (P3 dropped the picker silently), one line each in our words: loading; capabilities 404,
   `model_options` false, route 404/405 or multiplex-off profile (no menu); 401/403, 5xx, timeout or capabilities error (redacted,
   with Retry); `session_model_lock` false or no session yet (the menu opens, every row disabled, "read-only" / "Send a message
   first"); no usable supplier (keys live on the box, Torvli never holds them); default supplier signed out (orange, needs a new
   sign-in on the box). Gating is P3's and does not change.
6. **Switching.** The body stays `{"model": …, "provider": …}` (provider = the row slug), no `model_options`. `switchModel` sends
   nothing, and says the box does not offer it, when the loaded list lacks the id under that supplier, the item is disabled, or no
   list is loaded. P3's other refusals and its 409 text stay. All error text goes through `BotInfoCache.describe`, which redacts
   the bot key (P3's generic case used `localizedDescription`). The button's help says a choice pins the chat and Hermes has no
   way to unpin it.
7. **Headless proof.** Next to `overviewSummary` (format unchanged) `--render-snapshot` prints one more line per `--bot` from the
   same `ModelPickerModel`: suppliers in menu order with tag, model count and "submenu", hidden count, profile, and whether
   switching is possible (and why not), or the state's reason when there is no menu. Names and counts only. `--check-bots`
   stays as it is.
8. **Tests** (Swift Testing, URLProtocol mocks via `MockHermesProtocol`, synthetic data: shapes copied from the handlers,
   made-up names such as `lab-one`, `router`, `model-alpha`; new `ModelPickerTests.swift`). One builder emits a 0.20.5-shaped and a
   0.21.x-shaped payload, and every rule above gets a test. Also:
   - Sentinel strings in `key_env`, `auth_type`, `api_url`, `warning`, `usage` labels and `pricing` appear nowhere in
     `String(reflecting:)` of the parsed result, in any recorded request (URL, headers, body), in the encoded `Bot`/store JSON
     after a switch, in `overviewSummary` or in the headless line; catalog types are not `Encodable`; fixture names appear
     nowhere under `Sources/`.
   - A load makes exactly P3's GETs with prefix, bot key and no query string, identical on both fixtures; a switch sends one POST
     with keys == {model, provider}, then the read-back GET; refusals send no POST; a 500 echoing the key shows `[key]`.
   - Two bots on two profiles served different catalogs never mix; reloads follow item 4 with an injectable clock, including a
     reload that finishes during a switch.

## Risks
- The list is only as right as the profile's answer (the Codex fallback: 5 listed ids the live catalog lacks, 5 missing), and the
  lock validates nothing, so a listed id can still fail on the next turn (HTTP 200 reply text or an SSE error, per source). The
  fix is on the box; the menu follows on the next reload.
- Listed is not usable. The payload cannot tell a configured account from an ambient key, a keyless tier or a preset, so tags use
  `source` only and no copy says "your account".
- 0.21.x is source-read only (no live payload): `limit`, `free_tier_pending` and the cache-only first open must degrade to "no
  state", never to an error. On 0.20.5 a rate-limited provider looks unconfigured.
- Pinning is sticky (no unlock route, forks drop the lock). Custom-provider ids (bare slug or `custom:<key>`) are unverified; the
  box has none.
- Menu rendering is unseen (the snapshot draws the menu closed; OVH has no Swift). If the submenu misbehaves, set the threshold
  to `Int.max`. Konrad opening the Menu is the last hop.
