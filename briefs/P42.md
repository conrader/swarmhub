# P42 — Watch a bot work for another bot

Konrad, 2026-10-15: "If infra is doing something because other bot issued work - we need to see what its doing - also
avatar needs to animate to show that its busy". Builds on P41 (bot-msg parsed from the full command, recipient
"Working… · message from <sender>", reply on the sender's chip, persisted seen marks, arrival line). Starts after P41 merges.

## Facts
- A bot-msg run lives in the recipient's Hermes session `swarmhub-from-<sender>` (source api_server, title "From <sender>"),
  started by bot-msg's own curl (`POST /api/sessions/<id>/chat/stream`), not by SwarmHub. The session's rows (user message,
  assistant tool calls, tool results, final reply) are readable through the same session API SwarmHub uses for history
  (live case: Infra, 44 rows in 2.5 min, 2026-10-15 19:47–19:50).
- Avatars already have a working state (`BotAvatarState.working`, `AvatarMarkViews.swift` motion `.working`), used today
  only for SwarmHub's own turns.

## Build
1. **Live work card.** While a recipient works on a bot message (from the sender's running bot-msg step, or detected by
   polling: the From-<sender> thread changed and its last row is not a final assistant reply), poll that thread every 2 s
   (back off to 10 s after 1 min without change; stop at the final reply or 30 min) and show in the recipient's chat a
   "Working for <sender>" card whose steps unfold like SwarmHub's own turns (P29 Steps row: commands, files, web reads,
   skills), then the reply. Reuse the existing step/activity parsing of history rows; no new server calls beyond the
   session history read.
2. **Avatar and sidebar.** The recipient's avatar plays the working motion in the sidebar and chat header for the whole
   time, row text "Working… · for <sender>", back to idle at the end. Several bots can be working at once (P39).
3. **One conversation.** "Open conversation" shows the whole exchange: the sender's request, the recipient's steps, its
   reply — and further messages between the two in the same thread.
4. **Queued messages (`--no-wait`) and restarts:** detection by polling covers work SwarmHub didn't see start; after a
   restart a thread changed within the last 30 min that is still mid-run shows the live card again.
5. Load: at most one live poller per thread, none for bots on a disconnected connection; P39's turn limits don't apply
   (these are reads, not turns).

## Tests and done means
Fake server with a thread whose rows grow over time: card appears, steps unfold in order, reply ends it, avatar state
working → idle; back-off and 30-min stop; detection without a sender step; restart mid-run; two recipients at once; no
poller for a disconnected connection. Renders: Infra's chat with the live card mid-run; the sidebar with Infra working for
Jarvis (avatar working frame); the conversation sheet. One full `swift test` green in the run + the verify pass; files ≤ 500.
