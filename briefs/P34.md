# P34 — Bot-to-bot messages, visible and fast

Konrad, 2026-10-14: "when bots are communicating with each other I need to see a small avatar of the bot to which went
msg and ability to click to check their messages thread between them"; "receiving msgs should also be noted on the msg
feed"; "inter bot messages are one of the most common tools used so it needs to be super easy accessible"; "and fast".
**Accepted ("ok go"); defaults below.** Hermes stays vanilla.

## Facts (box, read-only, 2026-10-14; `scratchpad/peer-messaging-research.md`)
- Hermes' `message_agent` tool exists only on Bot-Mode installs (`profile.yaml ui_meta.hermes-bots`); this box has
  none. `hermes peer dm` targets registered remote peers (none). No hosted rooms.
- The one bot-to-bot message on the box: Jarvis ran `hermes -p grok-infra chat -c 'Bot Chat' --create-if-missing -Q
  --query-file -` through `terminal` (synchronous; 3.8 s CLI start before anything happens). The recipient session
  (`source=cli`, title "Bot Chat") carries no sender identity and no link back.
- A client reads a thread with the recipient's own key (`GET /api/sessions?title=…`, `/api/sessions/{id}/messages`).
  No notification route: arrivals are seen by polling session lists. The sender's chat stream shows `tool.started`
  with `tool_name` and `args`.

## Decisions
- **D1 One SwarmHub way to message a bot**: a script `bot-msg` in a new skill `swarmhub-messages` (installed into
  every Hermes bot; P31 Part A's extra-file install). `bot-msg --to <bot> [--wait <s>, default 300 | --no-wait] --
  "<text>"`. It reads the target's `API_SERVER_KEY` from the target profile's `.env` itself (never printed, never
  logged) and posts to the local gateway (`/p/<target>/api/sessions/{id}/chat`, a per-pair session titled
  `From <sender>` created on first use) — no Hermes CLI start, so it is as fast as the target's reply. `--no-wait`
  returns at once with the session id; the reply lands in the thread.
- **D2 The recipient knows who wrote**: every message starts with one line `[Message from <Sender> via SwarmHub]`;
  the skill tells the recipient to answer in that thread (its reply is what `bot-msg` returns).
- **D3 Log**: one line per message in `~/.hermes/swarmhub/bot-messages.log` (time, from, to, recipient session id,
  waited/replied, ms, ok/error) — no message text.
- **D4 Sender's chat**: a step whose command is `bot-msg --to X` shows X's small avatar + name on the step and on the
  reply ("→ Infra"); click opens the thread.
- **D5 Thread view**: a sheet with both avatars, the messages of the `From <sender>` session in the recipient (read
  with the recipient's key; falls back to the text in the sender's tool step when the recipient is not connected),
  newest at the bottom, refresh while open. Opens in under a second from what the app already has, then fills.
- **D6 Recipient's feed**: SwarmHub notices new messages in any connected bot's `From <bot>` sessions (one session-list
  request per bot on the existing refresh cadence, and immediately after a sender step finishes) and shows a line in
  that bot's chat — "<avatar> Jarvis wrote to Infra · Open thread" — plus a badge on the sidebar row.
- **D7 Easy access**: the Activity tab (P33) gets "Bot messages": every thread involving this bot, newest first, with
  avatars, last line and time; ⌘K lists threads ("Jarvis ↔ Infra"). Bots learn to prefer `bot-msg` over
  `hermes -p … chat` (skill text says it supersedes it).
