## Backend (`conrader/swarmhub-backend`, private; created 2026-10-15)
Live at `https://agenthut.net/swarmhub` (systemd `swarmhub-connections`, uvicorn 127.0.0.1:9417, state
`/var/lib/swarmhub-connections`). Branch `live` = the deployed release (20261014101517); `main` = the working source,
which also holds the agent-pairing relay (`relay.py`, `agents.py`) that is NOT deployed and is not deployed by P36.
- `POST /v1/reports` (SwarmHub sign-in bearer, as `/v1/composio/provision`): `{kind: bug|feature, title (≤140),
  body (≤8,000), source: agent|user, bot?, bot_backend?, app_version, skill_versions?, hermes_version?}` → `{id,
  status: "received"}`. Server-side redaction of key-like strings; rate limit 20/hour per account; stored in the
  service's sqlite (`reports` table; subject, fields, created_at, status received|triaged|planned|done|declined, note).
- `GET /v1/reports` (own reports, newest first, id/kind/title/status/note/created_at) and `GET /v1/reports/{id}`.
- No admin HTTP route: triage reads/updates the sqlite on the server with `scripts/reports.py` (list, show, set-status
  with a note). Built on a branch from `live`, deployed as a new release (rollback = previous symlink), then merged into
  `main`.

## App + skill (SwarmHub repo)
- Skill `swarmhub-feedback` with `scripts/swarmhub-report --kind bug|feature --title "…" -- "<body>"` (POSIX sh):
  writes a JSON report to `~/.hermes/swarmhub/reports/` (0700 dir, 0600 files), redacts key-like strings, adds bot,
  skill versions, Hermes version, time; prints a swarmhub block line `{"op":"report","id":"<local id>","kind":…,
  "title":…}` for the app. SKILL.md: when to file (a SwarmHub limitation, a failing SwarmHub skill/script, or the user
  says "tell SwarmHub…"); never include secrets; keep it factual.
- App: picks up `report` ops from replies and box reports via the manager's quiet listing turn (P35 discovery adds
  pending report files); a **Reports** inbox (sidebar item + Settings) with bot avatar, kind, title, editable body;
  **Send to SwarmHub** (requires SwarmHub sign-in; posts to `/v1/reports`; marks the box file sent) or **Dismiss**;
  sent reports show their status from `GET /v1/reports`. "Report a problem…" menu item for the user's own reports
  (app version + short diagnostics, editable before sending). Nothing leaves without Send.
- Our side: Claude reads new reports with `scripts/reports.py` and turns them into Open work rows / briefs for Konrad.

reports do not depend on it:
- `POST /v1/installs` (no auth, body `{}`; 10/hour per IP) → 201 `{"install_id":"ins_…","install_key":"<43 chars>"}`;

  Bearer (once sign-in is configured). Limits: 20/hour per install, 60/hour per IP. `GET /v1/reports` → `{"reports":[…]}`.
- Storage no longer depends on the sign-in configuration (the state dir and `reports`/`installs` always open).
