## Goal (unchanged)

shows one archive per bot, never two. Nothing that already exists on the box changes.

## Verdict: GO. Nothing stops P9. The v1 plan needed these corrections (all verified):

### Writer — use `SessionDB.import_sessions`, not create_session + append
`create_session` hard-codes `started_at=time.time()` and `end_session` hard-codes `ended_at`; there is no date parameter, so
archives would sort as "created now" (wrong `when` in `session_search`, wrong Usage windows). `SessionDB.import_sessions(list)`
(`hermes_state_portability.py:376`) is the box's own class, no raw SQL, atomic per call, **skips existing ids** (idempotent), and
preserves `started_at`, `ended_at` and **per-message timestamps**. It passed 16/16 then 38/38 on a copy. Per-call limits: 500
sessions, 10k msgs/session, 50k msgs total, 5 MiB/session JSON, 25 MiB total JSON.

### Session row shape — leave them OPEN
Write each archive session with `ended_at`/`end_reason` **NULL**, `archived=0`, `hidden=0`, `pinned=0`,
`parent_session_id`/`session_key` NULL, `source='grok-import'`. Why: both 0.20.5 and the pending 0.21.7 prune only **ended**
sessions (>90 days idle), and 0.21.7's stale-open reaper is source-scoped and does **not** list `grok-import` (rehearsed: pruned 0,
archives untouched at 200 days). So **no `config.yaml` edit is needed** — this keeps the "nothing existing changes" rule and avoids
the config-guard. `archived=1`/`hidden=1` would remove them from `GET /api/sessions`. Never enable `sessions.auto_archive` (it hides
even open sessions; search still works).

### Timestamps — float epoch seconds
Every message and session timestamp must be a float (or numeric string). An ISO-8601 string is **silently replaced by import
time** with no error. Derive the Europe/Warsaw day grouping and emit floats. Verify the box venv can load
`ZoneInfo('Europe/Warsaw')` (tzdata present) as a recon precondition; UTC gives 89 sessions vs 83 for Warsaw.

### Acceptance numbers — 6,835 importable (not 6,643/6,843)
Export has 6,843 entries: **6,835 importable** (user+assistant), 8 system notices + 11 events **skipped**, group's 28 stored twice
= **6,863 rows in 84 sessions**. Read-back must equal the **importable** count per profile (the index "messages" over-counts by the
8 notices on boppy 342→340, finance-controller 200→198, plainsay 430→429, netroas 127→126, saldora 181→180, reactor 296→295) and
must compare **every message** (role, content, float timestamp, order), not just counts. Authoritative per-profile counts come from
the export at import time.

## Part A — the importer (built + unit-tested on OVH; run on the box as `hermes`)
1. `scripts/hermes-import-grok.py` (≤500 lines; stdlib + the box's own `hermes_state` via pinned `sys.path`). Flags
   `--bundle-dir <dir> --profile <name> --db <path> --dry-run|--apply|--rollback --expect-count N`.
   - **Ids:** `grok-import-<id8>-<yyyymmdd>` (`id8` = first 8 chars of the bundle `source_id`; URL-safe; no `/`, `..`, or
     `-archived-`). Group session id `grok-import-group-<id8>-<yyyymmdd>` so a 1:1 reader can skip it.
   - **Titles:** `Grok archive · <Bot> · YYYY-MM-DD` (≤100 chars, unique per DB). A duplicate title raises `IntegrityError` and
     **rolls back the whole call**; import does not sanitize or length-check titles and an unset title hides the session from the
     slash listing — so always set it, pre-check existing titles, and wrap in try/except. Check `res['ok']`, `res['errors']` and
     `imported + skipped == len(payload)`.
   - **Roles/prefixes:** user→user, assistant→assistant. 981 inbound cross-bot messages are `role=assistant` from another author:
     keep `assistant`, prefix `[<author> → <to>] `. Group's 4 null-author user turns: prefix `[Konrad] `; other speakers
     `[DMT] `/`[Achilles] `. Skip the 8 system notices and 11 events. Insert in `seq` order (116 timestamp inversions kept as-is).
   - **Group:** stored in **both** DMT's and Achilles's DBs (same id/title is fine — unique per DB).
   - **Idempotent:** re-run skips existing ids; a changed export needs `--rollback` then re-import (only the 2026-10-13 sessions can
     still grow). `--rollback` = `delete_session` per `grok-import*` id (list with include_archived/include_hidden True).
   - **Output:** counts only; never message text, titles-with-content, tokens or secrets.
   - **Unit tests on OVH** (`scripts/test_hermes_import_grok.py`): a stub/fake `SessionDB` and a schema-only fixture; day-splitting
     in Europe/Warsaw, float timestamps, id/title generation + duplicate handling, prefixes, skip rules, idempotent re-run,
     rollback, the group-twice case. No real data in the repo; no box, no network.

2. **Execution context (any violation = hard stop).** Run as:

## Risks (accepted; write into the record)
- The list only reflects what Grok returned (713 server-side seq gaps are permanent). Recall ranking is BM25 (no recency), so old
  archive rows can out-rank recent live ones unless the bot queries `sort='newest'`; archive content is sent to the profile's model
  provider whenever recalled. A client with a profile key can PATCH/DELETE or chat into an archive id (chatting into a 1,088-message
  day would load it all into the paid model). A future updater restoring old DB snapshots, or a future SQLite ≥3.50.7 switching
  DELETE→WAL, are out-of-scope environment risks.
