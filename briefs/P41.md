## 1. Thread back button
`ChatView.swift:12`: the plain-style 22×22 chevron has no content shape, so a click outside the glyph lands on the header's
`windowDragStrip` (`WindowChrome.swift:48-62`) and starts a window drag / title-zone click. ⌘[ works (same `closeThread()`).
Fix: `.contentShape(Rectangle())` + `.accessibilityLabel("Back to chat")`; same for `HideSidebarButton` / `ShowSidebarItem`
and any other plain icon button inside a drag strip (grep them). Test: host the view in an NSWindow and hit-test the corners
and centre of the button frame — never a `WindowDragView`; a synthetic click at a corner clears `openThreadID`.

## 2. Bot-to-bot messages must be visible while they happen
Live case (box, 2026-10-15 19:47–19:50 UTC): Jarvis ran `terminal` with command
`/home/hermes/.hermes/profiles/grok-jarvis/skills/swarmhub/swarmhub-messages/scripts/bot-msg --from grok-jarvis --to grok-infra --wait 300 -- '…'`
(the full path alone is 88 chars). Infra's session `swarmhub-from-grok-jarvis` (title "From grok-jarvis", source
api_server) got the message, Infra worked 2.5 min (44 rows) and replied; Jarvis then summarised it to Konrad. SwarmHub showed
nothing: no Infra working, no arrival line, no way to read Infra's reply.
Causes found in code: (a) the step's bot-msg parse uses `event.command ?? event.preview` and the preview is cut at 80 chars
(`ToolActivity.swift:11,24,50`, `HermesBackend+TextParts.swift:39-48`), so `--to` is lost → no chip, no immediate check;
(b) seen-thread marks live only in memory (`AppStore+BotMessages.swift:13,125-130`): the first poll after launch records
existing threads as old, so a change around a restart is never shown; (c) the arrival line goes only to the recipient's main
chat, no badge while it's selected (`:139-148`). Errors are swallowed by `try?` (`:120`).
Build:
- Parse bot-msg from the full command (tool args / uncut first line), never the 80-char preview; recognise the script by
  name anywhere in the command, any path, `--to` before or after other flags.
- While a sender's bot-msg step runs: the recipient shows "Working… · message from <sender>" in the sidebar and in its chat
  header; the sender's step chip reads "Asked <recipient>…" and becomes "<recipient> replied" with the reply text
  expandable (from bot-msg's stdout in the tool result, or the recipient's thread).
- Persist seen marks with the store (per connection, per thread id), so restarts don't swallow changes; the first launch
  after this update treats threads changed in the last 24 h as new.
- The arrival line shows in the recipient's chat whatever thread is open, with "Open conversation" (the From-<sender>
  thread sheet showing both sides), and a badge unless that exact conversation is on screen.
- Poll errors: keep one quiet line in the bot's Info panel ("Couldn't check bot messages: …"), not a silent `try?`.
Tests: the live command above parses to from=grok-jarvis to=grok-infra (also `--to` first, relative path, quoted text with
`--to` inside the message); restart keeps marks; changed-in-24 h on first launch; recipient "Working…" during the step and
cleared after; arrival line while a side thread is open; reply text on the sender's chip. Renders: Jarvis's chip "Infra
replied" expanded; Infra in the sidebar "Working… · message from Jarvis"; Infra's chat with the arrival line.

Done means: one full `swift test` green in the run + the verify pass; files ≤ 500 lines; renders looked at.
