## Server (done, deployed 2026-10-15 18:16, `conrader/swarmhub-backend` branch `install-provision` b398d9c)
`POST /v1/composio/provision` now accepts the app's install key — `Authorization: Install <install_id>.<install_key>`,
the same anonymous install the P36 reports use (`SwarmHubService`, `POST /v1/installs`) — and returns
`{"project_id","api_key","user_id"}` for that install, creating its Composio project on the first call (idempotent per
install). `/health` is 200 `{"status":"ready","sign_in":false}` once the org key is configured, else 503. 429 = rate or
daily new-project cap. A signed-in Bearer token still works server-side but the app no longer uses it.

## App
1. `ComposioProvisioningClient` authenticates with the install credential from `SwarmHubService` (register one if this
   Mac has none, exactly as reports do; stored in the v2 key store, read silently). No `SwarmHubSigningIn`, no browser.
2. First **Connect** on any app: provision silently, keep the project key in the key store (the place the own-key path
   uses), then continue to that app's Composio connect link (ExternalLink; the app's own consent page — e.g. Google
   "Allow" — is the only screen). Later connections reuse the stored key; no second provision.
3. Remove every SwarmHub sign-in prompt and line from the app: Connected apps copy ("You sign in to SwarmHub in your
   browser…", "Signed in to SwarmHub…"), Settings → Account sign-in entries, and any `accessToken(forceSignIn:)` path.
   Background app actions (`BackgroundExecutionClient`) need server routes that are not deployed: show "Background app
   actions are not available yet." instead of any sign-in, no dead controls.
4. States: service ready → Connect buttons enabled with no key yet; 503 → "App connections aren't available yet."
   (no sign-in mention); 429 → "Too many new app connections right now. Try again in a while."; provisioning error →
   plain line + Retry. "Use your own Composio key" stays, collapsed under "Advanced".
5. Tests (hermetic, loopback fake server): the install header is sent and no sign-in is attempted; first Connect
   provisions once and stores the key; second Connect doesn't provision; 503/429/garbage responses; no install yet →
   one `/v1/installs` then provision; key never logged. Renders of the Connected apps pane: ready with no apps, after
   the first connection, not available (503). Files ≤ 500 lines. One full `swift test` at the end plus the verify pass.
