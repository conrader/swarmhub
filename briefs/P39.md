# P39 — Chats never block each other

Konrad, 2026-10-15: "when we are updating swarmhub instructions all msgs are blocked" … "to all bots".

## Cause (main b3a0ff6)
The store has ONE turn slot for the whole app: `isStreaming`, `streamTask`, `streamingAssistant`, `streamingBotID`,
`streamingConversation`, `activeStreamToken` (`AppStore.swift:239-250`; `isIdle` = `streamTask == nil`). `send` refuses or
steers when any turn runs (`AppStore.swift:215,224`, `AppStore+Groups.swift:104`); every composer reads the global
`isStreaming` (`ChatView.swift:83`, `ComposerView.swift:60,68`), so Send becomes Stop in every chat, and Stop there cancels
the other chat's turn. Installing SwarmHub's instructions (`AppStore+Skills.swift:82-98`) is an ordinary turn in the
manager's chat, so while the manager writes the skill files nothing else can be sent. Any long reply does the same.
Next messages wait on the global `isIdle` (`AppStore+NextMessage.swift:45`); box readings/discovery use the same gate
(`AppStore+BoxReadings.swift:88`, `AppStore+BoxDiscovery.swift:155,208`).

## Build (defaults)
1. **One turn slot per conversation.** Replace the single slot with per-conversation turn state keyed by the
   conversation's id (bot main chat, thread, group): task, assistant row, bot, token, steer state. Audit every use of the
   six properties and `isIdle`; give each the conversation-scoped meaning (`isStreaming(in:)`, `isIdle(conversation)`),
   and keep an app-wide `anyTurnRunning` only where something truly is app-wide (quit warning, sleep prevention).
2. **Sending.** A chat can start a turn whenever that chat has none running, whatever other chats do. While its own turn
   runs, the existing steer / next-message behaviour stays exactly as today (P28, P38 E queue). Groups: one group turn
   at a time per group; direct chats with the same bots stay free.
3. **Composer and Stop.** Each composer reflects only its own chat. Stop stops only that chat's turn. The sidebar shows
   which bots are working (existing per-bot indicator, now possibly several at once).
4. **Skill install / management turns** stay visible turns in the manager's chat (approvals unchanged) and no longer block
   other chats. Box readings and discovery wait only for the manager conversation they use.
5. **Everything keyed to the old slot keeps working per turn:** P16 reconcile/Retry and "Stopped locally", the P38 D run
   ledger and P38 E queue recovery (several turns in flight across a restart), workflows (one task turn at a time per
   workflow, as now), reviews (P37), notifications, steer hint, token usage, approvals cards landing in the right chat.
6. **Limit:** at most 6 turns at once app-wide (default); a 7th send waits as that chat's next message with the line
   "Waiting: 6 replies are already running." Plus a per-connection cap of 4 so one box isn't flooded.
