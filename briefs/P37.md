# P37 — Reviewer bots for specific things, or for all bots

Konrad, 2026-10-15: "make sure also that we can ask one agent to do review and approvals for specific things from
other agent"; "or all agents". **Accepted by those messages; defaults below.**

## What exists (main, 2026-10-15)
Per bot, `approvalMode` = Ask me | Auto-approve by rules | Reviewer bot (`reviewerBotID`); `AppStore+Approvals.swift`
asks the reviewer bot for approve/deny, with rails that always go to the user (`commandRequiresUserReview`,
`reviewerMustEscalate`, reviewer = self or missing, unknown/display-only command, reviewer timeout) and an audit
(`decidedBy reviewer:<id>`). Missing: routing by WHAT is asked, one setting for ALL bots, and reviews of finished work.

## Decisions
- **D1 Routing rules.** Per bot, an ordered list `when <match> → <Ask me | Approve | Reviewer: <bot> | Deny>`; first
  match wins; the last line is always "anything else → Ask me" (editable target). Match on: the action kind the
  approval carries (terminal command, file write/edit, network, delegate, bot message to <bot>, coding job, skill
  install, other), a command pattern (simple wildcards: `git push*`, `*deploy*`, `rm -rf*`), and optionally the
  target bot (for bot messages). The three existing modes migrate losslessly: Ask me = only the last line; Auto-approve
  by rules = today's `approvalRules` as Approve lines; Reviewer bot = "anything → Reviewer: X".
- **D2 Rules for all bots.** Settings → Approvals: a SwarmHub-wide list with the same shape, checked AFTER a bot's own
  lines (a bot's lines win). "One agent reviews everyone" = one global line "anything → Reviewer: Jarvis". A reviewer
  never reviews its own requests (those fall through to the next line / Ask me).
- **D3 Rails unchanged.** Everything that goes to the user today still does, whatever the rules say; a reviewer that
  doesn't answer in time → Ask me; every decision is audited with who decided and which rule matched.
- **D4 Reviews of finished work.** A second rule list, "Review after": `when <bot> finished <a coding job | changed
  files | sent a bot message to X | any turn with steps> → Reviewer: <bot>`. SwarmHub sends the reviewer the summary
  (the reply, the steps list, the code-job line, and the diff stat when the job reports one) through the P34
  `bot-msg` path in a thread "Review: <bot>"; the verdict comes back as a card under the original reply ("Looks good"
  / "Changes requested" + notes). "Send notes to <bot>" forwards the notes as the next message (one click; optional
  automatic per rule). Reviews never block the original reply.
- **D5 Where you see it.** Approval cards show the deciding rule and reviewer avatar; the Activity tab lists
  approvals and reviews per bot; the Model/approvals area of the bot's settings holds its lines; Settings → Approvals
  holds the global lines. OpenClaw approvals (P12) follow the same rules.

## Done means
Migration tests for the three old modes; rule matching tests (order, wildcards, kinds, target bot, self-review
fall-through, global after bot); rails still win; review-after flow with a mock reviewer (card, notes forward);
renders of the bot's rule editor, Settings → Approvals, an approval card decided by a reviewer, a review card.
