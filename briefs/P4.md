## Must do
1. **Steer.** While a turn is streaming and the server has `run_steer`, sending a message posts it
   to `/v1/runs/{run_id}/steer` (read handler for body) and shows it in the transcript as a steer
   bubble; without the capability, keep today's behaviour (queue or disable send — match current code).
2. **Fork / threaded reply.** "Reply in thread" on any assistant message forks the session at that
   point (`/api/sessions/{id}/fork`, read the handler for parameters) and opens the thread as a
   sub-conversation of the same bot, shown nested under the source message with a reply count.
   Without `session_fork`, hide the action.
3. **Attachments.** Composer paperclip + drag-and-drop + paste for images (png/jpeg/gif/webp,
   downscale to ≤2048px long edge, ≤5 MB after encoding) sent as `data:image/...` parts on whichever
   endpoint the bot uses (session stream if it accepts parts; otherwise chat completions content parts —
   verify from the handler). Non-image files: send text files (≤200 KB) inline as a fenced block with the
   file name; refuse others with a clear message. Thumbnails in the bubble; click to preview.
4. **Inline cards** parsed from assistant markdown, implemented with our own UI:
   question-with-options (a fenced ```choices block or a trailing numbered option list the model marks;
   pick one sends it as the user's reply), draft card (```draft fenced block with optional `to:`/`subject:`
   headers; "Send" posts "Send it" to the bot, "Copy" copies), link pills for bare URLs, inline images
   for markdown images. Document the card syntax in README so SOUL prompts can use it.
5. **Tapbacks** persisted per message in store.json (local only); **Mark as unread** in the sidebar
   context menu (manual unread flag survives restarts and clears on open).
6. **Media tab** lists every image/attachment and link in the bot's transcripts, newest first,
   click to jump to the message.
7. Tests: steer request shape + capability gating, fork request + thread model, data-URL encoding and size
   limits, card parsing (positive and negative cases), tapback/unread persistence, media extraction.
