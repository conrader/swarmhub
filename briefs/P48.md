# P48 — Connected accounts: the 400, several accounts per bot, real names

Konrad, 2026-10-16 (live on 0.5.5): "Composio request failed (HTTP 400)" when Jarvis ran a GitHub tool; "agent access
only allows me to connect one gmail - other gmails are turned off"; "i see some random name - i dont know which account
is witch"; then "build those three together". Evidence and Composio v3.1 references are in PLAN.md (rows dated
2026-10-16). Not released until Konrad names a release.

Composio facts (from docs.composio.dev, v3.1 reference, checked 2026-10-16):
- `POST tool_router/session`: `connected_accounts` is toolkit → **array** of account ids; "non-multi-account sessions
  are capped at length 1"; `multi_account` = `{enable, max_accounts_per_toolkit (2–10), require_explicit_selection}`;
  `enable:false` combined with `max_accounts_per_toolkit` or `require_explicit_selection:true` → 400.
- `POST tool_router/session/{id}/execute`: `tool_slug` (required), `arguments`, `account` (account id or alias) — the
  docs describe `account` for multi-account sessions (`require_explicit_selection`).
- 400 body: `message`, `code`, `slug`, `status`, optional `request_id`, `suggested_fix`, `errors`.
- `PATCH connected_accounts/{id}` takes `alias` ("A human-readable alias…", unique per entity and toolkit in the
  project, duplicate → 409; empty string clears it). List items carry `alias` and `word_id` (random, e.g.
  "gmail_red-castle"); there is no email/username field.

## 1. The 400 on execute
- `ComposioClient.request` keeps Composio's error body on a non-2xx: `message`, `slug`, `suggested_fix`, `request_id`
  (each capped at 300 chars, never any header, key or credential, never the request body). The error text becomes
  "Composio: <message> (<slug>)" plus the suggested fix when present. It shows in the chat, and the developer log gets
  the same line without secrets.
- Every failed app request the bot made gets a "SwarmHub app result" back to the bot with the error. Today Jarvis got
  nothing after `execute` at 04:45:46 and stopped. The bot must always get a result row, success or failure.
- Match the docs: a single-account session pins one account and execute sends **no** `account` field. A multi-account
  session (item 2) sends `account`. Never send `multi_account.enable:false` together with the other multi-account keys.
- Tests: fake Composio returns a 400 with a body → the chat shows the message and slug, the bot gets an error app
  result, and no secret appears in either. Single-account execute has no `account` key; multi-account execute has it.

## 2. Several accounts of one app per bot
Konrad: "we should allow multiple accounts of each app". This applies to every app, not just Gmail and GitHub: nothing in this item
is app-specific.
- Remove the one-account-per-app rule in `ConnectedAppsStore.setAllowed`, the pane caption and the P47 grant (P47's
  "skip a bot that already has another account of that app" becomes "add it", so a new account is on for every bot).
  Agent access lets several Gmail accounts be on for one bot, at most 10 per app.
- Run scope: an app with one granted account → single-account session (pin 1, no `account`). An app with 2–10 →
  `multi_account {enable:true, max_accounts_per_toolkit:<n, min 2>, require_explicit_selection:true}` with all of them
  pinned.
- The bot sees its accounts. The connected-apps chat context and the app search result list each app's accounts by
  name (item 3). The bot's `execute` request may carry `"account":"<name>"`, which the app maps to the id; only names
  this bot is granted are accepted. With several accounts and no name, the app returns an error result listing the
  names, with no guess. The approval card shows "Gmail · <name>". The bot prompt text is updated to say this.
- A connect for an app that already has an account opens its link session with `multi_account.enable:true`, so
  Composio adds the account instead of refusing or replacing it.
- Tests: two Gmail accounts on one bot → multi-account session body with both pins; execute with a name maps to the
  right id; an ungranted or unknown name is refused; no name with two accounts → error listing names; one account →
  single-account body; a P47 grant now adds a second account of the same app.

## 3. Account names: who it is, not word_id
- `ComposioAccount.label` never shows `word_id`. The order is alias, then "<App> account <n>" (n by connect order)
  with the connect date.
- After a new account appears (from Settings or a chat card), the app runs that app's read-only profile call once in
  a single-account session pinned to it. This is SwarmHub's own call, not a bot action, so it needs no approval; the
  pane says "Getting the account name…". Gmail: `GMAIL_GET_PROFILE` → `emailAddress`. GitHub:
  `GITHUB_GET_THE_AUTHENTICATED_USER` → `login`. Keep the table in one small file so more apps are one line each; an
  app not in the table keeps the fallback name. Then `PATCH connected_accounts/{id}` sets that as the `alias`, so it
  survives reinstalls; on 409 append " (2)", " (3)". Only the name field is read from the result, never tokens.
- Accounts that already exist with no alias (Konrad's) get the same naming once, on the next refresh of the pane.
- Rename: each account in Connected accounts has Rename… (sheet with a text field). It saves the alias the same way,
  and an empty name puts back the automatic one.
- Names show everywhere: Connected accounts, Agent access toggles ("Gmail · konrad@…"), approval cards, the chat
  context and search results the bot sees, the P47 "on for all your bots" line.
- Tests: profile result → alias PATCH with the email/login; 409 → " (2)"; existing alias-less accounts named once on
  refresh; rename saves, empty restores; no label ever equals a word_id.

## 4. A Connect apps modal with logos and what Composio is
Konrad: "Overall we should have a modal for connecting apps with app logos and explanation what is composio".
- The bottom-left **Connect apps** button (P47) opens a modal sheet instead of Settings. Chat connect cards keep their own
  sheet but use the same app tile and logo.
- **Top:** a short plain explanation, roughly: "SwarmHub connects your apps through Composio. Composio is a service that
  keeps your app sign-ins (you approve each app on its own page; SwarmHub never sees your password) and runs app actions
  when your bots ask. Each action a bot takes appears for your approval in its chat. You can disconnect any account at
  any time." Only say what the code really does; check approvals and token handling before wording it. Add a
  "Learn more" link to composio.dev through ExternalLink.
- **Grid** of app tiles, each with logo, name and short detail: the popular apps first, then search over the full
  catalog. Logo is the toolkit's `meta.logo` from Composio's toolkits API. Before a key exists, check whether that URL
  form needs no key (e.g. a public logos host) and use it for the popular apps; otherwise show a letter tile until the
  catalog loads. Load https only, from the host(s) `meta.logo` uses (allowlist), with an in-memory cache and a
  letter-tile fallback on any failure.
- **Each tile** shows its connected accounts by name (item 3) with **Add another account**, or **Connect** when it has
  none. A connect from here follows P47 (on for every bot) and item 3 (named after who it is).
- **Footer:** "Manage which bot uses which account in Settings → Connected apps" with a button there.
- Tests and renders never load a real logo: inject a fake image loader. Renders: the modal before any connection,
  after two Gmails + GitHub (names, Add another account), and the search results.
