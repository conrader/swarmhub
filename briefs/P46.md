## Facts (Hermes 0.22 source + live test on Jarvis, 2026-10-15 21:42–21:46 UTC)
- Native `/heartbeat` (`hermes_cli/heartbeat.py`, `gateway/run_goals.py`) only wakes sessions that came in through a
  messaging channel; api_server sessions are never registered, and there is no CLI/API to register one. Not usable.
- Cron runs always in a fresh `cron_<job>_<ts>` session, but `deliver: "bot-chat:<profile>"` (core,
  `cron/scheduler_delivery.py:773-940`) runs a full agent turn in that profile's session titled exactly "Bot Chat"
  (`hermes chat -c "Bot Chat"`), with the cron output as a user row "[Cronjob "<name>" output — scheduled job, not the
  user. …]". A cron reply of exactly `[SILENT]` suppresses delivery (`cron/scheduler.py:526`).
- Live test: Jarvis's SwarmHub session `agentapp_996cac31…` retitled "Bot Chat" (`PATCH /api/sessions/{id}`
  `{"title":"Bot Chat"}`, 200). A test job with `deliver: bot-chat:grok-jarvis` → its output arrived in that SwarmHub
  session at 21:43:23 and Jarvis replied in context at 21:43:34. Collision test: a 40 s turn in the same session
  21:44:16–21:45:06 and the job run at 21:44:23 → delivery landed 21:45:17, after the turn, no interleaving (the cron
  pre-turn took ~50 s; idle-waiting is not proven). Cost: two agent turns per non-silent wake (cron + chat).
- SwarmHub did NOT show the delivered rows: the app does not pull rows the box appends to a bot's main session.
- Jarvis already has `jarvis-hourly-heartbeat-cet` (`0 7-22 * * *` UTC = 08–23 CET, deliver `bot-chat:grok-jarvis`).
  Its session is now titled "Bot Chat" (keep).

## Build
1. **Main chat = "Bot Chat".** For every Hermes bot, title its SwarmHub main session "Bot Chat" (on connect and on first
   heartbeat setup; only if no other session of that profile already has that title — then ask). Threads keep their
   titles. SwarmHub shows its own bot name as before.
2. **Live rows from the box.** Poll each bot's main session (message_count / last_active from the session list SwarmHub
   already reads; 15 s, 5 s while a heartbeat or routine for that bot is running) and append rows the app didn't write:
   a cron delivery shows as "Woken by: heartbeat" (or "routine <name>") with the reply; never duplicate rows SwarmHub
   wrote itself; keep order (P43 segments). Exactly-`[SILENT]` replies hidden (P44).
3. **Heartbeat = one Hermes routine per bot** that SwarmHub creates/edits through the manager or `api/jobs`:
   name `swarmhub-heartbeat`, schedule from the user's interval + active hours (converted to the box's cron timezone),
   `deliver: bot-chat:<profile>`, prompt (editable): "Heartbeat: check what's open for Konrad (messages, routines,
   goals, files you're watching). If something needs him, say it briefly; otherwise reply exactly [SILENT]." Staggered
   minute per bot (spread across the hour by profile name hash). `/heartbeat every 1h 08:00-23:00 [prompt]`,
   `/heartbeat status|pause|resume|stop` and Settings drive this routine (P45's command/UI; remove its app-run timer).
   Adopt an existing bot-chat routine whose name contains "heartbeat" (Jarvis's) instead of creating a second one.
4. **All bots.** Settings → Heartbeat: a template (interval, hours, prompt) → "Apply to…" all / chosen bots, per-bot
   override, off by default; shows the next run and last result per bot; warns with the turn count per day (2 turns per
   non-silent wake) and caps concurrent heartbeats by the box capacity (P31 E advised slots).
5. Routine results that are heartbeats show only via item 2 (no separate routine card), silent ones only in the
   Routines tab as "ok · silent".
Tests: title set once, conflict asks; external rows appended once, in order, labelled; silent hidden; heartbeat routine
create/edit/pause/stop via the command and Settings; adopt existing; stagger; apply-to-all sends one batch; capacity cap.
Renders: Settings → Heartbeat with three bots; a chat with a "Woken by: heartbeat" row. One full `swift test` green in the
run + the verify pass; files ≤ 500 lines. After merge (not in the run): live check on Jarvis — next non-silent run shows in
the app.
