## Facts

- Over SwarmHub's API path the text goes straight to the agent: on 2026-10-15 20:02 the Swarmhub bot received

## Build
1. **Composer menu.** Typing `/` at the start opens a command list (filter as you type, ↑↓ Enter, Esc closes); unknown
   `/x` is sent as text after a one-line warning "Not a command — sent as a message". Commands (default set):
   `/help` (the list), `/new` (new thread), `/model <name>` (the existing model switch), `/stop`, `/retry` (P16 Retry of the
   last reply), `/status` (model, tokens, context, running goal/loop — from data the app has), `/goal`, `/subgoal`, `/loop`.
2. **`/goal <text>`** — a standing goal on that chat: a goal chip in the chat header ("Goal: … · round 3/20 · Pause · Clear").
   SwarmHub sends the goal as the first turn with a short protocol (work toward it; when it is fully achieved, end the reply
   with a `swarmhub` block `{"op":"goal","status":"done","summary":"…"}`; if blocked, `"status":"blocked","need":"…"`).
   After each finished turn without done/blocked, SwarmHub sends "Continue toward the goal: <text>" (+ subgoals) as the
   next turn — visible as "Woken by: goal" (P42 rule). Ends on done (card "Goal reached" + summary), blocked (card with
   what is needed, Resume), Stop, `/goal pause|clear`, a failed turn, or the budget: 20 rounds or 2 h by default
   (Settings → Chats). `/goal status` shows round, time, last summary; `/subgoal <text>|remove N|clear` adds criteria.
   Goals survive a restart (run ledger) and pause when the connection is offline. One goal per chat; P39 limits apply.
3. **`/loop [every] <prompt> [--times N] [--until <condition>]`** — re-sends the prompt on that interval while the app runs
   (min 1 min), shown as "Woken by: loop"; `/loop status|pause|resume|stop`. For box-side schedules point to Routines.
5. **`/heartbeat every <interval> [HH:MM–HH:MM] [<prompt>]`** (Konrad, 2026-10-15: "check jarvis routine - routine is not
   heartbest"; Jarvis had made a cron routine `jarvis-hourly-heartbeat-cet`, `0 7-22 * * *`, which runs in its own cron
   session without the chat's context and answers `[SILENT]`). A heartbeat re-enters THAT chat's own conversation (same
   Hermes session) on the schedule, only when the chat is idle, with a default prompt ("Heartbeat: check in on what's
   open and report only if something needs Konrad; otherwise reply [SILENT]"). Shown as "Woken by: heartbeat"; a reply
   that is exactly `[SILENT]` is hidden (no unread, no preview). Runs while SwarmHub is open; the header shows "Heartbeat ·
   hourly 08–23" with Pause/Stop; `/heartbeat status|pause|resume|stop`. Survives restart.
6. **`@` mentions in every chat** (Konrad: "do we have mentions with @"; today only group chats). Typing `@` opens the bot
   picker (same as groups); in a 1:1 chat, "@Infra <text>" sends the message to the open bot with an instruction to hand it
   to Infra through SwarmHub's bot-msg (swarmhub-messages) and report back — so the exchange is visible (P41/P42). If the
   open bot lacks the messaging skill, offer "Install SwarmHub skills on all bots" (P42) first. Groups unchanged.
4. Approvals, steer and the next-message queue behave as for typed messages; a user message during a goal round steers it.
