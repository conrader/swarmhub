## Facts (Hermes 0.22.0 source and Konrad's box, read-only, 2026-10-14; `scratchpad/codex-accounts-research.md`)
- Accounts: `hermes auth add openai-codex` (device code by default). HTTP login routes exist only on the Hermes
  dashboard (`POST /api/providers/oauth/openai-codex/start`, `GET …/poll/{id}`); the dashboard does not run on the box
  and nginx does not expose it. The gateway API has no login route.
- Pool: `$HERMES_HOME/auth.json` → `credential_pool.<provider>`; profiles without their own file read the global one.
  The box has **2 openai-codex entries** shared by all profiles (grok-jarvis has its own file without codex entries;
  lowcost is a symlink). Strategy unset → `fill_first`. A `usage_limit_reached` 429 benches that entry until OpenAI's
  reset time (else 1 h) and rotates to the next entry **in the same turn**. So conversation already falls back between
  ChatGPT accounts automatically.
- One account per role inside one profile is not possible (delegation leases from the parent's pool; static
  `delegation.api_key` has no refresh). The working boundary for "a separate account for coding" is a separate tool:
  stock Hermes skills `claude-code`, `codex`, `opencode` delegate coding to those CLIs, each with its own login.
- No per-credential usage route; `hermes usage --json` reads only the selected credential.
- Box: 2 CPUs, 3.8 GB RAM (1.35 GB available), 17 GB disk free; Node 22 in `~hermes/.local/bin`; `claude` and `codex`
  not installed. One Hermes CLI start = 3.8 s.

## Decisions (recommended defaults)
- **D1 Coding order per bot**: Claude Code (`claude -p`, Konrad's Claude subscription) → Codex CLI (a ChatGPT account
  of its own) → Hermes's own sub-agent (`delegation.*`). Settings → Models → "Coding agent" per bot and a SwarmHub-wide
  default; the next one is used only when the previous is not installed/logged in or returns a usage-limit error.
- **D2 Logins through SwarmHub**, all run on the box by the manager bot, never by SSH from the Mac:
  - Codex CLI: `codex login --device-auth` (flag to confirm against the installed version) → SwarmHub shows the link + code; nothing is pasted back.
  - Claude Code: a SwarmHub helper runs `claude setup-token` in a pseudo-terminal, shows the link, takes the one-time
    code Konrad pastes **into a SwarmHub sheet (not the chat)**, and stores the resulting token in a 0600 file the
    helper's jobs read. The token never reaches a chat, a log or the app. The one-time code passes through the
    manager once (single use, minutes). `ANTHROPIC_API_KEY` is never set.
  - ChatGPT accounts for conversation (the Hermes pool): `hermes auth add openai-codex` the same way; SwarmHub lists
    the pool (count, which is in use, benched until when) from the manager's report.
- **D3 Fallback, not load-spreading.** Keep `fill_first`: the second ChatGPT account is used only after a real limit
  error. No round-robin to stay under limits (OpenAI's terms forbid circumventing usage limits).
- **D4 Box capacity** (per box, so per customer): SwarmHub asks the manager for a read-only probe (CPUs, RAM total and
  available, disk free, load, and the coding-job log below) and computes "parallel coding jobs":
  `max(1, min(CPUs, floor((available RAM − 512 MB reserve) / job RAM)))`, job RAM = measured peak of past jobs on that
  box (default 600 MB until measured). Shows "This box: 2 CPUs, 3.8 GB — 1 coding job at a time" with advice when it
  queues often ("Jobs waited 14 min on average this week; a 4-CPU/8 GB box would run 3"). The limit is applied on the
  box; Konrad can override it.
- **D5 Queue on the box.** A SwarmHub script `~/.hermes/swarmhub/bin/code-job` (installed with the skill) takes one of N
  slots (`flock` on slot files), runs the chosen CLI with a timeout, applies D1's fallback on limit errors, and appends
  one line per job to `~/.hermes/swarmhub/coding-jobs.log` (bot, agent, start, wait, duration, peak RSS, exit). Bots
  learn to use it from a new SwarmHub skill `swarmhub-coding`, which says it supersedes the stock claude-code/codex
  skills.
- **D6 Scope.** Your box first (it is the only one with your Claude subscription). Claude Code on a customer box needs
  that customer's own Claude subscription; Codex CLI their own ChatGPT account. OpenClaw: later.

## Parts
- **A. Skill files beyond SKILL.md.** `SkillLibrary` installs a skill's extra files (`scripts/…`, mode 0755) with the
  same heredoc path; version/outdated logic unchanged. Tests.
- **B. `swarmhub-coding` skill + `code-job`.** The script (POSIX sh, tested in a temp HOME with stub CLIs: slots,
  queueing, fallback on a fake limit error, log line), the SKILL.md (when to use it, how to call it, how to report).
  Rendered per bot with its coding order.
- **C. Tool install + logins.** Manager-text recipes: install `@anthropic-ai/claude-code` and `@openai/codex` with
  the user's npm into `~/.local` (no root); `codex login --device-auth`; the Claude helper (`swarmhub-claude-login`,
  part of the skill's scripts) with the code passed via a 0600 fifo/file, token stored 0600; `hermes auth add
  openai-codex`. A new app sheet "Accounts" (per connection): Claude Code, Codex CLI, ChatGPT pool — status, Log in,
  Log out — driving those recipes through the manager and parsing their `swarmhub` blocks (new ops: `accounts`,
  `login_link`, `login_done`).
- **D. Sub-agent model.** "Change coding model…" in Manage bots and a Change… button on the Sub-agents line (the P30
  recipe with `KM=delegation.model KP=delegation.provider`); the manager reports each bot's `model.*`/`delegation.*`
  read from config.yaml in an op `models`, shown as "Sub-agents: gpt-6.1-sol (reported 14 Oct)".
- **E. Box capacity.** Op `box_capacity` from the read-only probe; the computation, the Settings line and advice; the
  limit written into the skill's config file on the box via the manager.
- **F. Live check on Konrad's box** (after his go on D2's logins): install both CLIs, log in, one tiny coding job each
  through `code-job`, the fallback on a forced limit, the capacity readout. Report what ran.
