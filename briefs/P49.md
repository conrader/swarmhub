## When
- Only for a bot that was **really created**: the manager's `createBot` (`AppStore+BotManager.swift`) and a Grok
  import that creates a new profile (`AppStore+GrokBinding.swift`, `kind == .new`). Never for bots that already exist
  and are only connected (setup scan, `addBotsFromBox`, box discovery, OpenClaw gateways, store restore, reinstall,
  reconnect, key change).
- Once per bot, ever: a persisted `orientedAt` on the bot (old store.json entries without it count as oriented, so
  nothing fires for existing bots after the update).
- It starts when the bot is ready (connected, key present, its Bot Chat titled per P46). It uses the normal turn path
  (P39 limits: it waits like any message). If the bot is not reachable, it waits and retries on the next connect, and
  is given up after 24 h with one quiet line.
- Settings → Advanced: "Orientation for new bots" on by default, plus the coordinator choice below.

## The orientation turn
SwarmHub sends one first message into the new bot's Bot Chat, shown collapsed as "Orientation" (like the P45 goal
first turn, `ChatAutomation.swift`). Its text is built SwarmHub-side from what the app already knows, with no Hermes
changes: the bot's name and description, its instructions (title only plus the first lines, not the whole SOUL), its
installed SwarmHub skills, its connected apps (P48 names), its teammates (the other bots, with descriptions), the
coordinator, Konrad's time zone, and the quiet hours. It asks the bot to:
1. greet Konrad in one line ("Hi Konrad, <name> here") and say in two or three lines what it will do here;
2. pick one concrete, **read-only** first job in its own area (survey what exists, what is built and what is missing)
   and start it now with its normal tools, or with a coding job if that fits (`swarmhub-coding`);
3. tell its coordinator about the job through SwarmHub messaging (P42 `swarmhub-messages`, or a team request if the
   coordinator is in a team, per team coordination) and ask for confirmation;
4. say when it will report: to the coordinator when the job is done, and to Konrad outside quiet hours (say the time,
   e.g. "after 08:00 Warsaw"); then deliver a short plan with the next queued tasks;
5. handle trouble itself: restart a job that died once, and flag what it cannot reach (a private repo, a missing key
   or connection), naming what Konrad has to do;
6. make no changes outside read-only work until Konrad or the coordinator says so.
The bot's reply shows normally, not collapsed. The coordinator's confirmation and later reports arrive as P42 bot
messages.

## Coordinator and quiet hours
- Coordinator: Settings → Advanced → Orientation → "Coordinator" picker over the Hermes bots. The default is the bot
  named Jarvis if there is exactly one, else the manager bot, else none (then reports go to Konrad only). A new bot is
  never its own coordinator.
- Quiet hours: reuse an existing setting if one exists (grep team-coordination notification preferences and the P46
  heartbeat active hours). Otherwise add "Quiet hours" (default 22:00–08:00, Mac time zone) next to it. The prompt
  states them; SwarmHub does not hold messages back itself.

## Tests and renders
- Tests: orientation fires for manager create and Grok `.new` import only; never for setup, add-from-box, OpenClaw,
  restore or reconnect; once per bot; old bots without `orientedAt` don't fire; waits when unreachable and fires on the
  next connect; off in Settings → nothing; the prompt contains greeting, read-only first job, coordinator name, report
  timing with quiet hours, and self-recovery, and never the full SOUL or any key; the coordinator default rules. Fakes
  only: no network, Keychain, browser or microphone.
- Renders (`--render-setup --only p49`): a new bot's chat with the collapsed Orientation row and a reply like the
  SwarmHub example; Settings → Orientation with the coordinator picker and quiet hours.
