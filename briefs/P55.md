# P55 — Live voice says why it failed

Konrad, 2026-10-16 ~21:30 CEST on 0.5.8: "I connected chatgpt but cant turn on voice mode - unfortunatelly its not even
giving me any error - something blinks but too fast to read" … "yes" (build). Not released until Konrad names a release.

## Evidence
ChatGPT is connected: SwarmHub's private Codex app-server runs (ChatGPT 26.1007.30912 with codex-cli 0.162.0-alpha.17.2).
The Mac's unified log has no AgentApp line about voice and no tccd line about the app. `CodexVoiceSession.fail`
(`Voice/CodexVoiceSession.swift`) maps every error except `LiveVoiceError`/`VoiceDictationError` to the fixed
"Codex could not open live voice for this account…" and drops the cause; `thread/realtime/error` and an early
`thread/realtime/closed` become the same text. Steps: `account.canUseVoice` → microphone permission → `thread/start` →
`thread/realtime/start` (version "v3", websocket) → `device.start()` → `appendAudio`.

## Fix
1. **Which step failed, in words.** Each step reports its own failure: "Microphone access is off for SwarmHub — turn it on
   in System Settings → Privacy & Security → Microphone" (with a button that opens that pane via ExternalLink's settings
   URL); "Your ChatGPT account can't use live voice here: <reason>"; "ChatGPT refused live voice: <code> <message>"
   (JSON-RPC error code and message, redacted: no headers, tokens, URLs with query strings, ≤ 300 chars); "Codex did not
   answer within 30 s"; "The audio device could not start: <reason>". `thread/realtime/error` carries its own
   message/code through the same redaction.
2. **It stays.** The error stays visible in the voice window until the user dismisses it or starts again; if the voice
   window or popover closes when the session stops, keep it open while an error is shown. A "Copy details" button copies
   step + code + redacted message.
3. **It is logged.** Every failure: one line under `com.konrad.agentapp:voice` with step, error type, code, redacted
   message. Also log each step's start at debug level.
4. **The protocol matches codex-cli 0.162.** Read the app-server protocol of the bundled codex (its `--help`, the
   app-server's schema output if it has one, e.g. `codex app-server generate-json-schema` or similar, without starting a
   voice session or using the microphone) and compare the method names and parameters SwarmHub sends (`thread/start`,
   `thread/realtime/start`, `appendAudio`, `stop`, notifications). Fix any mismatch; record what you compared.
5. Tests with a fake RPC: each step's failure shows its own text and is logged; redaction strips tokens/headers; the error
   stays after stop; Copy details. Never open the microphone or a real app-server in tests. Render (`--only p55`): the
   voice window with a microphone error and with a ChatGPT refusal.
