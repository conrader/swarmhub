## Goal
One in-app flow instead of `export-grokbot.py --fetch-server-history` plus `AgentApp --import-grok`: find Grok Bot on the Mac, list its
bots from its cache, fetch the complete history from Grok's servers with the user's own sign-in, import it through the existing importer,
and leave every bot either chatting through its Hermes profile or plainly marked history-only. No `python3` at runtime, no helper binary,
no SwiftPM dependency, one macOS Keychain prompt, read-only against Grok. By script it worked on 2026-10-13 (16 bots + 1 group, 6,843
messages, 23 list requests, about 22 s); P10 reproduces it natively and fixes what the script got wrong.

## Approach (decided)
A **native Swift port, in process** (Foundation, Security, CommonCrypto, URLSession) in `Sources/AgentApp/GrokExport/` (subfolders `Local`,
`Crypto`, `Server`, `Mapping`, `Flow`); the two Python modules are the spec and the test oracle, not a dependency. Rejected: running the
bundled scripts through `Process` (macOS does not reliably ship python3; the dialog would name `/usr/bin/security`, so an Always Allow
would trust a generic tool; throwaway code) and a frozen-Python helper (moves the work, unproven signing, two languages across the trust
boundary). Native fits: the one dialog is raised by Torvli itself on the user's click, secrets never leave process memory, no plaintext
history folder appears in `~/Documents`, and `importGrokBundles([GrokBotBundle])` already takes in-memory bundles. The order follows risk:
the macOS unknowns first (P10.0), the live path as a command before any UI (P10c), the sheet last (P10d). Cache-only import needs no
secrets and no network, so the private-API half can be switched off without losing the rest. Budget: about 3.1k production lines in about
27 files (40–250 lines each), 1.9k test lines.

migrated 2026-10-08). `~/Library/Application Support/Grok Bot/` holds `sand-client-persistence/*.blob` (32 files: the roster, 17

percent-encoded blob `sand.client.slice.client-meta.account-slot`, and `cursor-accounts.active` is the lowercase hex SHA-256 of that

Torvli is unsandboxed and stably signed (Apple Development, no hardened runtime) and must stay so; its `CFBundleExecutable` is `AgentApp`,
so the dialog may say "AgentApp". CryptoKit has neither PBKDF2 nor AES-CBC; `import CommonCrypto` has both.

**Protocol.** `docs/P8a-findings.md` has endpoint and fields; the Python is the spec (from `grokbot_server.py` the codec, `fetch_older`,
`resolve_rows`, `merge_entries`, `coverage`, `read_credentials`, `cursor_checksum`, `request_headers`; from `export-grokbot.py`
`load_cache`, `map_entries`, `card_text`, `attachment_ref`, `build_bundle`, `slugify`/`profile_slug`, `iso`, `Redactor`). The traps:
- Connect unary, binary protobuf, `content-type: application/proto`, a new `x-request-id` each time, 30 s timeout. Blob GETs carry no
  custom and no auth headers. Never set `Accept-Encoding` by hand. The client version is read live from the installed app's Info.plist
  (three numeric groups, else 0.70.2).
- `cursor-accounts` is a JSON **string** inside `sand-secrets.json`. Values are `base64("v10" + AES-128-CBC/PKCS7)`, optionally wrapped
  `scoped:v1:<x>:<base64>` (four parts). Key = PBKDF2-HMAC-SHA1(**the Keychain bytes verbatim**, "saltysalt", 1003, 16), IV = 16 × 0x20.
  Decrypt exactly three values (access token, machine id, team id), never the refresh token, `local-exec-file-key` or the profile. A
  wrong key still passes the padding check 0.4 % of the time, so also require UTF-8 and a three-segment token.
- `x-cursor-checksum` uses JavaScript int32 shifts: `t = floor(nowMs / 1e6)` as Int32, bytes `[t>>8, t, t>>24, t>>16, t>>8, t]` each
  `& 255`, `prev = 165`, `b[i] = ((b[i] ^ prev) + i) & 255; prev = b[i]`, header = base64url without padding + machine id (kept only if
  1…127 chars). A plain 64-bit port is wrong.
- Paging stops on an empty page or when the oldest seq ≤ 1, never on a short page (the script stops on any short page and would truncate
  silently if the server capped pages below 500; expect one extra, empty request for a bot whose seq 1 is a gap). Keep the script's filter
  of rows with `seq >= before_seq` (it makes the cursor strictly decrease); a page that was non-empty before that filter and empty after it
  means the server ignored the cursor: `protocolChanged`. Add ceilings the script lacks: at most 400 pages per bot and 2,000 requests per
  run (constants in `GrokProtocol`).

## Rules that bind every phase
1. **Read-only against Grok.** The client type can express exactly two calls, `ListGrokBotTranscriptEntries` and
   `PresignSandBoxStoreReads`, plus a GET of the https blob URLs Grok returns (no auth header, no cookies, redirects refused, host not
   localhost, `.local` or an IP literal). Strictly sequential, at least 0.5 s between request starts of every kind (injected clock). A
   4xx is never retried: a 401 pauses for a fresh sign-in, every other 4xx stops the run. Never send, edit, delete, mark read or change a
   setting; never use the refresh token; never write to Grok Bot's folder or Keychain item.
2. **The sign-in lives in memory only.** Never in `AppStore`, `@Published`, `UserDefaults`, Torvli's Keychain, a file, a log, an error
   string, a URL or argv. No `print`, `NSLog`, `os_log` or `Logger` inside `GrokExport/` (a lint test enforces it); headless commands
   print counts only. Only these leave the Mac, only to `api2.cursor.sh` and the blob hosts its answers name: the agent id, cursor and
   limit of each list request, the bearer token and the client headers. No message content, no telemetry.
3. **One Keychain Allow per import, explained first.** `SecItemCopyMatching` in Torvli's own process (never `/usr/bin/security`), on a
   private queue bridged by a continuation (not the main actor, not the cooperative pool), after the cheap checks passed, only from a
   user action or an announced headless run. One app-wide in-flight flag, so a closed and reopened sheet cannot stack a second dialog.
   The call cannot be cancelled: Cancel abandons the wait and a late result is zeroed and dropped. Never kill a process while its dialog
   is up (it orphans the dialog). A second prompt is allowed only after "Forget sign-in", a pause that outlived its hold, or a 401
   mid-run, and the screen says so first.
4. **Live contact with Grok or its Keychain item only in the marked live steps,** from the packaged, signed `~/Applications/Torvli.app`
   started with `open` (as `--ui-smoke` is; not the debug binary; not plain ssh, which has no GUI session and fails with
   `errSecInteractionNotAllowed`), with Konrad at the Mac. All else uses synthetic fixtures and URLProtocol stubs; nothing in
   `GrokExport/` defaults to `URLSession.shared`, so a test that forgets to inject a session cannot reach the network.
5. **Do not touch** `scripts/*.py`, `~/Documents/Torvli Grok Export` (read-only, for comparisons), Grok Bot's files, Konrad's box, or
   the real store without a backup.
6. **Honest copy.** "Memory only, never saved or logged" (Swift strings cannot be zeroed), `api2.cursor.sh` by name, "saved in Torvli's
   data folder on this Mac". Never "wiped", "only Grok's servers", "no files are written", "full history" or "cannot send".
7. Swift 6 strict concurrency (Sendable values, pacing state in an actor, `@MainActor` only for UI state). New code is formatted
   normally (≤140 columns; the repo's 785-character lines defeat the 500-line rule). Progress is text plus static bars with animation
   disabled; no new spinners. Our own avatars via `GrokAvatarMap`; no Grok assets.

**Secret lifetime** (a table-driven test asserts which secrets are alive in every coordinator state):

| Secret | Alive from | Zeroed |
|---|---|---|
| Keychain bytes | `SecItemCopyMatching` returns | as soon as the key is derived |
| Derived 16-byte key | derivation | right after the three values decrypt and the token checks out; **kept only if the token is expired** (pause "open Grok Bot once"), at most 10 minutes (continuous clock), with a visible "Forget sign-in" button, so Check again needs no second prompt |
| Token, machine id, team id (`SecretBytes`, one actor, not `Codable`, redacted description) | decryption | finished, cancelled, failed, dismissed, forgotten, or 10 minutes into a pause |
| `Authorization` string | request build | transient (cannot be wiped; Rule 6) |

### P10a — Offline core and importer hardening (no secrets, no network). Branch `p10a`
Today `importGrokBundles` forces `konrad.agenthut.net` on every bot, overwrites edited bots, ignores `persistenceEnabled` on the sheet
path and redacts everything on the main actor, and `GrokHistoryStore.merge` rewrites an undecodable archive with only the new lines.

1. **Importer.** `importGrokBundles(_:policy:)` with `GrokImportPolicy`. The default `.legacyFileImport` is today's behaviour: every
   existing test (the `konrad.agenthut.net` assertion included) passes unedited. `.inApp(serverURL:refreshIdentity:)`: (a) new bots take
   the Settings server URL (the `hermesBaseURL` default), never the constant; an existing or adopted bot keeps its own; (b) a bot
   already linked by `grokSourceID` gets history only (no overwrite of name, title, persona, avatar, backend, profile, URL) unless
   `refreshIdentity`; (c) binding for new and adopted bots: candidates = [`bundle.profile`, `grok-<slug>`, `<slug>`] valid per

   set, the first free candidate (the "Add key" banner asks for the key); else no profile = **history-only**. A linked bot without a
   profile is bound the same way later by `bindUnboundGrokBots()` (fill-only, never overwrites a profile); (d)
   `source.hidden_from_sidebar` sets `isHidden` on creation only; (e) both policies throw when `!persistenceEnabled`, and a failed save
   of `store.json` (today `try?`) surfaces as an error instead of a green run; (f) archive lines are prepared off the main actor and the
   commit yields between bundles. `GrokBotBundle` stays a lenient decoder with optional
   `source{hidden_from_sidebar, created_at_ms, harness, notify_on_agent_updates}`, `limitations`, `statistics`, message
   `attachments`/`reply_to`/`thread` (every fixture still decodes), `Sendable`, and `init(_ v1: GrokBundleV1)`. **History-only** = a

   `GrokBotBundle(v1)`. Same allowlist and branch order as `map_entries`. Deliberate differences, each with a test:

5. **`--grok-parity <dir>`** builds the bundles from the real cache in memory and compares them with a Python export of the same cache

## Risks
- **Private API.** Grok can change or refuse the interface at any time; the terms position is Konrad's (D1). Mitigation: gating by
  shape, the canary, `--grok-probe` after every Grok Bot update, cache-only that works without it, one switch. There is no release
  channel yet (no tags), so copy cannot promise "update Torvli".
- **Unverified macOS behaviour until P10.0:** the dialog wording and whether it asks for a password, the status for Deny, whether the
  attributes-only query is silent, whether a Finder-launched Torvli can read the folder without a prompt (earlier runs had Full Disk
  Access via ssh or Terminal), HTTP/2 and gzip through `URLSession`. A red P10.0 ends full-history mode.
- **Keychain trust.** Always Allow would give Torvli permanent decrypt rights over every Grok Bot safeStorage secret, the refresh token
  included; hence Allow in the copy, three values decrypted, best-effort wiping, and the key held only in a bounded pause.
- **Untested server paths and gaps.** Blob, presign and omitted rows (0 of 7,124 on 2026-10-13) are proven only against the fake. About
  9 % of sequence numbers are absent for reasons nobody has established, so "complete" cannot be promised; if Grok re-ids an entry at the
  same seq, both lines stay (the archive is additive by id).
- **Drift and cost.** Grok Bot auto-updates (cache layout moved 2026-10-08, roster already schemaVersion 4): fail closed with an honest
  message, never guess. About 3.1k lines of Swift 6 never yet compiled, tests that run only on the MacBook, three phases that need
  Konrad's clicks.
- **Collisions.** P11 moves the Overview model section and P12 adds an OpenClaw pane and binding; P10 touches `AppStore`,
  `SettingsAccountPane`, `SidebarView`, `ContentView`, `ChatView` and README. Keep edits to shared files to the ones this brief
  names (P10a's importer files, P10d(4)), put the rest in new files, and rebase instead of merging twice.
