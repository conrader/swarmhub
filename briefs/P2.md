# P2 — Routines (Grok Bot routines on Hermes cron jobs)

Read `PLAN.md` first; its standing constraints apply. Start from `main` after P1 is merged.
Hermes reference: `~/code/hermes-ref` at tag `v2026.8.19` — `gateway/platforms/api_server.py`

`cron/scheduler.py` (how runs execute and title their sessions, ~85-120).

Grok Bot behaviour to match: each bot has a Routines tab listing its scheduled routines, each with
a name, schedule, prompt, on/off state, last run and next run; you can add, edit, pause/resume,
run now and delete one; when a routine finishes, its result lands in the bot's chat as a card,
marks the bot unread and notifies (if the bot's notifications are on). Imported routines start
disabled.

## Hermes API (per bot = per profile, via the existing `/p/<profile>` prefix and that profile's key)
- `GET /api/jobs` → `{"jobs":[...]}`; `GET/PATCH/DELETE /api/jobs/{id}` (id is 12 hex chars);
  `POST /api/jobs` body `{name, schedule, prompt, deliver?, skills?, repeat?}` → `{"job":{...}}`;
  `POST /api/jobs/{id}/pause|resume|run`. PATCH allows `name, schedule, prompt, deliver, skills,
  skill, repeat, enabled`. Errors are `{"error": "..."}`; 424 means the scheduler is unavailable.
- Job fields include `id, name, prompt, schedule, enabled, state ("scheduled"/"paused"/…),
  next_run_at, last_run_at, last_status, last_error, repeat, origin`. Confirm exact shapes and the
  schedule string grammar (cron expression, "every 30m", etc.) from `cron/jobs.py`.
- Route presence decides the feature: if `/api/jobs` returns 404, the Routines tab shows
  "This Hermes server has no jobs API" and keeps today's local-only list read-only.
