# P54 — App requests are never silently ignored (the GitHub bug)

Konrad, 2026-10-16: "can you check right now plainsay transcript ?" … "the important part is the github bug". Built in
lane 2 next to P53. Not released until Konrad names a release.

## Evidence (Plainsay's Bot Chat on the box, 0.5.8)
- 19:02:49 assistant `[[SWARMHUB_APP_REQUEST_A21C0DFC-57A7-40FF-AB3F-AFF05724BDF6]] {"action":"execute","tool":
  "GITHUB_GET_VIEWER_GRAPHQL","account":"conrader","arguments":{}}`, then nothing.
- 19:04:08 assistant `[[SWARMHUB_APP_REQUEST_A21C0DFC-…]] {"action":"execute","tool":
  "GITHUB_LIST_REPOSITORIES_FOR_THE_AUTHENTICATED_USER",…,"page":1}}}` (one extra `}`), then nothing.
- No result row, no error line, no Composio call. `A21C0DFC…` is the marker of the 11:29 turn.

## Cause
`ConnectedAppsChat.swift:70` makes a new marker per turn; `AppToolRequest.parse` (`:9-12`) returns nil unless the reply
starts with **this turn's** marker. Plainsay copied the old marker from its history, so the reply counted as plain text:
nothing ran, nothing answered, the turn ended with the raw request as its "answer". `GITHUB_GET_VIEWER_GRAPHQL` is also not
a tool it discovered.

## Fix
1. In an apps-enabled turn, a reply that starts with any `[[SWARMHUB_APP_REQUEST_<uuid>]]` is never plain text. Stale
   marker: send the bot an app-result error "That request used an old marker. Use this one: <current marker>", log it
   (P52 log), and continue the turn so it retries. At most 2 such corrections per turn, then a chat line "Plainsay keeps
   sending app requests SwarmHub can't accept" and the turn ends normally.
   Keep the safety purpose of the marker: a marker-shaped line that appears only inside an app result or quoted text is
   still ignored. Only the bot's own reply in a SwarmHub-run turn counts.
2. Tolerant parse: one complete JSON object followed only by whitespace and stray `}` / `]` is accepted (log the trim).
   Anything else malformed keeps P52's error back to the bot.
3. A tool the bot never discovered (e.g. `GITHUB_GET_VIEWER_GRAPHQL`) goes back to the bot as an error "unknown tool;
   search first", not a silent end, unless it is a forbidden tool (P38 B `COMPOSIO_*`), which keeps ending the turn
   with a line.
4. Make sure the marker instructions are in every apps-enabled turn, including turns after a restart, `/goal`
   continuations and P42 bot-message turns. Add the current marker to the "Continue the original task" line after each
   app result, so the bot always has the fresh one in front of it.
5. If a turn still ends with a reply that starts with a marker, it shows as P51's folded line plus a warning line "This
   app request was not run" (never raw, never silent).
