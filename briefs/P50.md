# P50 — Chats open where you left them, with Jump to latest

Konrad, 2026-10-16: "when we start the app - I am on top of the msg feed - so the oldest ones" … "I think if we
rememebr what was the scroll position - that would be ok. Otherwise we need a button 'jump to latest'" … "or similar"
… "add this to current build". Built on the audit-fixes merge branch (`maudit`) and merged to main with it. Not released
until Konrad names a release.

Cause: `ChatView.swift:56-57` and `GroupChatView.swift:45-46` scroll to `"bottom"` only `onChange` of the last message or
the count. Nothing scrolls when a chat appears (launch, switching bot/group, closing a thread), and the LazyVStack starts
at the top.

1. **Remember the position.** For each conversation (bot chat, group, thread) keep the id of the top visible message,
   saved with the store so it survives a relaunch (absent field = none; old store.json loads fine). Opening the chat
   restores it, after the lazy rows lay out.
2. **No saved position, or its message is gone** (deleted, hidden as [SILENT], trimmed): open at the newest message.
3. **Jump to latest.** A floating button, bottom centre above the composer, whenever the view is not at the bottom:
   "Jump to latest", plus " · N new" when N messages arrived below since the user scrolled up. A click scrolls to the
   newest and hides it. Same in groups and threads. Accessibility label "Jump to latest message".
4. **Auto-scroll only at the bottom.** New messages and streaming text follow only when the view was already at (or
   within a few rows of) the bottom. Reading older messages is never interrupted. Sending a message always goes to the
   bottom.
5. Keep P41 jump-to-message (`store.scrollTarget`), the thread transcript scroll, arrivals above a thread, and the
   approval cards at the end.

Tests: the position is saved per conversation and restored; old store.json without it loads; a missing message falls back
to the newest; N counts only messages that arrived while scrolled up; sending resets to the bottom. Use the view-model
logic, no real scrolling or sleeps. Renders (`--render-setup --only p50`): a long chat reopened at a saved middle
position with "Jump to latest · 3 new", and a first open at the newest. Files ≤ 500 lines; commit identity Konrad's
noreply address, no Co-Authored-By.
