# P25 — OpenClaw in the setup window

Konrad 2026-10-14: "make OpenClaw show up in the setup window too". This finishes P21 D4 (`briefs/P21.md:16`): P12 was
to flip `OpenClawBackend.isImplemented`, add the "which software" step (S2) and its connect screen. P12 built the
transport, chat, approvals and the Settings → Advanced → Servers and keys → OpenClaw section, but left the flag `false`
(`Backends/OpenClawBackend.swift:9`), so the wizard still says "OpenClaw: add it later in Settings → Advanced."

After this phase a first-run user picks Hermes or OpenClaw in the setup window and, for OpenClaw, connects a Gateway,
pairs this Mac and adds its agents without opening Settings. The Settings section stays as it is.

## Decisions
- **D1 Flag.** `OpenClawBackend.isImplemented = true`. `SetupFlow.offersSoftwareChoice` keeps reading it.
- **D2 Steps.** `SetupFlow.Step` becomes `welcome, hosting, software, address, openClaw, choose, done`.
  Welcome → "Connect my existing box" → **software** (two cards: Hermes, OpenClaw) → Hermes: `address` (unchanged) ;
  OpenClaw: `openClaw` → Test → `choose` → Add → `done`. Back from `openClaw` or `address` returns to `software`;
  `SetupPrefill.startAtAddress` (Change connection / history-only banner, both Hermes) still starts on `address`, with
  Back going to `software`. The hosting card's footer button goes to `software` too.
- **D3 OpenClaw connect screen (S3-OC).** Fields: Address (default `OpenClawCopy.tunnelURL`), Key (secure; caption: the
  Gateway token from `OpenClawCopy.tokenCommand`; blank allowed for Tailscale/proxy identity), "Allow plain ws:// on my
  private network" toggle, folded "More" with Device name and "Keep the key after pairing" (same defaults as
  `OpenClawGatewaySheet`). URL validation is `GatewayURLRules.validate`, its problem shown inline, Test disabled while
  invalid. The three help lines of `OpenClawGatewaySheet.help` (token command, tunnel, approve) appear with Copy
  buttons. Reuse, don't copy: move the shared field/help views out of `OpenClawGatewaySheet` into one small view both use.
- **D4 Test and pairing.** Test connects through the real hub path (`openClawHub.test` / `agents(for:)`), so the same
  identity and pairing code runs as in Settings. To do that the Gateway entry and key ARE saved at Test (P12's
  `saveGateway`); this is the one documented exception to "only Add writes", and it is undone: Cancel, Back to
  `software`, or closing the window before Add calls `forgetGateway` for a Gateway this wizard run created (never for one
  that existed before the run). Results:
  - connected → `choose` lists the agents from `agents.list` (all ticked, already-bound ones shown disabled "already added");
  - `pairingRequired` → stay on S3-OC with the plain line "Approve this Mac on the OpenClaw host, then press Test again",
    the exact `GatewayState.approveCommand` (shell-safe request id) with Copy, and the Test button relabelled
    "Test again"; no polling loop;
  - any failure → its redacted one line (`redactedOpenClaw`), never the key.
- **D5 Add.** Adds one bot per chosen agent, same shape and idempotency as `addBotsFromGateway` (refactor that into one
  function taking an optional chosen set; Settings keeps passing nil = all). `done` names the count and opens the first.
  Nothing on the Hermes side changes.
- **D6 Copy.** All new strings in `SetupCopy` (+ the `all` list). S1 card line becomes
  "Works with Hermes and OpenClaw." The ban list of P21 item 5 still applies to `SetupCopy`, with this narrow change:
  "OpenClaw" is allowed on the S2 cards and the S3-OC screen copy (update `softwareNames` and the guard tests to the new
  allowed set). Commands are shown verbatim in monospace and are not copy. Plain words: say "key", not "token", in labels;
  the caption may say once "(OpenClaw calls it the Gateway token)".
- **D7 Preview.** `--setup-preview` and `--render-setup` can show `software` and `openClaw` (both pure, no network). The
  render list gains those two steps, including one pairing-required render with a fake request id.
- **D8 Groups.** OpenClaw agents still don't join groups (`joinsGroups`), unchanged.
