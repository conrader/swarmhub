## Goal
No chat, group or 1:1, may silently lose, truncate or skip a reply. After this phase:
- a turn ends "finished" only when the box closed the run, and a reply is called complete only when the box's own row says it stopped normally;
- a turn that did not finish is stored as incomplete or not sent, in the transcript, with a button;
- whatever the box finished while the Mac was away is fetched, never regenerated;
- nothing is sent twice by the app, and the one window where it still can is documented;
- a store hurt by the old behaviour can be healed on demand (`--reconcile`).

**Rules that bind every part.**
1. One function decides what the end of a turn means (`finishTurn`).
2. Every read of the box is a GET and a reconcile writes only Torvli's own store; the only POSTs are the user's Send and Retry.
3. No row, reply or character is deleted.
4. No stream is cancelled because of wake or a path change: the box interrupts a run whose client disconnects.
5. Retry reads the box first, and nothing resends by itself.
6. No real chat text enters the repo, a test, a log or a report.

## Facts: what the box does (0.20.5 source; the live box was not contacted)
- `GET /api/sessions/{id}/messages` (`api_server.py:3626-3684`): `order=oldest|latest`, `limit` ≤500, `offset` (with `latest` it counts back from the newest row). Rows carry integer `id`, `role`, `content`, `tool_calls`, `timestamp`, `finish_reason`. Only active, non-compacted rows come back, so the box can hold fewer rows than the Mac. `inline_images` is read nowhere: user rows with images return full data URLs.
- A turn on the box is a `user` row followed by every assistant segment as its own row. Hermes stores segments without the leading paragraph break the live text has. For a group member the `user` row is the context blob (`[Group chat “…” … Messages since your last reply:]` plus `Author: text` lines, trimmed), never the raw text.
- Session stream: after `_run_agent` returns, the box always sends `assistant.completed` and `run.completed` with hard-coded `completed:true, partial:false, interrupted:false` and sets the run status `completed` (:4009-4041); on an exception `error` (:4053); `done` comes from a `finally` (:4056). So **a terminal event means the box closed the run, not that it answered**; interrupted partials and lease failures are stored without a normal `finish_reason`. Error rows carry `error|agent_error|content_filter` (`hermes_state.py:3060-3062`). `done` alone proves nothing. Headers go out right after validation (:4080-4081), body upload comes first. Keepalive every 30 s (:155). No `Idempotency-Key` on this route.
- A client disconnect (noticed at the next write) makes the box `agent.interrupt` (:4093-4097); the partial is persisted (`conversation_loop.py:4327-4358`); a run that finished first is persisted whole.
- `GET /v1/runs/{id}` serves session runs (status queued, running, waiting_for_approval, stopping, completed, failed, cancelled; kept 3,600 s; capability `run_status`). Only `/v1/runs` maps a stop to `cancelled`. A new turn on a session with an active run waits up to 1,800 s for the turn lease (`run_agent.py:8645-8650`) and its user row is written only after that.
- `run.completed.pending_steer` carries a steer accepted after the final response; `parseNative` drops it (listed in Out of scope).

### 1. Reconcile from the box
New: `Stores/HistoryReconciler.swift` (pure: values in, a plan out; no network, clock or SwiftUI), `Stores/AppStore+Reconcile.swift`, `Backends/HermesBackend+Reconcile.swift`. Changed: `BackendMessage` (`finishReason: String?`, integer `id`), `AgentBackend` (`recentMessages(sessionID:window:offset:)` and `runStatus(runID:)`; the default `recentMessages` forwards to `loadMessages` as a tail slice, `runStatus` nil), `parseMessage` (keeps `finish_reason`, parses Int ids, drops image data URLs from user rows), `AppStore+History.swift` (`loadHermesHistory` calls the engine; `mergeHermesHistory` and `comparable` stay and the engine must append the same rows on their tests), `open(_ bot:)` and `open(_ group:)` (opening reconciles), `ContentView` (launch sweep, Part 4 gating).
- **Read-only, GET only.** `recentMessages` is `GET api/sessions/{id}/messages?order=latest&limit=60&offset=<60·k>`, widened by whole windows while a page is full and the oldest row to check (`incomplete`, `notSent`, empty, or `nil` within the first window) is not covered, at most 5 windows (`--reconcile` pages everything). Windows are merged by row id; overlap or a gap aborts the pass as a read failure (rows can land between GETs). Clock skew comes from the GET's `Date` header; row time only places added rows. Cap the bytes read per sweep. 404 `session_not_found` means no server copy and is not an error. A GET that fails at the connection level is repeated once at once, except `.timedOut`. A legacy-transport bot has no sessions: nothing to read, no Refresh.
- **Sessions.** Bot chat: `hermesSessionID`. Thread: its fork session, extend and fill only. Group: per member `group.session(for:)` or the fallback `sessionNamespace + GroupRouting.sessionID(group:bot:)`, read through that member's own backend (own profile prefix and Keychain key); a member without a readable key is skipped and counted. Authors of old rows who are no longer members are read while their bot still exists.
- **Turns.** A server turn is a `user` row plus the non-empty `assistant` rows up to the next `user` row, joined by a blank line. Bot chat and thread: a non-steer text user row and the first text assistant row after it (filter `presentation == .text`, non-steer, non-system, as `mergeHermesHistory` does). Group, for one member: each row that member wrote with the user row that triggered it (`metadata["for"]`, else the nearest non-steer user row above).
- **Pairing**, newest local turn first, each server turn pairs once, never on time. Turns with a non-empty reply pair first; empty or `notSent` ones take what is left, so a resent "hi" cannot steal the box's turn. Bot chat and thread: `AppStore.comparable` equality with `outgoingText`. Group: add `GroupRouting.parseContext(_:)` beside `context` and match **whole entries** (author Konrad and `comparable(entry) == comparable(trigger.outgoingText)`), never substrings; the test builds blobs through `context`, so a format change fails it. An empty trigger (image-only), or a blob where the `[… earlier messages omitted]` marker precedes the trigger, is unmatchable by user side: pair those by reply relation inside the member's ordered sequence, and only when both replies have ≥20 non-space characters. Same-text turns pair newest to newest; across different texts order is not required (Retry can land a turn out of order).
- **Reply relation**, whitespace ignored: `equal`, `localPrefix`, `serverPrefix`, `conflict`.
- **Eligibility.** Only `incomplete`, `nil` and empty `notSent` rows may be extended or filled. `finished` and `stopped` rows are never edited, but they still consume their paired server turn (otherwise it comes out unpaired and is added as a duplicate).
- **Outcomes.** `equal` settles (a `nil` row that is equal stays `nil`: no stamp, no write). `localPrefix` extends: append the server text after the matched prefix, minus the leading whitespace the local text already ends with (incident case: local `P1 + "\n\n"`, server `P1 + "\n\n" + P2`, 100 → 293, old text a byte-for-byte prefix). An empty local reply, or a `notSent` row the box has, is filled from the server turn; a bot-chat user row with no reply row gets one inserted. `serverPrefix` and `conflict` leave the row untouched and are counted.
- **Adding.** An unpaired server turn newer than the oldest pair is added (group member: assistant row with `authorID` = the member; bot chat: user row and reply row) after the last local row not newer than its server time, else at the end; with no local turn at all, every server turn is added. Mid-transcript additions are capped at 10 per pass, the rest reported; turns older than every pair are ignored and counted. **Duplicate guard:** never add a server turn whose reply or user text is equal or prefix-related to any local row of that member or conversation (count it `ambiguous`), or whose box row id is already in some row's `metadata["box"]`. Every adopted, extended or added row records its box row ids there. An unpaired local turn is untouched. When local turns exist, the box has rows and nothing pairs, the plan is `diverged` and the existing quiet note appears as today (an empty server list with local turns also still gives the note).
- **"Later" settle.** A `notSent` group row whose trigger sits as a whole entry in the blob of a later paired turn of the same member settles as `finished`, why `later` (that turn carried it).
- **Settling (attestation).** `incomplete` becomes `finished` only when the local reply equals the server's **and** the server turn's last assistant row has `finish_reason ∈ {stop, end_turn, length}`. `nil`, `tool_calls`, `tool_use`, `error`, `agent_error`, `content_filter`, `incomplete` never attest. `runStatus` may only veto: queued, running, waiting_for_approval or stopping mean keep polling (and do not consume a schedule slot, capped at about 30 min); it never attests. Text unchanged across two reads ≥10 s apart only stops polling. A non-active run (or no `run_status`) with an unattesting row ends as `incomplete` with the footer "The box has no more of this reply" (or "The box ended this reply with an error" for an error reason). An empty `incomplete` placeholder older than 120 s (box clock) whose user turn the box does not have, with the window reaching back past it, becomes `notSent`.
- **Invariants** (tests loop over generated cases): no local row deleted or reordered; an extended reply keeps its old text as a prefix; a second pass over the same server rows changes nothing; a row that is streaming, `stopped`, or changed since the snapshot is never touched; a conversation with a streaming turn is skipped until it ends; extended and added rows start no notification, and added rows alone bump the unread count when the chat is not open.
- **No automatic pass raises `errorMessage`** (open, launch, wake, path, schedule: change the assignment in `loadHermesHistory`); only the user's Refresh reports, as a row footer.
- **Triggers**, one pass per session at a time. Automatic passes are ≥15 s apart per session, except the cut-turn schedule (Part 3), which is exempt. They are: launch (D2's sweep, after the UI is up, skipped offline), a chat or group opened (30 s since its last pass), an interrupted turn, wake and network restored, the first successful box response after a failure streak, the Refresh button, `--reconcile`. The caption "Restored from the box" comes from `metadata["restored"]` (`extended` or `added`).

### 2. Truthful turn state
New: `Models/TurnState.swift` (`TurnState`, `TurnOutcome`, pure `TurnOutcome.classify`), `Stores/AppStore+Turns.swift` (one stream consumer and one `finishTurn`, used by both send paths), `Views/TurnStateFooter.swift`. Changed: `ChatMessage`, `AgentBackend` (stream end), `AppStore.swift` send/stop, `AppStore+Groups.swift`, `MessageView`. The terminal-event logic stays in `HermesBackend.swift` unless it would pass 500 lines; if it moves, un-private `HermesRunRegistry`, `makeRequest` and `parseMessage`.
```swift
enum TurnState: String, Codable, Sendable { case finished, incomplete, stopped, notSent }   // ChatMessage.turnState: TurnState?  (@Published)
struct StreamBreak: LocalizedError { let delivered: Bool; let underlying: Error }
```
- **State on the row that holds the reply** (nil = written before P16; the engine treats nil as possibly truncated). `finished`: a terminal event arrived. `incomplete`: the row exists and the turn has not been shown to end; a row is born `incomplete`. `stopped`: the user pressed Stop, set at once in `stop()`; never extended. `notSent`: the turn did not reach the box as far as the Mac knows; the row is kept, empty. Encoded only when set (an untouched store encodes byte-identically; store version stays 2). **`turnState` decodes with `(try? decodeIfPresent) ?? nil`** so an unknown value cannot make the whole store undecodable. Metadata keys: `for`, `run` (read with `stopTarget` after the first event), `why` (offline, timeout, error, refused, stopped, quit, later), `ambiguous`, `restored`, `box`, `tone`.
- **Terminal events.** Native: `assistant.completed` or `run.completed`. Legacy: `data: [DONE]`, and a legacy finish chunk with `finish_reason:"error"` or `hermes.failed` yields `.failed`. `done` alone is not one. EOF without a terminal event throws `StreamBreak(delivered: true, …)`; any error after the response headers is wrapped the same way; an error before them is wrapped with `delivered: false`; HTTP error status stays `BackendError.http`; cancellation stays cancellation. The consumer treats a stream that finishes without having yielded `.completed` as `incomplete`, and the reviewer path stays covered.
- **Classification** (`TurnOutcome.classify`, pure; a table test pins every row):

| What happened | Row | Footer | Box has it? | Reconcile | Rest of a group round |
|---|---|---|---|---|---|
| terminal event | `finished` | none | yes | no | continues |
| the user pressed Stop | `stopped` | "Stopped" if empty | yes | no | skipped members get `notSent`, why `stopped` |
| certainly unsent: `notConnectedToInternet`, `cannotFindHost`, `cannotConnectToHost`, `dnsLookupFailed`, `secureConnectionFailed`; 401, 403, 409, 422, 429; `ModelRefusal`; request never started per `URLSessionTaskMetrics` | `notSent` | "Not sent (<why>)" | no | no | offline-class stops the rest (why `offline`); HTTP/refusal continues |
| ambiguous before the headers: open deadline, `timedOut`, `networkConnectionLost`, 5xx, 52x | `notSent` + `ambiguous` | "Not confirmed (<why>) — the box may have it" | maybe | no | stops: rest get `notSent`, why `timeout` or `offline` |
| any other error before the headers (`BackendError.unavailable/invalidURL`, `AttachmentError`, session create or model plan failure) | `notSent`, why `error` | "Not sent (error)" | no | no | continues |
| connection error after the headers | `incomplete` (kept, even empty) | "Incomplete" | yes | yes | stops: rest get `notSent`, why `offline` |
| EOF without a terminal event, or the box's `error` event / `run.failed` | `incomplete` | "Incomplete" | yes | yes (the box's own failure: once) | continues |

- **A persisted line for every failure**, a `.system` row after the reply row, `"<Bot>: <reason>"`, through `BotInfoCache.describe(_:key:)` so a proxy-echoed key shows `[key]`; an identical line is not repeated back to back. These rows get `metadata["tone"]="warning"` and `MessageView` shows `exclamationmark.triangle` for them (no animation), keeping the checkmark for neutral notes. `errorMessage` is set exactly where it is today (D3).
- **Nothing is deleted.** The group branch that removes an empty placeholder goes; the 1:1 path stamps its state. A refused send in a 1:1 chat becomes `notSent`, why `refused`; in a group it stays the existing "was skipped" system row.
- **Notifications and unread.** Only `finished` notifies. An `incomplete` reply that has text still bumps the unread count.
- **Footer** (`TurnStateFooter`, in `MessageView`): the texts in the table; under an `incomplete` row that is not streaming also a Refresh button (hidden when the chat has no sessions), and "Checking the box…" as plain text while a pass runs; under an empty `finished` row with why `later`, "Delivered with a later message"; under a restored row, "Restored from the box". Hide the tapback and reply actions only on an empty assistant `.text` row without attachments (image-only user rows and routine cards are legitimately empty). Plain buttons in the style of the steer label, no animation, accessibility labels.

### 3. Retry, and never a double send
New: `Stores/AppStore+Retry.swift`. Changed: `AppStore+Turns.swift` (in-flight ledger, reconcile schedule), the footer, and both send paths (`runTurn(reusing:)` into an existing `notSent` row, no steer fallback).
- **`retry(_ row)`** works on a `notSent` row only. **It claims the stream slot synchronously, before its first await** (`isStreaming`, `activeStreamToken`, `streamTask`, and a `GroupRun` for groups, footer "Checking the box…"), so `send`, `send(to:)`, a second Retry and `stop` all see a turn in progress and Stop stays live. The claim is released on every exit, including a failed read. After the read it re-checks on the main actor that the row is still `notSent` and unchanged; any mismatch drops the Retry (no steer, no POST).
- **Steps.** (1) Read the box (item 1's read of that row's session; a chat with no session yet counts as "the box lacks the turn"). (2) If the pairing finds the turn, adopt it and settle the row; if the box has the user turn but no reply yet, mark `incomplete` with `run` and let the schedule poll; no POST. (3) Only when the read succeeded, the window reaches back past the row, the box has no such turn, and no unpaired server user turn is newer than the member's last paired turn: run the normal send into the same row. If a newer unmatched server user turn exists, show "Can't match the box's newest message; nothing was sent" and offer an explicit Send anyway. (4) If the read fails or does not reach back far enough, keep `notSent` and add "Can't reach the box; nothing was sent." Never skip step 1. An `ambiguous` row needs a second explicit tap while it is younger than 30 min.
- **What it sends.** Bot chat and thread: the original user row's `outgoingText` and images (history cut at that row, because `sendSession` sends the last user message). Group: a context built now by `GroupRouting.context` for that member, plus the trigger row's images re-encoded; on `AttachmentError.unreadable` keep `notSent`, add a line, send nothing.
- **Offered only** on a member's newest row, for a current member with a key and a working backend. A legacy-transport bot gets no one-tap Retry. If the member answered a later turn, the engine settles the older row. In a bot chat any `notSent` row can be retried.
- **Guard.** An in-memory ledger keyed `conversation|member|user row id` refuses a second attempt while one runs; after a cut stream the app only reads. Documented residual windows: a request an edge proxy still holds, and a request queued behind the box's turn lease whose user row is not yet written.
- **Automatic reconcile after a cut stream.** An `incomplete` row schedules passes at 0, 3, 10, 30 and 90 s (injected schedule, exempt from the 15 s floor), each GET-only. A pass that cannot reach the box uses no slot and repeats at 2, 5, 15 and 30 s, then 2 and 10 min, then waits for the next trigger. Refresh runs a pass at once.

### 4. Sleep, wake, network and timeouts
New: `Stores/ConnectivityMonitor.swift`, `Backends/HermesTimeouts.swift`. Changed: `AppStore.init` (default session, `connectivity:` parameter), `HermesBackend` (`makeRequest` sets `timeoutInterval`, open deadline), `ContentView` (start beside `startRoutinePolling`).
```swift
enum ConnectivityEvent: Sendable { case willSleep, didWake, pathUp, pathDown }   // ConnectivitySource.events; ManualConnectivity in tests
```
- `SystemConnectivity`: `NWPathMonitor` (`pathUp` when satisfied after not satisfied), and `NSWorkspace.shared.notificationCenter` for `willSleepNotification`/`didWakeNotification`. **Terminate is not an event in the stream**: a block observer on the default center for `NSApplication.willTerminateNotification` (queue `.main`) calls `MainActor.assumeIsolated { store.flushNow() }` synchronously.
- **Gating.** The launch work (`SystemConnectivity.start()`, `recoverInterruptedRounds()`, the sweep) is gated on `routines.autoLoad` and runs once per process (a `didLaunchRecovery` flag), so snapshot renders, `--render-snapshot`, headless tools, tests and a second window never trigger it. `SystemConnectivity` is never created in tests.
- **Reactions.** `willSleep`: flush a save. `didWake`, `pathUp` and the first successful box response after a failure streak (a path event can fire while the link is still dead, as on 2026-10-13): flush the URL session, then a reconcile pass for every conversation holding an `incomplete` or `notSent` row or a pending round, and for the open one. `pathDown`: nothing is cancelled (rule 4); a stalled stream ends by its own idle timeout. A round starts no member's turn while the path is down (the table's "stops" rows).
- **Timeouts** (`HermesTimeouts`, one file, each constant with its reason): chat stream idle **90 s** (3× the box's 30 s keepalive, chat stream only); open deadline **20 s plus body bytes ÷ 50 KB/s**, a race around `session.bytes(for:)` that fails the attempt as `timedOut` when no response headers have arrived (upload counts, 5–10 MB messages are legal); GET reads and session create 30 s; jobs, fork, approval and model POSTs stay at 60 s; steer and stop 8 s. Set `request.timeoutInterval` explicitly in `makeRequest`. `HermesURLSession.make()` returns **one process-wide session** (also used by the `HermesBackend(...)` calls in settings and `AgentApp`) with `urlCache = nil` and `.reloadIgnoringLocalCacheData` (read-first decisions must never see a cached GET); `waitsForConnectivity` is already false by default, and the resource timeout stays at the platform default.

### 5. In-flight work survives
New: `Models/GroupRound.swift`. Changed: `GroupChat` (`round: GroupRound?`, encoded only when set, decoded with `(try? …) ?? nil`), `AppStore+Turns.swift` (autosave, flush), `AppStore+Groups.swift` (round bookkeeping, Stop rows), `save()` (reports a failed write once per streak instead of swallowing it).
```swift
struct GroupRound: Codable, Equatable { var userMessageID: UUID; var remaining: [UUID]; var active: UUID? }
```
- **Saves.** Save synchronously at placeholder birth and at every `round` change; only token appends are throttled (at most every 2 s, `autosaveInterval` injectable). The row is `incomplete` on disk throughout. `willSleep`/terminate save at once; the final save still ends every turn.
- **Round record.** Written with the user row (`remaining` = the recipients), updated as each member starts and ends, cleared when the round ends.
- **Launch recovery** (`recoverInterruptedRounds()`, from `ContentView`'s `.task` under the Part 4 gating, never from `init`): handles only group ids with `round != nil` captured at decode, and is a no-op unless `!isStreaming && streamTask == nil && groupRun == nil`. Each member in `remaining` gets a `notSent` row, why `quit`, and one system line "`AppConstants.name` quit before <names> were asked. Retry on their rows."; the round is cleared and saved. Nothing is sent. Never write the literal app name in Sources (P18 guard).
- **Stop.** When a Stop ends a round, each member still waiting gets a `notSent` row, why `stopped`, and one line "Stopped. Skipped: <names>."

## Risks
- The repair is only as good as the pairing. A wrong pair could extend the wrong reply, so the engine extends only on a strict prefix inside a paired turn, only rows that are `incomplete`, `nil` or empty, guards against duplicates, caps mid-transcript additions, and `--reconcile --dry-run` shows the plan first. A format change in `GroupRouting.context` fails the `parseContext` tests loudly.
- The box may rewrite the final text (think-block stripping, media tags): `conflict` means no change and an honest `incomplete`, never a wrong edit.
- `finish_reason` over HTTP and `run_status` are source-read on 0.20.5 (the incident row did carry `finish_reason=stop`, read from `state.db`); 0.21.x is unverified. Both degrade to "not attested", which keeps the footer instead of clearing it.
- A reply the box also cut (it interrupted the run when the client vanished) stays `incomplete` for good: Refresh finds no more and says so.
- The double-send guard cannot see a request an edge proxy still holds or one queued behind the turn lease; a Retry after an ambiguous failure can then send twice (the box serialises them). Documented, not solved; the second-tap rule narrows it.
- The 20 s open deadline and 90 s idle timeout cancel a request the box may already have; the box then interrupts that run and the row reads "Not confirmed" or "Incomplete" until Retry or the reconcile adopts the partial. The idle timeout assumes the 30 s keepalive reaches the Mac through Cloudflare and nginx; no stream in the evidence ran past 30 s, so that is unobserved. Each constant is one line in `HermesTimeouts`.
- The launch sweep adds up to 20–40 GETs after the UI is up (bytes capped); if it ever slows startup, delay it, do not drop it.
- The footers and buttons are unseen on screen (the snapshot draws them and the executor looks once). Konrad's Wi-Fi test is the last hop.
