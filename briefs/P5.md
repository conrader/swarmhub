Grok Bot behaviour to match: a group chat contains the user plus several bots (e.g. "Konrad, DMT,
Achilles"); the user can address one bot with @name or everyone; each bot answers in the shared thread
with its own avatar; the Members tab lists who is in the chat and lets the user add/remove bots.

## Must do
1. Model: a `GroupChat` (id, name, member bot ids, messages with author = user or bot id, unread,
   hidden, muted) persisted in store.json with a version-safe decoder (old stores still load).
   Sidebar shows groups in their own section with stacked member avatars.
2. Routing: a user message with `@Name` (case-insensitive, autocomplete popup in the composer) goes only to
   the mentioned bots; with no mention it goes to every member, sequentially in member order (not in
   parallel, to keep the box light). Each bot runs in ITS OWN Hermes session dedicated to this group
   (`group-<groupID>-<botID>`, created via the existing session-create path), with the group transcript
   since that bot's last turn sent as context (author-prefixed lines, capped at ~8k chars). Approvals,
   Stop and steer keep working per bot (Stop stops the bot currently answering and skips the rest).
3. Members tab: list members with avatar/name/profile, add bot (picker of existing bots), remove bot,
   rename group. New group: "New group" button → pick ≥2 bots.
4. Tests: mention parsing (incl. names with spaces, unknown names, email-like text not a mention), routing
   order and Stop-skips-rest, per-bot session ids, context capping, persistence round-trip + old-store decode.
