# P26 — The manager agent on OpenClaw (bot management by message)

Konrad 2026-10-14: "open claw and hermes are connected the same way via msg to agent?" → "do all at once". P22 lets the
manager bot (Jarvis) create bots, change their instructions and avatars, and retire them, by message, on stock Hermes,
with the manager text sent on demand only. This phase gives an OpenClaw agent the same role on stock OpenClaw.
Nothing is installed on the OpenClaw host; the text travels with the management turn, exactly like P22.

Facts (openclaw@2026.10.3 docs, read 2026-10-14; `docs/cli/agents.md`, `docs/concepts/agent-workspace.md`,
`docs/gateway/configuration/hot-reload.md`, `docs/tools/exec.md`):
- `openclaw agents list --json`; `openclaw agents add <name> --workspace <dir> --non-interactive --json` (name → agent id;
  non-interactive needs name + workspace); `openclaw agents delete <id> --force --json` (workspace/state go to Trash,
  not hard-deleted; the only agent can't be deleted); `openclaw agents set-identity --agent <id> --name/--emoji`.
- Instructions live in the agent's workspace `AGENTS.md` (persona/tone `SOUL.md`; also `IDENTITY.md`, `USER.md`).
  Default workspace for a new agent: `~/.openclaw/workspace-<id>`. `agents.*` config changes hot-apply (no restart).
- The agent runs shell through its `exec` tool (subject to the host's exec policy and approvals; P12 Part C already
  shows Gateway approvals in SwarmHub).
- OpenClaw has no system-prompt parameter (P12: `bot.persona`/`systemPrompt` are sent nowhere).

## Decisions
- **D1 Role.** `isManager`, `setCanManageBots`, `manager(for:)` accept `.openClaw` bots. A connection for OpenClaw is
  `openclaw:<gatewayID>` (one manager per Gateway, one per Hermes base URL as today). The editor's "Can manage bots"
  toggle shows for OpenClaw bots too. No automatic migration (Jarvis stays the Hermes manager).
- **D2 Text.** New `Resources/BotManager/manager-openclaw.md` (≤ ~3 KB, same voice and rules as `manager-hermes.md`):
  ask Konrad first before create/change/retire; never print secrets or config files; recipes:
  list `openclaw agents list --json`; create `openclaw agents add "<name>" --workspace ~/.openclaw/workspace-<id>
  --non-interactive --json` then write `AGENTS.md` in that workspace with a heredoc; read
  `cat <workspace>/AGENTS.md` (workspace from the list JSON); change = copy `AGENTS.md` to `AGENTS.md.prev-<UTC stamp>`
  then heredoc; retire = `openclaw agents delete <id> --force --json` only after an explicit yes (it moves files to
  Trash); never touch the default agent or `{{MANAGER}}`; never edit `openclaw.json` by hand; avatars are SwarmHub
  marks (same shape/colour lists as the Hermes text); if `exec` is not available, say so and give Konrad the exact
  commands instead. Same swarmhub block contract and ops; `name` is the OpenClaw agent id. `BotManagerText` picks the
  template by backend; placeholders `{{MANAGER}}` (agent id). Package/build scripts copy the new file (both already
  copy `Resources/BotManager`).
- **D3 On demand without a system prompt.** The decision when to attach stays `ManagementExchange` (unchanged). For an
  OpenClaw manager the text is sent inside that turn's user message, wrapped in one marked block before Konrad's text:
  `<swarmhub-manager v="1">…</swarmhub-manager>\n\n<his text>`. Only on attaching turns. The chat bubble shows his text
  only; history loaded from the Gateway (`OpenClawHistory`) strips a leading marked block the same way, so it never
  appears in the transcript view; the composer/steer path never adds it. Hermes keeps the system-prompt path unchanged.
  Make this a backend-neutral request field (e.g. `managementText`) that `HermesBackend` appends to the system prompt
  as today and `OpenClawBackend` wraps into the message; keep Hermes request bodies byte-identical (test).
- **D4 Applying blocks.** `handleManagerReply` works for both. OpenClaw specifics:
  - `bot_created`: no keys. Refresh `openClawHub.agents(for:)` a few times over ~10 s (same knobs as `botProbeAttempts`/
    `botProbeDelay`); when the id is listed add one bot bound to `(gateway, id)` (reuse the `addBotsFromGateway` path
    with a chosen set, shared with P25 if it already landed; otherwise a small helper), apply description/avatar,
    notice "<manager> created <name>"; not listed → "Couldn't see <name> yet".
  - `bots`: offers for listed ids with no bound bot; Add binds directly (no key flow).
  - `avatar`, `description`, `instructions`, `instructions_changed`: app-side, `boundBot` matched by agent id on that
    Gateway.
  - `bot_retired`: mark retired + hide, as for Hermes; never for the manager itself.
- **D5 Menu.** The Manage bots menu and BotOffersCard appear in an OpenClaw manager's chat as for Hermes.

## Tests (Swift Testing, fakes only)
1. Role: one manager per Gateway; toggling on a second OpenClaw bot of the same Gateway turns the first off; Hermes
   and OpenClaw managers coexist.
2. On demand: a non-management turn to the OpenClaw manager sends Konrad's text only; a management turn sends exactly
   one leading marked block + his text; a follow-up within the exchange attaches; after a block it stops. Hermes body
   byte-identical to before for the same inputs.
3. Display: the bubble and Gateway-loaded history never show the marked block.
4. Template: placeholders filled; no `{{` left; size bound; ban on secrets commands (`cat .env`, `openclaw.json` edits)
   in the text.
5. Blocks: bot_created → bound bot after the fake hub lists the id (and the "couldn't see" path); bots → offers →
   Add binds; avatar/description/instructions/retired on OpenClaw bots; ops never touch Hermes bots of another
   connection and vice versa.
