## Facts (read-only recon 2026-10-13/14; re-confirm in Part A step 1)
- A bot is a folder `/home/hermes/.hermes/profiles/<name>/`: `SOUL.md` (its instructions), `config.yaml`, `profile.yaml`
  (description), `.env` (only `API_SERVER_KEY`), `skills/`, `memories/`, `state.db`.
- Created with `hermes profile create NAME [--clone|--clone-all|--clone-from X] [--description]`
  (`hermes_cli/subcommands/profile.py:29-60`, `profiles.py:1075`). The API server rescans the profiles folder on every request
  (`api_server.py:1974-2008`), so a new profile with a key answers at `/p/<name>/` without a restart (*inferred, verify*).
  Telegram adapters and cron load profiles only at startup.
- Jarvis's terminal runs as user `hermes` with approvals off (`approvals.mode: off`, `HERMES_YOLO_MODE=1`), so it can already run
  `hermes profile create` and overwrite any `SOUL.md`. The file tool always asks a human before writing a `soul.md`
  (`tools/file_tools.py:712-733`). No profile tool exists. The `hermes-agent` skill documents `profile create` (`SKILL.md:195`).
- SwarmHub cannot list profiles. It probes names typed in Settings via `/p/<x>/v1/models`, one key each
  (`HermesBackend.swift:226-249`); "Add bots from box" needs pasted name/key pairs (`AppStore+HermesProfiles.swift:41`).
- SwarmHub's bot "Instructions" field is local only and goes out as the session system prompt on top of the box's SOUL.md
  (`BotEditorView.swift:45`, `HermesBackend.swift:256`). SwarmHub never reads or writes SOUL.md.
