## 1. Read-only actions run without approval
- Classify each app tool once (cache per tool slug), conservative:
  - **Asks:** a Composio `tags` entry meaning destructive/write (e.g. `destructiveHint`) if present; or any word in the
    tool's action part from a deny list: SEND, CREATE, UPDATE, DELETE, REMOVE, ADD, MODIFY, EDIT, MOVE, COPY, STAR,
    UNSTAR, FOLLOW, UNFOLLOW, MERGE, POST, REPLY, FORWARD, TRASH, ARCHIVE, LABEL, MARK, RUN, EXECUTE, QUERY (raw
    GraphQL/SQL), PROXY, UPLOAD, SET, PATCH, PUT, INVITE, APPROVE, ACCEPT, DECLINE, CANCEL, CLOSE, OPEN, LOCK, TRANSFER,
    PAY, BOOK, SCHEDULE, SUBSCRIBE, ENABLE, DISABLE, REVOKE, GRANT, DISPATCH, TRIGGER, COMMENT, REACT, PIN, SAVE, WRITE.
  - **Runs freely:** a tag clearly meaning read-only (e.g. `readOnlyHint`) and no deny word; or an action part that
    starts with GET, LIST, FETCH, SEARCH, FIND, READ, RETRIEVE, LOOKUP, COUNT, CHECK, VALIDATE, WHO_AM_I, DESCRIBE,
    DOWNLOAD (to the app only) and contains no deny word. Examples: `GMAIL_FETCH_EMAILS`, `GMAIL_GET_PROFILE`,
    `GITHUB_GET_THE_AUTHENTICATED_USER`, `GITHUB_LIST_REPOSITORIES…` run; `GMAIL_SEND_EMAIL`,
    `GITHUB_RUN_GRAPH_QL_QUERY`, `GITHUB_UPDATE_THE_AUTHENTICATED_USER`, `GITHUB_STAR…`, `GITHUB_FOLLOW…` ask.
  - Anything else: **asks**.
- A freely run read shows as the P51 folded line ("Plainsay used GitHub · Get the authenticated user · ok"), with no
  approval card. A write keeps the P37/P48 approval card with the account name.
- The approval card note changes from "App actions always ask you." to "Changes in your apps ask you; reading runs on
  its own." Connected apps (window and Settings) states the same rule in one line. The P48 Composio explanation text is
  updated to match.
- The P50 audit's narrow shell auto-approval and `reviewerMustEscalate` are unchanged (they cover shell/box approvals,
  not app reads). A forged box approval still never auto-runs an app action (only the app's own classified read does).

## 2. App failures are logged, returned to the bot, and don't end the goal
- Every app request failure gets a log line under `com.konrad.agentapp:composio`, including `invalidResponse`,
  `tooLarge`, decoding failures and lost connections: route kind, HTTP status if any, Composio slug/message if any, and
  for an unreadable answer its **shape only** (top-level keys and types, byte size; never values, never ids, tokens or
  keys). This is what tells us why "unexpected response" happened.
- The chat line names what failed ("Plainsay: GitHub · Run GraphQL query failed: Composio's answer could not be read
  (<shape>)") instead of the generic text.
- Every such failure goes back to the bot as a "SwarmHub app result" error (P48 did this only for Composio/transport
  errors), so the turn continues. Only SwarmHub's own refusals (access changed, undiscovered tool) still end the turn.
- A `/goal` (P45) is not stopped by an app failure the bot was told about: the round continues; it stops only when the
  turn itself fails or the bot ends the goal.
- Find why `GITHUB_GET_THE_AUTHENTICATED_USER`'s first execute produced "unexpected response" before the approval
  (look at the execute response decoding and the approval ordering: the call may have been attempted before approval or
  decoded with the wrong shape). Fix it if it is ours; otherwise the new log line makes it visible.
