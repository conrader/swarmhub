## Goal
Every model an agent's settings offer, or that Torvli applies to it, comes from that agent's own backend: never a Torvli list, never free text.
- **Hermes bot:** `/api/model/options` of its bound profile. A bot with no profile uses the default profile; a Grok history-only bot has none and says so. The top-level `model` is the **agent default**.
- **OpenClaw bot:** its Gateway's model list and the agent's configured model, through a backend-neutral catalog that P12 plugs into. Until then it reads "Models come from the OpenClaw gateway once connected." and offers no choices. This replaces P11/P13's "Managed in OpenClaw".
- **Torvli-wide default:** it stays a (supplier, id) pair. It is shown and applied per bot only where that bot's own list offers it. Elsewhere the bot runs on its agent default and says so (P13 D3).

## Facts (recon 2026-10-13: Torvli read statically; Hermes read-only, live on 0.20.5 and by source on 0.21.7; OpenClaw by source and schema only)
- **Hermes, per profile with the bot's own key** (`HermesBackend.swift:374`, `AppStore.swift:245`): `GET api/model/options` returns `model`/`provider`, the profile's configured default, and `providers[]`, the choices (P11's facts stand).
  - No route exposes delegation, auxiliary or fallback models.
  - A lock's provider is unreadable (Torvli records it); model writes are session-scoped.
  - `/v1/models` ids and `/v1/capabilities.model` are virtual names, never a model.
- **OpenClaw (schema 2026.10.3):** `models.list` and `agents.list` are read-scope calls. `agents.list[].model.primary` is the agent's effective default. A chat pin is reversible; an agent-level default is admin-only. Detail under "What P12 must implement".

## What P12 must implement to plug in (P17 ships none of it; basis: schema 2026.10.3, no Gateway contacted)
`OpenClawBackend: ModelCatalogProviding` in a new `OpenClawBackend+Models.swift` (≤150 lines) with its own fixtures.
- `catalogScope` = `gatewayID|agentID` (P12's `OpenClawBinding {gatewayID, agentID, sessionMode}`), `secrets` = the Gateway token, one catalog from two calls. No other Torvli file changes.
- `BotInfoCache.loadCatalog` maps errors: 404/405 and `BackendError.unavailable(text)` are `.unavailable`, anything else is `.failed` (Retry). Transient failures (`startup-sidecars`, timeouts) throw ordinary errors.
- **Calls:**
  - `models.list {agentId, view:"configured", includeDetails:true}`.
  - Add `sessionKey` (same agent) once the chat exists; the session-scoped capability name is unverified (docs say `session-scoped-model-catalog`, first-party iOS checks `published-model-catalog`), so try one and fall back.
  - A connect cap `model-selection-policy` yields `manualSelectionAllowed`. Whether adding it to P12's caps changes pairing or forces a re-approval is unverified: P12 decides and records it.
  - `agents.list[].model.primary` ("provider/model", the effective default) is `agentDefault`. Split it at the first `/` against the supplier slugs present in the rows, because an id may itself contain `/`.
  - A role-restricted Gateway's `modelSelectionPolicy.defaultModel` wins.
  - Never `refresh`, `authProfileId` or an `@profile` suffix.
- **Mapping:**
  - Supplier = row `provider` (the wire has no display name), model = `id`. Drop `manualSelectionAllowed == false`.
  - `missing-auth` and `auth-failed` become disabled rows in our words. `cooldown` (+`unavailableUntil`) is only a tag. `available` counts only on session-scoped calls.
  - **`pinning = .none` in P12.** P12 ships no `sessions.patch`, so menus stay read-only. P12b flips it to `.reversible` together with the apply side.
  - A 2026.8.x Gateway rejects `sessionKey`/`includeDetails`: retry once as `{agentId, view:"configured"}`, else `.unavailable("Update OpenClaw to list this agent's models.")`.
