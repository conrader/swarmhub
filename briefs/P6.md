Read `PLAN.md` first; its standing constraints apply. Start from `main` after P5 is merged.
Format spec: `docs/agentapp-bot-bundle-v1.md` (in this repo). Real exports are CONFIDENTIAL and are
never committed; tests use synthetic bundles you write under `Tests/Fixtures/bundles/`.

Konrad's requirement: all his Grok Bot bots, including transcripts, importable.

## Must do
1. Import a whole export folder (`index.json` + `<slug>/bundle.json` + skills) or a single bundle.json
   via the existing Template Import entry point (File → Import…). Reject unknown `format` values.
   Preview lists every bot with message/event counts and what maps / converts / is skipped, behind the
   existing confirmation gate.
2. Mapping: name, title, description → persona (through the existing secret filter), avatar shape+colour →
   our own avatar set (map each Grok shape/colour to the closest original Torvli avatar + accent; never
   Grok assets), rename events → shown in the bot's history as system lines, unread/notify flags,
   routines → imported routines (P2: not on server, created paused only on request), skills → imported skills.
3. Transcripts: imported messages are stored as a read-only "Grok history" archive per bot (shown above the
   live chat, collapsed by default, searchable, clearly labelled imported, never sent to Hermes as
   conversation turns). Keep memory use sane for large transcripts (load lazily from a per-bot file next to
   store.json rather than inside store.json).
4. Profile binding uses P1's rule (`grok-<slug>` key present → bind). Re-importing the same bot (same
   `source_id`) updates the archive and fields without duplicating the bot.
5. Group chats present in the bundle (see spec/FIX notes: inferred) map to P5 groups when all members imported.
6. Tests with synthetic bundles: index + 2 bots, unsupported format, redaction markers preserved, lazy archive
   file written and reloaded, re-import idempotency, avatar mapping table, routines arrive disabled.
